# 표정 분류 — ViT

얼굴 사진 한 장에서 표정 7종(화남·역겨움·무서움·웃음·무표정·슬픔·놀람)을 분류한다.
구글 ViT-base 를 FER2013 으로 파인튜닝했다 ([ADR-0032](../../docs/03_decision/0032-추론-모델-3종-확정.md)).

**진위 판별기가 아니다.** 표정을 수치로 읽을 뿐이고, 그 값은 거짓말 탐지의
특징 벡터에 들어가는 **재료**다 — 근거는 아래 「이 값을 어디까지 믿나」.

## 결과 — 세 회차

RTX 3050 8GB. 회차마다 `runs/<이름>/` 에 따로 남는다(`python compare.py`).

| 회차 | 전체 정확도 | 표정 평균 | 무엇을 바꿨나 |
|---|---|---|---|
| 01-기본 | 69.84% | 63.57% | FER2013 · 5 에폭 |
| 02-클래스가중치 | **71.02%** | 70.39% | 적은 표정에 가중치 · 증강 강화 · 9 에폭 |
| 03-FERPlus | 74.89% | **77.90%** | **라벨을 FERPlus 로 교체** |

**전체 정확도보다 표정 평균을 본다.** 전체로 고르면 흔한 표정만 잘 맞히는 모델이
뽑힌다 — 1차가 그랬다(웃음 90%, 역겨움 32%).

### 표정별 — 여기가 진짜 결과다

| 표정 | 01 | 02 | 03 | |
|---|---|---|---|---|
| **무서움** | 47% | 49% | **76%** | +29%p |
| 화남 | 64% | 68% | **81%** | |
| 슬픔 | 55% | 56% | **74%** | |
| 역겨움 | 32% | 74% | **81%** | |
| 웃음 | 90% | 87% | **91%** | |
| 놀람 | 82% | 85% | 83% | |
| 무표정 | 74% | 74% | 59% | 유일하게 떨어짐 |

## 무서움이 왜 두 번이나 안 올랐나 — 모델이 아니라 라벨이었다

1차 47% → 2차 49%. 클래스 가중치를 줘도 거의 안 움직였다. 파고들어 보니
**정답지가 틀려 있었다.**

FER2013 은 **한 사람이** 3만 5천 장에 라벨을 붙였다. 같은 사진에 **10명이 다시
투표한** FERPlus(마이크로소프트, MIT)로 바꿔 보니:

```
FER2013 "무서움"  4,097장
FERPlus "무서움"    652장   ← 10명이 보니 84%가 무서움이 아니었다
```

**틀린 정답지를 맞히려고 애쓰고 있었다.** 라벨을 바꾸자 47% → 76% 가 됐다.

`unknown`(222장) · `NF`(얼굴 아님, 177장)도 FERPlus 가 표시해 줘서 뺐다.
`contempt`(경멸)는 7종을 유지하려고 쓰지 않는다.

## 무표정만 떨어진 이유

FERPlus 에서 무표정이 10,309장(최다)이 되면서 클래스 가중치가 0.39 로 눌렀다.
적은 표정을 살리려고 내준 자리다. 전체 정확도(74.89%)가 표정 평균(77.90%)보다
낮은 것도 평가셋에 무표정이 2,597장이라서다.

**면접에서 보고 싶은 것은 긴장·불안 계열이라 이 교환은 우리에게 이득이다.**

### 3차 상세 — 학습 장수와 재현율

평가 7,048장(FERPlus). 라벨을 바꾸면서 장수가 크게 달라졌다.

| 표정 | 학습 장수 (FER2013 → FERPlus) | 재현율 |
|---|---|---|
| 웃음 | 7,215 → 7,528 | **91%** |
| 놀람 | 3,171 → 3,562 | 83% |
| 화남 | 3,995 → 2,467 | 81% |
| 역겨움 | 436 → **191** | 81% |
| **무서움** | 4,097 → **652** | **76%** |
| 슬픔 | 4,830 → 3,515 | 74% |
| 무표정 | 4,965 → **10,309** | 59% |

**"무서움" 이 4,097 → 652 로 줄었다.** 10명이 다시 보니 그 대부분이 무서움이
아니었다는 뜻이고, 우리가 1·2차에서 47~49% 를 받던 이유가 이것이다.

## 이 값을 어디까지 믿나

면접에서 보고 싶은 것은 긴장·불안 계열이다.

| | 1·2차 | **3차** |
|---|---|---|
| 무서움 | 47~49% | **76%** |
| 슬픔 | 55~56% | **74%** |

**쓸 만한 수준으로 올라왔다.** 다만 이것은 **표정을 맞히는 정확도**이지
거짓말을 맞히는 정확도가 아니다 — 표정과 진위는 다른 문제다.

법정 영상 실측에서 거짓 영상이 `happy`, 진실 영상이 `fear` 로 나왔다.
**표정만으로는 진위가 갈리지 않는다**([ADR-0032](../../docs/03_decision/0032-추론-모델-3종-확정.md) 결정 7).

발표에서 쓸 수 있는 문장:

> 표정 7종을 분류한다. 전체 74.9%, 표정별 평균 77.9% 다.
> 이것은 표정을 맞히는 정확도이고, 진위 판정의 **재료**로만 쓴다.

`demo.html` 이 표정마다 재현율을 「믿을만함」으로 같이 띄우는 이유다 —
91% 짜리 웃음과 59% 짜리 무표정이 같은 막대로 보이면 안 된다.

## 돌리는 법

```bash
cd ai/expression-vit
uv venv -p 3.13
uv pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124
uv pip install -r requirements.txt

.venv/Scripts/python.exe build_ferplus.py           # FERPlus 라벨 합치기 (한 번)
.venv/Scripts/python.exe train.py --data ferplus    # 학습 (9 에폭 · 67분)
.venv/Scripts/python.exe compare.py                 # 회차 비교
.venv/Scripts/python.exe evaluate.py        # 성적표 + 혼동 행렬
.venv/Scripts/python.exe predict.py 사진.jpg # 사진 한 장
.venv/Scripts/python.exe serve.py           # http://localhost:5100
```

데이터(58MB)는 `train.py` 가 알아서 받는다. **학습 결과(328MB)와 데이터는
레포에 넣지 않는다** — 위 명령이면 같은 값이 다시 나온다.

| 파일 | |
|---|---|
| `data.py` | 데이터 읽기. `--data ferplus` 면 FERPlus 라벨. **RAF-DB 로 갈아탈 때 고칠 곳도 여기** |
| `build_ferplus.py` | FER2013 사진 + FERPlus 라벨을 합친다. 순서가 맞는지 스스로 검사한다 |
| `compare.py` | 회차를 한 표로 비교 |
| `train.py` | 파인튜닝. 체크포인트는 **가장 좋은 것 하나만** 남긴다 |
| `evaluate.py` | 정확도 · 혼동 행렬 · 표정별 재현율/정밀도 |
| `predict.py` | 사진 한 장(또는 폴더) |
| `serve.py` + `demo.html` | 브라우저에서 확인 (사진 업로드 · 카메라) |

## 8GB 카드에서 겪은 것

- **평가를 학습보다 큰 묶음·높은 정밀도로 돌리면 죽는다.** 첫 시도에서 1 에폭
  학습을 마치고 평가에 들어가자마자 죽었다. 평가도 fp16 으로, 같은 묶음 크기로,
  `torch.cuda.empty_cache()` 뒤에 돌린다. 지금은 4.7GB / 8GB 로 여유가 있다.
- 학습 출력을 파이프에 물리면 버퍼링 때문에 **죽은 이유가 안 보인다.** 로그
  파일로 바로 받는다(`> train.log 2>&1`).
