# 표정 분류 — ViT

얼굴 사진 한 장에서 표정 7종(화남·역겨움·무서움·웃음·무표정·슬픔·놀람)을 분류한다.
구글 ViT-base 를 FER2013 으로 파인튜닝했다 ([ADR-0032](../../docs/03_decision/0032-추론-모델-3종-확정.md)).

**진위 판별기가 아니다.** 표정을 수치로 읽을 뿐이고, 그 값은 거짓말 탐지의
특징 벡터에 들어가는 **재료**다 — 근거는 아래 「이 값을 어디까지 믿나」.

## 결과

RTX 3050 8GB · 5 에폭 · 33분 · batch 32 · fp16.

| 에폭 | loss | 평가 정확도 |
|---|---|---|
| 1 | 1.4814 | 60.17% |
| 2 | 0.9933 | 65.74% |
| 3 | 0.8252 | 68.61% |
| 4 | 0.6839 | 69.59% |
| **5** | **0.5849** | **69.84%** |

증가폭이 5.6 → 2.9 → 1.0 → 0.3 %p 로 줄었다. 더 돌려도 크게 오르지 않는다.

### 표정마다 실력이 크게 다르다

평가 7,178장. **전체 정확도 하나만 보면 이게 안 보인다.**

| 표정 | 학습 장수 | 재현율 | 정밀도 |
|---|---|---|---|
| 웃음 | 7,215 | **90.1%** | 88.9% |
| 놀람 | 3,171 | 82.1% | 79.2% |
| 무표정 | 4,965 | 73.5% | 62.7% |
| 화남 | 3,995 | 64.4% | 59.0% |
| 슬픔 | 4,830 | 55.3% | 59.7% |
| 무서움 | 4,097 | 47.2% | 58.3% |
| 역겨움 | **436** | **32.4%** | 78.3% |

재현율 = 그 표정 중 몇 %를 맞혔나 · 정밀도 = 그 표정이라 답한 것 중 몇 %가 맞았나

역겨움은 학습 표본이 웃음의 1/16 이다. 정밀도(78.3%)는 높은데 재현율(32.4%)이
낮은 것은 **모델이 확신할 때만 역겨움이라 답하고 나머지는 놓친다**는 뜻이다.

### 가장 많이 헷갈린 것

```
슬픔   → 무표정   237번
무서움 → 슬픔     193번
슬픔   → 화남     133번
슬픔   → 무서움   132번
무표정 → 슬픔     131번
```

**어두운 표정끼리 서로 번진다.** 웃음·놀람처럼 티가 나는 것은 잘 가른다.

## 이 값을 어디까지 믿나 — 우리 쓰임새에 중요하다

면접에서 보고 싶은 것은 긴장·불안인데, **하필 그것이 가장 못 맞히는 쪽**이다.

| | |
|---|---|
| 잘 맞힘 | 웃음 90% · 놀람 82% — 면접 판단에는 덜 중요 |
| 못 맞힘 | **무서움 47% · 슬픔 55%** — 긴장·불안 계열 |

거짓말 탐지 쪽에서 법정 영상을 돌렸을 때 진실 영상이 `fear 71%` 로 나왔는데,
**그 fear 자체가 절반밖에 못 믿을 값**이라는 뜻이다.

발표에서 쓸 수 있는 문장:

> 표정 7종을 69.8% 정확도로 분류한다. 다만 긴장·불안 계열은 47~55% 로 낮아,
> 단독 판단 근거로 쓰지 않고 참고 재료로만 쓴다.

`demo.html` 이 표정마다 이 재현율을 「믿을만함」으로 같이 띄우는 이유다 —
90% 짜리 웃음과 32% 짜리 역겨움이 같은 막대로 보이면 안 된다.

## 돌리는 법

```bash
cd ai/expression-vit
uv venv -p 3.13
uv pip install torch torchvision --index-url https://download.pytorch.org/whl/cu124
uv pip install -r requirements.txt

.venv/Scripts/python.exe train.py           # 학습 (33분)
.venv/Scripts/python.exe evaluate.py        # 성적표 + 혼동 행렬
.venv/Scripts/python.exe predict.py 사진.jpg # 사진 한 장
.venv/Scripts/python.exe serve.py           # http://localhost:5100
```

데이터(58MB)는 `train.py` 가 알아서 받는다. **학습 결과(328MB)와 데이터는
레포에 넣지 않는다** — 위 명령이면 같은 값이 다시 나온다.

| 파일 | |
|---|---|
| `data.py` | FER2013 내려받기·읽기. **RAF-DB 로 갈아탈 때 고칠 곳은 여기 하나** |
| `train.py` | 파인튜닝. 체크포인트는 **가장 좋은 것 하나만** 남긴다 |
| `evaluate.py` | 정확도 · 혼동 행렬 · 표정별 재현율/정밀도 |
| `predict.py` | 사진 한 장(또는 폴더) |
| `serve.py` + `demo.html` | 브라우저에서 확인 (사진 업로드 · 카메라) |

## 8GB 카드에서 겪은 것

- **평가를 학습보다 큰 묶음·높은 정밀도로 돌리면 죽는다.** 첫 시도에서 1 에폭
  학습을 마치고 평가에 들어가자마자 죽었다. 평가도 fp16 으로, 같은 묶음 크기로,
  `torch.cuda.empty_cache()` 뒤에 돌린다. 지금은 4.7GB / 8GB 로 여유가 있다.
- 학습 출력을 파이프에 물리면 버퍼링 때문에 **죽은 이유가 안 보인다.** 로그
  파일로 바로 받는다(`> train.log 2>&1`).
