# 서류 점수 B 등급 저평가 보정 — "일부 충족" 이 C 로 떨어지던 것 (2026-10-19)

> **왜.** [결정성 실측](doc-score-determinism-2026-10.md)(PR #365)에서 같은 지원서의 점수 흔들림은 0 이 됐지만, 기대 등급 B(요건 일부 충족) 11명 중 2명만 B 로 나왔다. B 평균 44점으로 C 구간(50 이하)이고, 임계 60 자동 탈락으로 이어진다.
>
> **결론.** 원인은 채점 프롬프트가 "일부 충족" 의 요건 점수대를 정해 주지 않은 것(a)이다. `chain_evaluate.v4` 에 요건 점수 구간표를 넣어 **일치 15/24 → 21/24, B 2 → 8명**이 됐고 A 8명·C 5명은 그대로다. 다만 B 대부분이 52~54점이라 **임계 60 자동 탈락은 그대로**다 — 이것은 임계 정책 문제로 남긴다.

## 원인 가르기 — 수정 후(v3) 24명 결과로 하나씩 바꿔 본 것

서류 점수 = 요건 60 · 우대 10 · 문화 30 가중 평균(`screening.DEFAULT_WEIGHTS`). 등급은 `fit_score = round(서류/20)` 으로 3 이면 B.

| 가설 | 확인 방법 | 일치 (24명) | 판정 |
|---|---|---|---|
| 지금 (v3) | — | 15 (A 8 · B 2 · C 5) | |
| (c) 우대 점수가 끌어내림 | 우대 가중치 0 / 우대를 최소 50 으로 | 15 / 15 | **원인 아님.** B 한 명도 안 바뀜 |
| (b) 등급 경계가 안 맞음 | B 를 서류 40~69 로 넓힘 | 20 | 등급표는 맞아지지만 점수는 40점대 그대로 → 임계 60 자동 탈락이 안 풀림 |
| (a) 요건 점수대 미정 | B 의 요건 점수(25~69)를 +20 | 20 | **주원인.** 서류 점수 자체가 B 구간으로 올라감 |

- v3 의 요건 점수: A 75~95 · **B 25~55** (김태호 75·남기훈 72 제외) · C 5~15. 순서는 맞는데 B 가 낮게 몰려 있다.
- 문화 근거가 없으면 50, 우대는 B 대부분 0~15 라서 서류 ≈ 0.6 × 요건 + 16. **서류 51(B) 을 넘으려면 요건 58 이상**이 필요한데, v3 점수 기준표는 100(전부 충족)과 0(무관) 두 끝만 적고 중간을 비워 뒀다. "근거가 없으면 50 근처" 와 "하나라도 확인 안 되면 미충족" 두 문장도 서로 부딪쳤다.
- 덧붙여 (b) 쪽 작은 사실: 파이썬 `round` 는 .5 를 짝수로 보내서 서류 50 → 2(C), 90 → 4 가 된다. B 는 실제로 51~69 다. 이번에는 고치지 않았다.

## 보정 — `chain_evaluate.v4` (v3 유지)

입력·출력 모양은 v3 와 같다. 바뀐 것은 점수 기준 절뿐이다.

| 요건 점수 | 언제 |
|---|---|
| 85~100 | 같은 직무, 필수 항목 전부 충족 |
| 70~84 | 같은 직무, 모자라거나 근거가 약한 항목 1개 |
| **60~69** | **일부 충족** — 같은 직무(또는 요구 기술을 실무에 쓴 인접 직무)지만 필수 항목 둘 이상이 모자람. 같은 계열의 다른 기술, 연차가 하한에 조금 못 미침도 여기 |
| 30~59 | 다른 직무의 개발 경력, 요구 기술은 곁다리 |
| 0~29 | 개발과 무관, 또는 실무 경력 없음(교육·개인 프로젝트만) |

- 채점 순서 첫 단계에 "실무 직무가 공고 직무와 같은가" 를 넣었고, 원문에 없는 요건 항목은 미충족으로 센다(문화만 근거 없으면 50).
- 60 을 "일부 충족" 하한으로 둔 이유: 문화 50 · 우대 10 일 때 요건 60 → 서류 52 로 B 안쪽에 들어온다. 55 에서 시작하면 서류 49 로 C 가 된다.
- 가중치·등급 경계·임계는 건드리지 않았다.

## 남는 것

1. **B 가 B 구간에는 들어왔지만 임계 60 아래라 여전히 자동 탈락한다.** v4 B 8명 중 7명이 52~58점. 임계 60 이 B 구간(51~69) 한가운데 있어서다. B("추가 확인")를 사람이 보게 하려면 공고 임계를 50 근처로 내리거나, B 구간을 탈락 대신 보류(hold)로 두는 규칙이 필요하다. 임계 기본값·자동 판정 규칙은 ADR-0034 영역이라 이번에 건드리지 않았다.
2. **남은 불일치 3명.** 강현우 50(요건 62 · 문화 35 — 인재상 충돌을 잡았고, 50 은 반올림 규칙상 C). 신예은 42(자바 백엔드 6년을 "다른 직무" 로 봄). 오하람 38(파이썬 데이터 엔지니어를 "다른 직무" 로 봄). 구간표에 "다른 서버 언어"·"인접 직무" 를 적었는데도 모델이 30~59 를 골랐다.
3. **A 가 조금 내려왔다.** 평균 82 → 78, 최저 76 → 74(오세린·배수아). "1개 미흡이면 70~84" 구간 때문이다. 이번 조건에서는 A 의 문화가 75 이상이라 괜찮았지만, 인재상 근거가 없는(문화 50) A 지원자는 요건 75 면 서류 66(B)이 될 수 있다. 인재상 표가 채워진 공고에서 다시 볼 것.
4. **C 가 조금 올라왔다.** 평균 22 → 27, 최고 37(홍지민). 직무가 다른 개발자가 30~59 구간으로 간다. C 경계(50)까지 13점 여유.
5. **검증 세트가 따로 없다.** 구간표는 이 24명의 기대 등급을 보고 만들었고, 같은 24명으로 쟀다. 실제 지원서(이력서 PDF 포함)에서 등급 분포를 한 번 더 봐야 한다.
6. 기존 지원자의 점수는 요약을 다시 만들기 전까지 v3 점수 그대로다.
7. concerns 가 "최대 3개" 를 넘는 일은 v3 에도 비슷하게 있었다(48회 중 v3 22회 · v4 20회). 이번 변경과 무관.
