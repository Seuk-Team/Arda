# 서류 점수 결정성 — 같은 지원서에 같은 점수가 나오는가 (2026-10-19)

> **왜.** "같은 사람이 같은 지원서를 넣으면 평가가 그대로 나오는가" 라는 질문에 실측으로 답한다. 운영 요약 백엔드(Claude Haiku 4.5)는 `complete()` 에 temperature 가 없어 기본값 1.0 으로 돌았고, 2단계 채점(`chain_evaluate.v2`)은 1단계 요약(기술 3개·경험 2개)만 보고 원문을 못 봤다. PR #365 가 둘을 고쳤다.
>
> **결론.** 수정 후 같은 입력 5회의 서류 점수 폭이 **최대 9점 → 0점**이 됐고, fit-check 24명 기대 등급 일치도는 **12~13/24 → 15/24** 로 나빠지지 않고 올랐다.

## 무엇을 바꿨나 (PR #365)

| 조건 | 2단계 프롬프트 | temperature | 뜻 |
|---|---|---|---|
| 수정 전 | `chain_evaluate.v2` — 요약만 봄 | 미지정(기본 1.0) | 지금까지의 운영 |
| v2·temp 0 | `chain_evaluate.v2` | 0 | temperature 효과만 떼어 본 대조군 |
| **수정 후** | **`chain_evaluate.v3` — 원문(이력서·자소서) + 요약** | **0** | `AnthropicBackend.complete()` 그대로 |

- temperature 는 SDK 1.x 가 `create()` 에서 뺐으므로 `extra_body={"temperature": 0}` 로 보낸다. temperature 를 받는 모델(Haiku 4.5, Sonnet·Opus 4.5/4.6)에만 보내고, 400 으로 거절하는 모델(Opus 4.7 이후, Sonnet 5 계열, Haiku 5.5)에는 보내지 않는다.
- **temperature 0 도 Claude API 에서 완전 결정적이지는 않다.** 흔들림을 크게 줄일 뿐이며, 서버 쪽 사정으로 드물게 다른 답이 나올 수 있다. 아래 실측에서는 한 번도 갈리지 않았다는 뜻이다.

## 방법

- 모델 `claude-haiku-4-5-20251001`. 운영 경로(`summarizer.generate_summary` 의 1단계 요약 → 2단계 채점)를 DB 없이 그대로 재현했다. 공고는 `scripts/fit_check/create_postings.py` 의 요강 2개, 지원자는 `scripts/fit_check/applicants.yaml`(이력서 파일 없이 폼 필드 + 자기소개).
- 회사 인재상(`talent_profile`)은 "인재상 정보 없음" — 요강 description 안의 [인재상] 절로만 들어간다(fit-check 09-10 과 같은 조건).
- 서류 점수 = 요건·우대·문화 세 갈래의 기본 가중 평균(`screening.DEFAULT_WEIGHTS`). 통과 임계 60.
- 등급: `fit_score = round(doc_score / 20)` → 4~5 = A, 3 = B, 1~2 = C (`report.py` 와 같은 기준).
- 호출 약 400회. 스크립트는 세션 임시 폴더에 두었다(저장소 밖).

## 남는 것 (이번 PR 범위 밖)

1. **B 등급이 전 조건에서 C 쪽으로 낮게 나온다.** 박도윤·신예은·오하람·백서준은 수정 전에도 40점대였다. 수정 후 B 평균이 5점 더 내려가 B 일치는 3~4 → 2명이 됐다(전체 일치는 A 가 올라 늘었다). "일부 충족" 을 50~69 로 둔 등급 경계와 프롬프트 점수대가 안 맞는 문제라, 점수 기준 문구나 경계를 따로 맞춰야 한다.
2. **남기훈이 62 → 59 로 임계 60 아래가 됐다.** 원문 자기소개의 "자기 도메인만·승인 라인" 신호를 읽어 문화 점수가 50 → 25 가 된 것이다. fit-check 가 잡으려던 인재상 충돌을 이제 잡는다는 뜻이지만, 기대 B 인 사람이 자동 탈락한다는 점은 공고 임계(기본 60)를 정할 때 같이 봐야 한다.
3. **정보 부족 2명(문가영·장우진)은 어느 조건에서도 `insufficient` 가 나오지 않았다.** 1단계 요약 프롬프트의 문제라 이번 변경과 무관하다. 수정 후 점수는 36점으로 낮아 "낮은 확신" 쪽이다.
4. 이번 실측은 Haiku 4.5, 이력서 파일 없는 가상 지원자, 인재상 표 비움 조건이다. 실제 이력서 파일(PDF)이 붙으면 원문이 길어져 2단계 입력 토큰이 늘어난다.

## 함께 검토한 것

- **structured outputs (`output_config.format`)**: Haiku 4.5 실호출로 확인. 지금 `_STEP_SCHEMAS` 를 그대로 넣으면 400 (`additionalProperties` 를 모든 object 에 `false` 로 명시해야 함). 그것을 넣어도 400 (`integer` 의 `minimum`·`maximum` 미지원). `maxLength`·`maxItems`·`minimum`·`maximum` 을 걷어내면 통과한다. 즉 지금 스키마의 길이·개수·범위 제약은 서버가 강제할 수 없어, 켜려면 Anthropic 용 스키마 변환과 클라이언트 쪽 검증이 따로 필요하다. **이번에는 켜지 않았다.**
- **면접 채점 `interview/scoring.py` 의 `profile_summary`**: 면접 채점의 재료는 전사(질문·답변)이고 서류 요약은 "참고" 자리다. 서류 채점처럼 근거가 요약뿐인 구조가 아니므로 범위 밖으로 뒀다.
