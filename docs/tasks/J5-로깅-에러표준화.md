# [J5·J6] 구조화 로깅 + 에러 코드 표준화

> 담당: 팀원4 · 역할 E(인프라·인증) · 브랜치: `feat/j5-logging-errors`
> **PR 단위**: 이 지시서 전체 = PR 1개

## 배경

지금은 API 마다 `HTTPException(404, "…을 찾을 수 없습니다")` 처럼 **메시지 문구가 제각각**이다. 프론트가 에러를 구분하려면 한국어 문자열을 비교해야 하고, 문구가 바뀌면 화면이 깨진다.

그리고 문제가 생겼을 때 **어떤 요청이 실패했는지 추적할 방법이 없다.** print 도, 요청 id 도 없다.

이 둘은 같이 해야 한다 — **에러 코드가 있어야 로그에 무엇을 남길지가 정해진다.**

## 선행 조건 — 없으면 중단

아래가 하나라도 아니면 **시작하지 말고 팀 채널에 알린다.** 없는 것을 상상해서 만들지 않는다.

- [ ] [J0 앱 뼈대](J0-앱-뼈대.md) PR이 머지돼 있다
- [ ] **API 가 최소 2개 파트 이상 머지돼 있다** — 고칠 대상이 있어야 한다

## 가장 중요한 규칙

- **[backend/app/models.py](../../backend/app/models.py)를 수정하지 않는다.** 컬럼이 부족해 보여도 추가하지 않는다. 멈추고 팀 채널에 묻는다.
- **[docs/01-erd.md](../01-erd.md)·[docs/02-api.md](../02-api.md)를 수정하지 않는다.** 공용 문서다.
- **인증·권한 코드를 넣지 않는다.** 인증은 팀장 담당(A1~A3)이고 아직 없다. 토큰 검사를 흉내 내면 나중에 팀장 것과 충돌한다. 사용자 id 가 필요한 자리는 `# TODO(A1): 토큰의 사용자로 채운다` 주석만 남긴다.
- **`main.py` 는 `include_router` 한 줄만** 건드린다. 그 파일의 다른 부분은 손대지 않는다.
- **기존 API 의 동작을 바꾸지 않는다.** 응답 **형식만** 통일한다. 상태 코드가 달라지면 안 된다.
- **`print` 를 쓰지 않는다.** 표준 `logging` 을 쓴다.
- **로그에 개인정보와 시크릿을 남기지 않는다.** 이메일·전화번호·토큰·AWS 키를 찍지 않는다. 지원자 식별은 `application_id` 로 한다.
- **다른 사람의 라우터 파일을 고치지 않는다.** 전역 핸들러로 처리한다. 라우터를 하나씩 고치면 4명 파일을 다 건드리게 된다.

## 완료 조건

- [ ] `backend/app/errors.py` — 에러 코드 enum + 공통 응답 스키마
- [ ] `backend/app/logging_conf.py` — JSON 한 줄 로깅 설정
- [ ] **전역 예외 핸들러**를 `main.py` 에 등록 (`include_router` 외에 이 부분은 추가해도 된다 — 팀장 승인 항목)
- [ ] 모든 에러 응답이 같은 모양: `{"code": "...", "message": "...", "request_id": "..."}`
- [ ] 에러 코드는 **문자열 상수** — `NOT_FOUND` · `VALIDATION_FAILED` · `CONFLICT` · `FORBIDDEN` · `INTERNAL`
- [ ] **요청마다 `X-Request-ID`** 를 부여하고 응답 헤더와 로그에 함께 남긴다. 클라이언트가 보낸 값이 있으면 그것을 쓴다
- [ ] 로그는 **JSON 한 줄** — `ts` · `level` · `request_id` · `method` · `path` · `status` · `duration_ms`
- [ ] **5xx 는 스택트레이스를 로그에만** 남기고 응답에는 넣지 않는다
- [ ] 로그에 이메일·전화·토큰이 **찍히지 않는다**

## 완성 예시

**이 형태를 그대로 따른다.**

```python
# backend/app/errors.py
class Code(str, Enum):
    NOT_FOUND = "NOT_FOUND"
    VALIDATION_FAILED = "VALIDATION_FAILED"
    CONFLICT = "CONFLICT"
    FORBIDDEN = "FORBIDDEN"
    INTERNAL = "INTERNAL"
```

```python
# backend/app/main.py (추가분)
@app.middleware("http")
async def request_context(request: Request, call_next):
    # 클라이언트가 준 id 가 있으면 이어 쓴다. 프론트 로그와 서버 로그를 맞출 수 있다
    rid = request.headers.get("X-Request-ID") or str(uuid.uuid4())
    started = time.perf_counter()
    response = await call_next(request)
    response.headers["X-Request-ID"] = rid
    logger.info("", extra={"request_id": rid, "method": request.method,
                           "path": request.url.path, "status": response.status_code,
                           "duration_ms": round((time.perf_counter() - started) * 1000, 1)})
    return response


@app.exception_handler(Exception)
async def unhandled(request: Request, exc: Exception):
    # 스택트레이스는 로그에만. 응답에 넣으면 내부 구조가 밖으로 샌다
    logger.exception("unhandled", extra={"request_id": request.state.request_id})
    return JSONResponse(status_code=500, content={
        "code": Code.INTERNAL, "message": "서버 오류가 발생했습니다",
        "request_id": request.state.request_id})
```

로그에 개인정보를 넣지 않는다.

```python
# 나쁨 — 이메일이 로그에 남는다
logger.info("지원서 접수 %s", application.email)
# 좋음 — 식별은 id 로 한다
logger.info("지원서 접수", extra={"application_id": application.id})
```

backend/app/api/ 아래 다른 사람 라우터 파일을 고치지 마라 — 전역 핸들러로 처리한다.

## 검증 방법

```bash
P=localhost:8000/api/v1
curl -si $P/applications/999999 | grep -i 'x-request-id'
curl -s $P/applications/999999 | python -c 'import sys,json;d=json.load(sys.stdin);print("키:",sorted(d.keys()));print("code:",d["code"])'
curl -s -o /dev/null -w '상태유지 %{http_code}\n' $P/applications/999999
curl -s -H 'X-Request-ID: my-trace-123' -o /dev/null -D - $P/applications/999999 | grep -i 'x-request-id'
curl -s -X POST $P/applications/1/evaluations -H 'content-type: application/json' -d '{"score":99}' | python -c 'import sys,json;print("검증에러 code:",json.load(sys.stdin)["code"])'
echo '--- 로그에 개인정보 확인'
curl -s -X POST $P/public/postings/1/applications -H 'content-type: application/json' -d '{"name":"로그테스트","email":"secret@x.com","phone":"010-9999-8888","privacy_agreed":true}' >/dev/null
grep -c 'secret@x.com\|010-9999-8888' /tmp/app.log || echo '개인정보 미노출 OK'
```

기대 결과:

- 모든 에러 응답이 `code` · `message` · `request_id` **세 키**를 갖는다
- 404 는 `code: "NOT_FOUND"`, 422 는 `VALIDATION_FAILED`
- **상태 코드가 바뀌지 않았다** (404 는 여전히 404)
- 응답 헤더에 `X-Request-ID` 가 있다
- **클라이언트가 보낸 `X-Request-ID` 가 그대로 돌아온다**
- 로그가 **JSON 한 줄**이고 `duration_ms` 가 있다
- **로그에 이메일·전화번호가 없다**
