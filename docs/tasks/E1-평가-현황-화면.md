# [E1·E2] 평가 현황 화면 (정적 목업)

> 담당: (이름) · 브랜치: `feat/e1-evaluations-mockup`
> **PR 단위**: 이 지시서 전체 = PR 1개

## 배경

**면접관 관점** 화면. 내게 배정된 평가 대기 목록을 왼쪽에, 평가 입력 패널을 오른쪽에 두고, 하나 등록하면 자동으로 다음 지원자로 넘어간다([05-design](../05-design.md) §0.5). 자동 이동은 정적 목업에서는 만들지 않고, **버튼과 화면만** 만든다.

오른쪽 패널은 `mockup.html`의 상세 패널(`.dpanel`)과 같은 물건이다. 그대로 복사해서 안에 들어가는 내용만 바꾼다.

## 시작 전에 읽는다

- [ ] [docs/05-design.md](../05-design.md) **전체를 한 번 읽는다**
- [ ] [CLAUDE.md](../../CLAUDE.md)의 "범위" 항목
- [ ] [frontend/mockups/mockup.html](../../frontend/mockups/mockup.html)을 브라우저로 열고, **행을 클릭해 오른쪽 상세 패널을 열어 본다**

## 선행 조건 — 없으면 중단

- [ ] `main`에 `mockup.html`이 있고, 행 클릭 시 상세 패널이 열린다
- [ ] 직전 UI 작업 PR이 머지돼 있다

## 가장 중요한 규칙 — 새로 만들지 않는다

- 값은 전부 `:root` 토큰으로.
- 복사해 쓸 것: `.sidebar` `.nav` `.me` / `.head` `.title` / `.tpanel` `.trow` `.thead` `.trow-item` `.t-num` / `.dpanel` `.dinner` `.dhead` `.dsec` `.dclose` `.stage` / `.ninput`(평가 코멘트 입력) / `.btn` `.btn-primary`
- 새로 만드는 것은 **점수 선택(`.rate`) 하나뿐**이다. 아래 완성 예시를 그대로 쓴다.
- 목업에 없는 요소가 필요해지면 **멈추고 팀장에게 묻는다.**

## 완료 조건

- [ ] `frontend/mockups/mockup-evaluations.html` 1개 파일. `:root` 토큰 블록 + 필요한 클래스 복사
- [ ] 사이드바 `.active`를 "평가 현황"으로 옮긴다
- [ ] 헤더: 제목 "평가 현황". 우측에 `.head-meta` 규격으로 `평가 대기 12명`
- [ ] 왼쪽: 평가 대기 목록 테이블. 컬럼 4개 — **이름 / 공고 / 단계 / 배정일**. 행 6개
- [ ] 오른쪽: `mockup.html`의 `.dpanel`을 복사한 평가 패널. **항상 열린 상태**로 둔다(`class="dpanel open"`). 닫기 버튼은 그대로 둔다
- [ ] 패널 내용은 위에서 아래로: 이름 + 단계(`.dhead` 그대로) / **지원 정보**(`.dsec` + `.dlist`를 `mockup.html`에서 복사, 항목은 학력·경력·기술 3개면 충분) / **평가**(점수 선택 + 코멘트 입력 + 등록 버튼)
- [ ] 점수는 1~5 중 하나 선택. 선택 전에는 등록 버튼 비활성, 선택하면 활성 (`mockup.html`의 `#nadd` 토글과 같은 방식)
- [ ] 코멘트 입력은 `mockup.html`의 `.ninput`을 그대로 복사해 쓴다
- [ ] 등록 버튼 아래에 "등록하면 다음 지원자로 넘어갑니다" 안내를 12px `--text-sub`로 한 줄
- [ ] 상태 전부 (05-design §6): 점수 버튼 default / hover / press / focus-visible / 선택됨, 등록 버튼 default / hover / press / focus / disabled
- [ ] 창 폭 1100px 이하에서 패널이 `mockup.html`과 같은 방식으로 동작한다(그 미디어 쿼리도 함께 복사한다)

## 완성 예시

점수 선택은 목업에 없다. **아래를 그대로 복사해 쓴다. 값을 바꾸지 않는다.**

```html
<style>
.rate{ display:flex; gap:var(--sp-2); }
.rate button{ width:44px; height:44px; border-radius:var(--r-ctl); cursor:pointer;
              border:var(--border-w) solid var(--border); background:var(--bg-elev);
              font-family:var(--sans); font-size:var(--font-body); font-weight:600; color:var(--text);
              font-variant-numeric:tabular-nums;
              transition:background var(--dur-fast) var(--ease), border-color var(--dur-fast) var(--ease); }
.rate button:hover{ background:var(--bg-sunken); }
.rate button:active{ transform:translateY(1px); }
.rate button:focus-visible{ outline:2px solid var(--leaf); outline-offset:2px; }
.rate button[aria-pressed="true"]{ background:var(--leaf); border-color:var(--leaf); color:#fff;
                                   text-shadow:var(--ts-onfill); }
</style>

<div class="rate" role="group" aria-label="평가 점수">
  <button type="button" aria-pressed="false">1</button>
  <button type="button" aria-pressed="false">2</button>
  <button type="button" aria-pressed="false">3</button>
  <button type="button" aria-pressed="false">4</button>
  <button type="button" aria-pressed="true">5</button>
</div>
```

버튼 44×44px은 임의 값이 아니라 터치 타깃 최소 규격이다(05-design §9, Apple HIG). **줄이지 마라.**

## 검증 방법

```bash
python -m http.server 5500 --directory frontend/mockups
```

`http://localhost:5500/mockup-evaluations.html`

기대 결과:

- 사이드바·패널이 `mockup.html`과 눈으로 구분되지 않는다
- 점수를 고르기 전에는 등록 버튼이 회색, 고르면 잎초록으로 바뀐다
- 선택한 점수 버튼만 잎초록으로 채워진다
- Tab으로 점수 버튼과 입력·등록 버튼에 초록 포커스 링이 보인다
- 창 폭을 1100px 아래로 줄여도 겹침·가로 스크롤이 없다
- 콘솔에 에러가 없다
