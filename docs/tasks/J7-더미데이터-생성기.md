## 배경

검색·필터(H)와 인덱스 튜닝은 데이터가 많아야 의미가 있다. 실제와 비슷한 분포의 지원서 10만 건을 만들어 넣는 스크립트가 있어야 B 파트 전체(검색 API·인덱스·성능 측정)가 굴러간다. 이 작업은 다른 모듈에 의존하지 않아서 스키마 확정 직후 바로 시작할 수 있다.

## 완료 조건

- [ ] `backend/scripts/seed_dummy.py` 실행 시 공고 10개 + 지원서 100,000건이 DB에 들어간다
- [ ] 건수를 인자로 조절할 수 있다 (`--count 1000` 등, 기본 100000)
- [ ] 데이터가 그럴듯하다: 한국어 이름, 유효한 형식의 이메일·전화번호, 학력·경력 연차·기술 태그(Python·FastAPI·React·AWS 등에서 랜덤 조합), 단계 분포는 접수 위주(접수 50% / 서류 25% / 면접 15% / 합격 4% / 불합격 6% 근사)
- [ ] 같은 공고에 같은 이메일 중복 없음 (UNIQUE 제약 위반 안 남)
- [ ] 재실행하면 기존 더미를 지우고 새로 넣거나, `--append`로 추가할 수 있다

## 검증 방법

```bash
python backend/scripts/seed_dummy.py --count 100000
```

이후 DB에서:

```sql
SELECT current_stage, count(*) FROM applications GROUP BY current_stage;
```

기대 결과: 총합 100,000, 단계 분포가 위 근사치와 비슷하면 성공. 실행 소요 시간도 기록해 둘 것(성능 측정 파트에서 씀).
