# [C1·C2·C3·F4] 지원 폼 화면 (정적 목업, 공개)

> 담당: (이름) · 브랜치: `feat/c1-apply-form-mockup`
> **PR 단위**: 이 지시서 전체 = PR 1개

## 배경

**지원자가 로그인 없이** 들어오는 유일한 화면. 외부 링크로 접근하므로 **사이드바가 없다.** 공고 정보를 보고, 지원 정보를 입력하고, 이력서·자기소개서 파일을 올리고, 개인정보 수집에 동의한 뒤 제출한다.

내부 화면이 아니라서 구조는 다르지만 **색·글자 크기·간격·버튼은 전부 같아야 한다.** 로그인 화면(`mockup-login.html`)과 같은 계열로 보이면 성공이다.

## 시작 전에 읽는다

- [ ] [docs/05-design.md](../05-design.md) **전체를 한 번 읽는다**
- [ ] [CLAUDE.md](../../CLAUDE.md)의 "범위" 항목
- [ ] `mockup.html`과 `mockup-login.html`을 브라우저로 열어 **눈으로 본다**

## 선행 조건 — 없으면 중단

- [ ] **A1 로그인 화면 PR이 머지돼 있다** — 입력 컴포넌트(`.tfield` `.tinput`)를 거기서 복사한다. 아직이면 기다린다
- [ ] `main`에 `mockup.html`이 있고 브라우저에서 열린다

## 가장 중요한 규칙 — 새로 만들지 않는다

- 값은 전부 `:root` 토큰으로.
- 복사해 쓸 것: `mockup-login.html`의 `.tfield` `.tinput` / `mockup.html`의 `.logo` `.ninput` `.btn` `.btn-primary` `.badge` `.badge-open` `.head-meta`, 체크박스 스타일(`accent-color:var(--leaf)`)
- 새로 만드는 것은 **파일 업로드 카드(`.upload`)와 진행률 막대(`.prog`)뿐**이다. 아래 완성 예시를 그대로 쓴다.
- 목업에 없는 요소가 필요해지면 **멈추고 팀장에게 묻는다.**

## 완료 조건

- [ ] `frontend/mockups/mockup-apply.html` 1개 파일. `:root` 토큰 블록 + 필요한 클래스 복사
- [ ] **사이드바 없음.** 배경 `var(--bg)` 위에 가운데 정렬된 폭 640px 카드 하나. 카드 안 텍스트는 **좌측 정렬**(05-design §11)
- [ ] 카드 맨 위: 로고(`.logo`) + 공고명 + `.badge .badge-open`("진행중") + `.head-meta`로 `마감 2026.03.31`
- [ ] 입력: 이름 / 이메일 / 연락처 / 최종 학력 / 경력 연차 — `.tfield` `.tinput` 복사. 전부 `<label for>` 연결
- [ ] 자기소개서: `mockup.html`의 `.ninput` 복사, 최소 높이는 그대로
- [ ] 파일 업로드 **2개**: 이력서 / 자기소개서 파일. 각각 파일 선택 버튼 + 선택된 파일명 + 진행률 막대(F4)
- [ ] 진행률 막대는 정적 목업이라 **60% 상태로 하나 보여주고**, 나머지 하나는 선택 전 상태로 둔다
- [ ] 허용 형식 안내를 12px `--text-sub`로: `PDF · DOCX · HWP · 10MB 이하`
- [ ] 개인정보 수집 동의 체크박스(C3) + "동의하지 않으면 제출할 수 없습니다" 안내. **체크 전에는 제출 버튼 비활성**
- [ ] 제출 버튼(`.btn .btn-primary`, 카드 폭 100%)
- [ ] 상태 전부 (05-design §6): 입력·체크박스·버튼의 default / hover / press / focus-visible / disabled
- [ ] 창 폭 375px에서도 카드가 화면에 들어오고 가로 스크롤이 없다

## 완성 예시

업로드 카드와 진행률은 목업에 없다. **아래를 그대로 복사해 쓴다. 값을 바꾸지 않는다.**

```html
<style>
.upload{ display:flex; align-items:center; gap:var(--sp-3); padding:var(--sp-3);
         background:var(--bg-sunken); border-radius:var(--r-card); font-family:var(--sans); }
.upload .ufile{ flex:1; min-width:0; font-size:var(--font-sm); color:var(--text);
                white-space:nowrap; overflow:hidden; text-overflow:ellipsis; }
.upload .ufile.empty{ color:var(--text-sub); }
.upload .ubtn{ flex:none; height:32px; padding:0 var(--sp-3); border-radius:var(--r-ctl);
               background:var(--bg-elev); border:var(--border-w) solid var(--border);
               font-family:var(--sans); font-size:var(--font-sm); font-weight:600; color:var(--text);
               white-space:nowrap; cursor:pointer; text-shadow:var(--ts-heading);
               transition:background var(--dur-fast) var(--ease); }
.upload .ubtn:hover{ background:var(--bg-sunken); }
.upload .ubtn:focus-visible{ outline:2px solid var(--leaf); outline-offset:2px; }

.prog{ height:6px; margin-top:var(--sp-2); border-radius:999px;
       background:var(--bg-sunken); overflow:hidden; }
.prog > span{ display:block; height:100%; background:var(--sprout); border-radius:999px;
              transition:width var(--dur-base) var(--ease); }
</style>

<div class="upload">
  <span class="ufile">김도현_이력서.pdf</span>
  <button type="button" class="ubtn">파일 선택</button>
</div>
<div class="prog"><span style="width:60%"></span></div>
```

`--sprout`(연두)를 진행률에 쓰는 이유는 05-design §1의 "연두 = 면·채움" 용도에 맞기 때문이다. **다른 색으로 바꾸지 마라.**

## 검증 방법

```bash
python -m http.server 5500 --directory frontend/mockups
```

`http://localhost:5500/mockup-apply.html`

기대 결과:

- **`mockup.html`과 `mockup-login.html`을 옆 탭에 함께 띄우고 나란히 비교한다.** 색·간격·글자 크기·모서리 반경·그림자가 눈으로 구분되지 않는다. 목업에 없는 요소를 새로 만들지 않았다
- 동의 체크 전에는 제출 버튼이 회색, 체크하면 잎초록으로 바뀐다
- 진행률 막대가 연두로 60% 차 있다
- Tab으로 모든 입력·버튼·체크박스에 초록 포커스 링이 보인다
- 창 폭 375px에서 카드가 화면 안에 들어오고 가로 스크롤이 없다
- 긴 파일명을 넣어도 두 줄로 밀리지 않고 `…`로 잘린다
- 콘솔에 에러가 없다
