# [H1·H2] 지원자 통합 검색 화면 (정적 목업)

> 담당: (이름) · 브랜치: `feat/h1-applicants-mockup`
> **PR 단위**: 이 지시서 전체 = PR 1개

## 배경

사이드바 "지원자" 화면. 특정 공고가 아니라 **전 공고를 가로지르는 검색 테이블**이다([05-design](../05-design.md) §0.5). 10만 건 검색 성능을 보여주는 무대라 **응답 시간 표기**가 이 화면의 특징이다. 칸반은 없다.

`mockup.html`(공고의 지원자 화면)과 구조가 거의 같다. **베껴서 컬럼과 툴바만 바꾸는 작업**이고, 새로 만들 요소가 없어야 정상이다.

## 시작 전에 읽는다

- [ ] [docs/05-design.md](../05-design.md) **전체를 한 번 읽는다**
- [ ] [CLAUDE.md](../../CLAUDE.md)의 "범위" 항목
- [ ] [frontend/mockups/mockup.html](../../frontend/mockups/mockup.html)을 브라우저로 열어 **눈으로 본다**

## 선행 조건 — 없으면 중단

- [ ] `main`에 `mockup.html`이 있고 브라우저에서 열린다
- [ ] 직전 UI 작업 PR이 머지돼 있다

## 가장 중요한 규칙 — 새로 만들지 않는다

- 값은 전부 `:root` 토큰으로. 직접 쓴 색·간격·폰트 크기 금지.
- 복사해 쓸 것: `.sidebar` `.nav` `.me` / `.head` `.title` / `.toolbar` `.search` `.dd` / `.tpanel` `.trow` `.thead` `.trow-item` `.t-num` `.tfoot` `.pager` `.btn-page` / `.stage` `.stage-progress` `.stage-accepted` `.stage-rejected`
- **퍼널 레일은 넣지 않는다.** 그건 공고 하나에 속한 화면의 것이다.
- 목업에 없는 요소가 필요해지면 **멈추고 팀장에게 묻는다.**

## 완료 조건

- [ ] `frontend/mockups/mockup-applicants.html` 1개 파일. `:root` 토큰 블록 + 필요한 클래스 복사
- [ ] 사이드바 `.active`를 "지원자"로 옮긴다
- [ ] 헤더: 제목 "지원자". 뒤로 가기 버튼·우측 버튼 없음
- [ ] 툴바: `mockup.html`의 `.search` 복사. 드롭다운 항목은 **전체 / 이름 / 이메일**. placeholder는 "이름 또는 이메일 검색"
- [ ] 툴바 오른쪽 끝에 **응답 시간 표기**: `.head-meta` 규격(14px `--text-sub`, tabular-nums)으로 `1,248건 · 0.14초`
- [ ] 테이블 컬럼 6개: **이름 / 공고 / 단계 / 경력 / 평가 / 지원일**. 체크박스 컬럼 없음(일괄 처리는 공고별 화면에만 있다)
- [ ] "공고" 칸은 공고명 — 이 화면이 전 공고 통합이라는 걸 이 컬럼 하나가 증명한다. 길면 `ellipsis`
- [ ] 행 8개. 단계는 `.stage-progress` / `.stage-accepted` / `.stage-rejected`가 섞이게
- [ ] 행 클릭 시 `mockup.html`로 이동 (상세 패널은 이 화면에서 만들지 않는다)
- [ ] `.tfoot` + `.pager` 복사, "1,248명 중 1–8"
- [ ] 긴 이름·긴 공고명 각 1건씩 넣어 `ellipsis` 확인 (05-design §7)
- [ ] 가로 스크롤 없음, 겹침 없음

## 완성 예시

컬럼 폭만 이 화면 값으로 교체한다. 그 외에는 새로 만들 것이 없다.

```html
<style>
/* mockup.html의 .trow를 복사한 뒤 grid-template-columns만 이 값으로 교체 */
.trow{ grid-template-columns:120px minmax(160px,1fr) 88px 72px 64px 104px; }
</style>

<div class="trow thead">
  <span>이름</span><span>공고</span><span>단계</span>
  <span class="t-num">경력</span><span class="t-num">평가</span><span class="t-num">지원일</span>
</div>
```

## 검증 방법

```bash
python -m http.server 5500 --directory frontend/mockups
```

`http://localhost:5500/mockup-applicants.html`

기대 결과:

- **`mockup.html`을 옆 탭에 함께 띄우고 나란히 비교한다.** 색·간격·글자 크기·모서리 반경·그림자가 눈으로 구분되지 않는다. 목업에 없는 요소를 새로 만들지 않았다
- 사이드바가 `mockup.html`과 눈으로 구분되지 않는다
- 긴 이름·긴 공고명이 두 줄로 밀리지 않고 `…`로 잘린다
- 행 hover 배경 변화, Tab 이동 시 초록 포커스 링
- 창 폭을 줄여도 가로 스크롤이 없다
- 콘솔에 에러가 없다

## 막히면 · 되돌리기

- **30분 넘게 막히면 혼자 붙들지 말고 팀 채널에 묻는다.** 혼자 Claude와 씨름한 2시간이, 팀장이 5분에 답할 것을 이상한 결과물로 바꿔놓는다.

```bash
git checkout -- .
```

그래도 이상하면 브랜치째 버리고 처음부터 다시 시작한다.

```bash
git checkout main && git branch -D <브랜치명>
```

- **`git status`에 지시서에 없는 파일이 떠 있으면 Claude가 범위를 벗어난 것이다.** 그 변경은 되돌리고 팀 채널에 알린다.
