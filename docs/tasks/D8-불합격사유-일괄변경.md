# [D8·D9] 불합격 사유 기록 + 일괄 단계 변경

> 담당: 팀원3 · 역할 A(도메인 백엔드) · 브랜치: `feat/d8-reason-bulk`
> **PR 단위**: 이 지시서 전체 = PR 1개

## 배경

서류에서 100명을 떨어뜨리는데 카드를 하나씩 끌면 100번을 끌어야 한다. 그리고 왜 떨어뜨렸는지가 어디에도 안 남아 **나중에 "이 사람 왜 불합격이었죠?"에 아무도 답할 수 없다.**

두 기능을 한 PR 로 묶는 이유는 **같은 지점을 건드리기 때문**이다 — 둘 다 단계 변경 경로에 얹힌다.

**단계 전환 규칙 자체는 팀장 담당(D3)이다.** 이 지시서는 팀장이 만든 전환 함수를 **호출**할 뿐 규칙을 새로 만들지 않는다.

## 선행 조건 — 없으면 중단

아래가 하나라도 아니면 **시작하지 말고 팀 채널에 알린다.** 없는 것을 상상해서 만들지 않는다.

- [ ] **팀장의 D3 단계 전환 로직이 머지돼 있다** — 전환 규칙을 호출할 함수가 있어야 한다. 없으면 기다린다
- [ ] **`stage_history` 에 `reason` 컬럼을 추가하는 건을 팀장이 합의·반영했다** ([01-erd.md](../01-erd.md) D8 확장 여지)
- [ ] [D1 지원자 API](D1-지원자-API.md) PR이 머지돼 있다

## 가장 중요한 규칙

- **[backend/app/models.py](../../backend/app/models.py)를 수정하지 않는다.** 컬럼이 부족해 보여도 추가하지 않는다. 멈추고 팀 채널에 묻는다.
- **[docs/01-erd.md](../01-erd.md)·[docs/02-api.md](../02-api.md)를 수정하지 않는다.** 공용 문서다.
- **인증·권한 코드를 넣지 않는다.** 인증은 팀장 담당(A1~A3)이고 아직 없다. 토큰 검사를 흉내 내면 나중에 팀장 것과 충돌한다. 사용자 id 가 필요한 자리는 `# TODO(A1): 토큰의 사용자로 채운다` 주석만 남긴다.
- **`main.py` 는 `include_router` 한 줄만** 건드린다. 그 파일의 다른 부분은 손대지 않는다.
- **전환 규칙을 여기서 다시 구현하지 않는다.** 팀장이 만든 함수를 호출한다. 규칙이 두 곳에 있으면 반드시 어긋난다.
- **일괄 변경은 전부 성공하거나 전부 실패한다.** 50명 중 30명만 바뀌고 끝나면 담당자가 무엇이 됐는지 알 수 없다.
- **메일도 건별로 큐에 넣는다.** 일괄이라고 한 통으로 묶어 보내면 안 된다.

## 완료 조건

- [ ] `stage_history.reason` 을 `PATCH /applications/{id}/stage` 요청에서 받는다 (선택)
- [ ] `to_stage="rejected"` 인데 `reason` 이 없으면 **422** — 불합격은 이유를 남긴다
- [ ] `POST /api/v1/applications/bulk-stage` — 여러 명 한 번에. 본문 `{application_ids: [...], to_stage, reason?}`
- [ ] **한 건이라도 전환 규칙에 걸리면 전체 롤백**하고 **409** + 실패한 id 목록을 응답에 담는다
- [ ] 한 번에 최대 **200명**. 넘으면 422
- [ ] 성공 시 각 지원자마다 `stage_history` 1행 + 메일 큐 1건
- [ ] 응답에 `changed` 개수와 `skipped`(이미 그 단계였던 건) 목록
- [ ] `GET /applications/{id}/history` 응답에 `reason` 포함

## 완성 예시

**이 형태를 그대로 따른다.**

```python
# backend/app/api/applications.py (추가분)
@router.post("/applications/bulk-stage")
def bulk_stage(body: BulkStageRequest, db: Session = Depends(get_db)):
    if len(body.application_ids) > 200:
        raise HTTPException(http.HTTP_422_UNPROCESSABLE_ENTITY, "한 번에 200명까지 가능합니다")
    if body.to_stage == "rejected" and not body.reason:
        raise HTTPException(http.HTTP_422_UNPROCESSABLE_ENTITY, "불합격은 사유를 입력해야 합니다")

    rows = db.scalars(select(Application)
                      .where(Application.id.in_(body.application_ids))).all()
    changed, skipped, failed = [], [], []
    for row in rows:
        if row.current_stage == body.to_stage:
            skipped.append(row.id)
            continue
        try:
            # 전환 규칙은 팀장의 서비스 함수 하나에만 있다. 여기서 다시 구현하지 않는다
            change_stage(db, row, body.to_stage, reason=body.reason, changed_by=None)
            changed.append(row.id)
        except StageTransitionError:
            failed.append(row.id)

    if failed:
        # 30명만 바뀌고 끝나면 담당자가 무엇이 됐는지 알 수 없다. 전부 되돌린다
        db.rollback()
        raise HTTPException(http.HTTP_409_CONFLICT,
                            {"message": "허용되지 않는 전환이 있습니다", "failed": failed})

    db.commit()
    return {"changed": len(changed), "skipped": skipped}
```

## 검증 방법

```bash
P=localhost:8000/api/v1
curl -s -o /dev/null -w '사유없는불합격 %{http_code}\n' -X PATCH $P/applications/1/stage -H 'content-type: application/json' -d '{"to_stage":"rejected"}'
curl -s -X PATCH $P/applications/1/stage -H 'content-type: application/json' -d '{"to_stage":"rejected","reason":"경력 요건 미달"}' >/dev/null
curl -s $P/applications/1/history | python -c 'import sys,json;print("사유:",[h.get("reason") for h in json.load(sys.stdin)])'
curl -s -X POST $P/applications/bulk-stage -H 'content-type: application/json' -d '{"application_ids":[2,3,4],"to_stage":"screening"}'
curl -s -X POST $P/applications/bulk-stage -H 'content-type: application/json' -d '{"application_ids":[2,3,4],"to_stage":"screening"}' | python -c 'import sys,json;print("재실행:",json.load(sys.stdin))'
curl -s -o /dev/null -w '규칙위반 %{http_code}\n' -X POST $P/applications/bulk-stage -H 'content-type: application/json' -d '{"application_ids":[1,2],"to_stage":"accepted"}'
psql "$DATABASE_URL" -c "select count(*) from email_logs where stage='screening'"
```

기대 결과:

- 사유 없는 불합격 → **422**
- 사유를 넣으면 `history` 에 `reason` 이 남는다
- 일괄 변경 3명 → `changed: 3`
- 같은 요청 재실행 → `changed: 0`, `skipped: [2,3,4]`
- 규칙 위반이 섞이면 **409** 이고 **아무도 안 바뀐다** (전체 롤백)
- 메일 큐가 **건별로** 쌓인다 (3명이면 3건)
