# [B1] 채용 공고 목록 화면 (정적 목업)

> 담당: (이름) · 브랜치: `feat/b1-postings-mockup`
> **PR 단위**: 이 지시서 전체 = PR 1개

## 배경

사이드바 "채용 공고"를 눌렀을 때 나오는 화면. 공고를 클릭하면 그 공고의 지원자 화면([mockup.html](../../frontend/mockups/mockup.html))으로 넘어간다. API 연결은 범위 밖이고 **정적 HTML 목업 1장**만 만든다.

이 화면은 지원자 화면과 **구조가 거의 같다**(사이드바 + 헤더 + 툴바 + 테이블). 그래서 새로 만드는 게 아니라 **베껴서 컬럼만 바꾸는 작업**이다.

## 시작 전에 읽는다

- [ ] [docs/05-design.md](../05-design.md) **전체를 한 번 읽는다.** 색·크기·간격·상태 규칙이 전부 여기서 나온다
- [ ] [CLAUDE.md](../../CLAUDE.md)의 "범위" 항목 — 자기 담당 파일 밖을 고치지 않는다
- [ ] [frontend/mockups/mockup.html](../../frontend/mockups/mockup.html)을 브라우저로 열어 **눈으로 본다.** 이 화면은 저것과 같은 물건처럼 보여야 한다

## 선행 조건 — 없으면 중단

- [ ] `main`에 `mockup.html`이 있고 브라우저에서 열린다
- [ ] **복사 원본으로 지정된 파일의 PR이 머지돼 있다** — 이 화면의 복사 원본은 `mockup.html` 하나뿐이고 그것은 이미 `main`에 있다. **기다릴 것이 없다. 바로 시작한다**

## 가장 중요한 규칙 — 새로 만들지 않는다

- **색·간격·폰트 크기·radius·그림자·모션 값을 직접 쓰지 않는다.** 전부 `mockup.html`의 `:root` 토큰을 쓴다.
- 이 화면에 필요한 것은 **전부 `mockup.html`에 이미 있다.** 그대로 복사한다: `.sidebar` `.nav` `.me` / `.head` `.head-top` `.title` `.badge` `.badge-open` `.head-meta` / `.toolbar` `.search` `.dd` / `.tpanel` `.trow` `.thead` `.trow-item` `.t-num` `.tfoot` `.pager` `.btn-page` / `.btn` `.btn-primary`
- **목업에 없는 요소가 필요해지면 멈추고 팀장에게 묻는다.** 이 지시서에는 예외가 없다 — 새 클래스를 만들 일이 없어야 정상이다(컬럼 폭 지정 하나만 예외, 아래 완성 예시 참고).
- [docs/05-design.md](../05-design.md) §11 금지 항목을 지킨다. 장식을 임의로 붙이지 않는다.

## 완료 조건

- [ ] `frontend/mockups/mockup-postings.html` 1개 파일. `mockup.html`의 `<style>` 안 `:root` 토큰 블록과 위에 적힌 클래스들을 복사해 넣는다
- [ ] 사이드바는 `mockup.html`과 **완전히 동일**. 단 `.active`를 "채용 공고"에 준다 (지금도 채용 공고에 있으니 그대로 두면 된다)
- [ ] 헤더: 뒤로 가기 버튼(`.back`) **없음**. 제목은 "채용 공고", 우측에 "공고 등록" 버튼(`.btn .btn-primary`, `mockup.html`의 `.head-top .btn` 위치 규칙 그대로)
- [ ] 툴바: `mockup.html`의 `.search`(검색 입력 + 지우기 버튼 + 드롭다운)를 그대로 복사. 드롭다운 항목만 **전체 / 진행중 / 마감**으로 바꾼다
- [ ] 테이블 컬럼 5개: **공고명 / 상태 / 지원자 수 / 마감일 / 등록일**. 체크박스 컬럼 **없음**(공고는 일괄 처리가 없다)
- [ ] 행 6개. 상태는 `.badge .badge-open`("진행중")과 마감 상태 두 종류가 섞이게 한다. **마감 뱃지는 `mockup.html`에 없으므로 새로 만들지 말고, 마감된 공고는 상태 칸에 `.stage.stage-progress` 규격의 회색 글자 "마감"으로 적는다**
- [ ] 숫자·날짜 칸은 `.t-num`(tabular-nums) 사용. 날짜 표기는 `2026.03.12`, 마감은 `D-12` (05-design §2 표기 통일)
- [ ] 행 전체가 클릭 가능: `.trow-item`을 `<a href="mockup.html">`로 감싸거나 행에 `onclick="location.href='mockup.html'"`. hover·focus-visible은 `mockup.html`의 `.trow-item` 규칙 그대로
- [ ] 하단 `.tfoot` + `.pager` 복사 ("48건 중 1–6" 식으로 숫자만 바꾼다)
- [ ] **긴 공고명 1개**를 넣어 `ellipsis`가 도는지 확인한다 (05-design §7 극단값)
- [ ] 어떤 창 크기에서도 겹침·삐져나옴 없음, 가로 스크롤 없음

## 완성 예시

컬럼 폭은 화면마다 다르므로 이 화면 것만 아래로 **그대로** 쓴다. 값을 바꾸지 않는다.

```html
<style>
/* mockup.html의 .trow를 복사한 뒤, grid-template-columns만 이 값으로 교체한다 */
.trow{ grid-template-columns:minmax(220px,1fr) 96px 96px 96px 112px; }
</style>

<div class="trow thead">
  <span>공고명</span><span>상태</span><span class="t-num">지원자</span>
  <span class="t-num">마감</span><span class="t-num">등록일</span>
</div>

<div class="trow trow-item" onclick="location.href='mockup.html'" tabindex="0">
  <span class="name">백엔드 개발자 (신입)</span>
  <span class="badge badge-open">진행중</span>
  <span class="t-num">1,248</span>
  <span class="t-num">D-12</span>
  <span class="t-num">2026.02.28</span>
</div>
```

## Claude에게 시키기

한 번에 다 시키지 말고 **0 → 1 → 2 → 3 순서로 하나씩** 시킨다. 각 단계가 끝나면 브라우저에서 직접 열어보고 다음으로 넘어간다.

```
0단계.
docs/05-design.md 전체와 frontend/mockups/mockup.html 을 읽어라.
읽은 뒤, 이 화면에 적용되는 규칙(색·폰트 크기·간격·상태·금지 항목)을 5줄로 요약해서 보여줘라.
아직 파일을 만들지 마라.

1단계.
frontend/mockups/mockup-postings.html 을 새로 만들어라.
mockup.html에서 :root 토큰 블록과 사이드바(.sidebar/.nav/.me) 전체를 그대로 복사한다.
오른쪽 본문 영역은 아직 비워둔다. 사이드바 .active는 "채용 공고"에 그대로 둔다.
새 색·새 간격 값을 만들지 마라 — 토큰만 쓴다.

2단계.
본문에 헤더와 툴바를 붙여라.
헤더: mockup.html의 .head/.head-top을 복사하되 뒤로 가기 버튼(.back)은 빼고,
제목은 "채용 공고", 우측에 "공고 등록" 버튼(.btn .btn-primary).
툴바: mockup.html의 .toolbar와 .search를 통째로 복사하고, 드롭다운 항목만
전체 / 진행중 / 마감 으로 바꿔라. 검색 placeholder는 "공고명 검색".

3단계.
테이블을 붙여라. mockup.html의 .tpanel/.trow/.thead/.trow-item/.tfoot/.pager를 복사하고,
.trow의 grid-template-columns만 지시서의 완성 예시 값으로 교체한다.
컬럼은 공고명 / 상태 / 지원자 / 마감 / 등록일 5개, 체크박스 컬럼은 만들지 마라.
행 6개를 넣되 하나는 마감된 공고(상태 칸에 회색 "마감"), 하나는 아주 긴 공고명으로 해서
ellipsis가 도는지 보이게 하라. 행 클릭 시 mockup.html로 이동하게 한다.
```

**주의**: Claude가 스키마 변경, `mockup.html` 수정, 새 색·새 간격 값 추가, 라이브러리 설치를 제안하면 **수락하지 말고** 팀 채널에 물어본다.

## 검증 방법

```bash
python -m http.server 5500 --directory frontend/mockups
```

브라우저에서 `http://localhost:5500/mockup-postings.html` 을 열고 확인한다.

기대 결과:

- **`mockup.html`을 옆 탭에 함께 띄우고 나란히 비교한다.** 색·간격·글자 크기·모서리 반경·그림자가 눈으로 구분되지 않는다. 목업에 없는 요소를 새로 만들지 않았다
- 사이드바가 `mockup.html`과 눈으로 구분되지 않는다 (같은 폭·같은 색·같은 항목 높이)
- 행에 마우스를 올리면 배경이 바뀌고, Tab으로 이동하면 초록 포커스 링이 보인다
- 행을 클릭하면 지원자 화면(`mockup.html`)으로 넘어간다
- 긴 공고명이 두 줄로 밀리지 않고 `…`로 잘린다
- 창 폭을 줄여도 가로 스크롤이 생기지 않는다
- 콘솔에 에러가 없다

## 막히면 · 되돌리기

- **30분 넘게 막히면 혼자 붙들지 말고 팀 채널에 묻는다.** 혼자 Claude와 씨름한 2시간이, 팀장이 5분에 답할 것을 이상한 결과물로 바꿔놓는다.
- **결과가 이상해지면 고치려 들지 말고 버린다.** 코드를 읽어 고치는 것보다 되돌리는 편이 빠르고 안전하다.

```bash
git checkout -- .
```

그래도 이상하면 브랜치째 버리고 처음부터 다시 시작한다.

```bash
git checkout main && git branch -D <브랜치명>
```

- **`git status`에 지시서에 없는 파일이 떠 있으면 Claude가 범위를 벗어난 것이다.** 그 변경은 되돌리고 팀 채널에 알린다.
