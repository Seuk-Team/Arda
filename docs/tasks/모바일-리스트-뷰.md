# [모바일] 지원자 목록 모바일 뷰 (정적 목업)

> 담당: (이름) · 브랜치: `feat/mobile-list-mockup`
> **PR 단위**: 이 지시서 전체 = PR 1개
> **기능 번호 미지정** — 팀장이 붙인 뒤 발행한다

## 배경

공고의 지원자 화면([mockup.html](../../frontend/mockups/mockup.html))을 **768px 이하 폭에서 어떻게 보여줄지**만 만든다. 05-design §9가 정한 규칙은 셋이다 — 칸반 금지, 단계 탭 + 리스트로 대체, 단계 이동은 상세 화면 버튼으로.

**`mockup.html`을 고치지 않는다.** 모바일 전용 시안 파일을 따로 만들고, 나중에 팀장이 `mockup.html`에 미디어 쿼리로 합친다. 다른 사람 작업과 겹치지 않게 하려는 것이다.

## 시작 전에 읽는다

- [ ] [docs/05-design.md](../05-design.md) **전체를 한 번 읽는다.** 특히 §9 반응형 — 브레이크포인트 세 값은 확정이라 **바꾸지 않는다**
- [ ] [CLAUDE.md](../../CLAUDE.md)의 "범위" 항목
- [ ] `mockup.html`을 브라우저에서 열고 **창 폭을 좁혀 본다.** 어디서 깨지는지 직접 보고 시작한다

## 선행 조건 — 없으면 중단

- [ ] `main`에 `mockup.html`이 있고 브라우저에서 열린다
- [ ] 직전 UI 작업 PR이 머지돼 있다

## 가장 중요한 규칙 — 새로 만들지 않는다

- 값은 전부 `:root` 토큰으로. 브레이크포인트는 **768px 하나만** 쓴다(1100px는 상세 패널용이라 이 작업과 무관).
- 복사해 쓸 것: `.logo` `.search` `.stage` `.stage-progress` `.stage-accepted` `.stage-rejected` `.badge` `.btn` `.btn-primary` `.dpanel` 계열
- **터치 타깃은 최소 44×44px**(05-design §9, Apple HIG). 데스크톱에서 작던 것도 모바일에선 키운다
- **hover에 의존하는 정보를 만들지 않는다**(§5) — 모바일엔 hover가 없다
- 목업에 없는 요소가 필요해지면 **멈추고 팀장에게 묻는다.**

## 완료 조건

- [ ] `frontend/mockups/mockup-mobile.html` 1개 파일. `:root` 토큰 블록 + 필요한 클래스 복사
- [ ] **상단 바**: 왼쪽에 로고(`.logo`), 오른쪽에 검색 아이콘 버튼(44×44px). 데스크톱 사이드바는 넣지 않는다
- [ ] 그 아래 **공고명 + 마감 D-day** 한 줄
- [ ] **단계 탭**: 지원 접수 / 서류 검토 / 면접 / 최종 합격 / 불합격 5개. 가로로 넘치면 **탭 줄만 가로 스크롤**(§3에서 가로 스크롤은 칸반 영역에만 허용이지만, 단계 탭은 칸반을 대체하는 것이므로 허용한다). 탭 높이 44px, 선택된 탭 표시
- [ ] **지원자 카드 리스트** 6장. 카드 1장에: 이름(굵게) / 단계 뱃지 / 경력·학력 한 줄(`ellipsis`) / 지원일. 카드 높이 최소 72px, 탭 영역 확보
- [ ] 카드를 누르면 **상세가 전체 화면으로 덮는다**(`mockup.html`의 `.dpanel` 1100px 미디어 쿼리 방식 그대로 복사). 닫기 버튼 유지
- [ ] 상세 화면 하단에 **단계 변경 버튼 자리**를 둔다 — 드래그가 없는 환경의 유일한 이동 수단이다(§10). 버튼은 44px 이상
- [ ] 375px 폭에서 겹침·삐져나옴 없음. 페이지 자체의 가로 스크롤 없음(탭 줄 제외)
- [ ] 긴 이름 1건을 넣어 `ellipsis` 확인 (§7)

## 완성 예시

카드 리스트는 목업에 없다. **아래를 그대로 복사해 쓴다. 값을 바꾸지 않는다.**

```html
<style>
.mlist{ display:flex; flex-direction:column; gap:var(--sp-2); padding:var(--sp-3); }
.mcard{ display:block; width:100%; text-align:left; min-height:72px; padding:var(--sp-3);
        background:var(--bg-elev); border:var(--border-w) solid var(--border);
        border-radius:var(--r-card); font-family:var(--sans); cursor:pointer; }
.mcard:active{ background:var(--bg-sunken); }
.mcard:focus-visible{ outline:2px solid var(--leaf); outline-offset:2px; }
.mcard .mtop{ display:flex; align-items:baseline; gap:var(--sp-2); }
.mcard .mname{ flex:1; min-width:0; font-size:var(--font-body); font-weight:600; color:var(--text);
               white-space:nowrap; overflow:hidden; text-overflow:ellipsis; }
.mcard .msub{ display:block; margin-top:var(--sp-2); font-size:var(--font-sm); color:var(--text-sub);
              white-space:nowrap; overflow:hidden; text-overflow:ellipsis; }
.mcard .mdate{ display:block; margin-top:4px; font-size:var(--font-caption); color:var(--text-sub);
               font-variant-numeric:tabular-nums; }
</style>

<div class="mlist">
  <button class="mcard" type="button">
    <span class="mtop">
      <span class="mname">김도현</span>
      <span class="stage stage-progress">면접</span>
    </span>
    <span class="msub">2년 · OO대 컴퓨터공학 · Python · FastAPI</span>
    <span class="mdate">2026.03.12</span>
  </button>
</div>
```

`:hover` 대신 `:active`를 쓴 것은 모바일에 hover가 없기 때문이다(§5). **hover를 추가하지 마라.**

## Claude에게 시키기

**0 → 1 → 2 → 3 → 4 순서로 하나씩.** 각 단계 후 브라우저 창을 375px로 좁혀서 확인하고 넘어간다.

```
0단계.
docs/05-design.md 전체와 frontend/mockups/mockup.html 을 읽어라.
이 화면에 적용되는 규칙을 5줄로 요약해서 보여줘라. 아직 파일을 만들지 마라.

1단계.
frontend/mockups/mockup-mobile.html 을 만들어라.
mockup.html에서 :root 토큰 블록을 복사한다. 데스크톱 사이드바는 넣지 마라.
상단 바(왼쪽 로고, 오른쪽 44x44 검색 아이콘 버튼)와 그 아래 공고명 + D-day 한 줄까지만.
아이콘은 mockup.html에 있는 svg를 복사해 쓴다.

2단계.
단계 탭 5개를 붙여라 — 지원 접수 / 서류 검토 / 면접 / 최종 합격 / 불합격.
탭 높이 44px, 넘치면 탭 줄만 가로 스크롤. 선택된 탭이 무엇인지 보이게 하고,
탭을 누르면 선택이 바뀌게만 하라 (내용 필터링은 하지 않는다).

3단계.
지원자 카드 리스트 6장을 붙여라. 지시서의 .mlist/.mcard CSS를 그대로 복사해 쓴다.
단계 뱃지는 mockup.html의 .stage 클래스를 그대로 쓰고 색을 바꾸지 마라.
하나는 아주 긴 이름으로 넣어 ellipsis가 도는지 보이게 하라.

4단계.
카드를 누르면 상세가 전체 화면을 덮게 하라.
mockup.html의 .dpanel과 1100px 미디어 쿼리 방식을 복사해서 쓰되, 768px 기준으로 맞춘다.
상세 안에는 이름 + 단계, 지원 정보 3줄, 그리고 하단에 단계 변경 버튼 자리(높이 44px 이상)까지.
```

**주의**: Claude가 `mockup.html` 수정, 새 브레이크포인트 추가, 새 색·간격 값 추가, 하단 탭바·햄버거 메뉴 같은 목업에 없는 패턴을 제안하면 **수락하지 말고** 팀 채널에 물어본다.

## 검증 방법

```bash
python -m http.server 5500 --directory frontend/mockups
```

`http://localhost:5500/mockup-mobile.html` 을 열고 **개발자도구에서 폭을 375px로** 맞춘다.

기대 결과:

- 페이지 전체에 가로 스크롤이 없다 (단계 탭 줄만 가로로 밀린다)
- 카드·탭·버튼을 손가락으로 누를 수 있는 크기다(44px 이상)
- 긴 이름이 두 줄로 밀리지 않고 `…`로 잘린다
- 카드를 누르면 상세가 전체 화면을 덮고, 닫기 버튼으로 돌아온다
- 콘솔에 에러가 없다

## 막히면 · 되돌리기

- **30분 넘게 막히면 혼자 붙들지 말고 팀 채널에 묻는다.** 혼자 Claude와 씨름한 2시간이, 팀장이 5분에 답할 것을 이상한 결과물로 바꿔놓는다.
- **결과가 이상해지면 고치려 들지 말고 버린다.** 코드를 읽어 고치는 것보다 되돌리는 편이 빠르고 안전하다.

```bash
git checkout -- .
```

그래도 이상하면 브랜치째 버리고 처음부터 다시 시작한다.

```bash
git checkout main && git branch -D <브랜치명>
```

- **`git status`에 지시서에 없는 파일이 떠 있으면 Claude가 범위를 벗어난 것이다.** 그 변경은 되돌리고 팀 채널에 알린다.
