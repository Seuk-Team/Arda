# [C4] 지원 완료 확인 메일

> 담당: 팀원1 · 역할 C(파일·알림) · 브랜치: `feat/c4-confirm-mail`
> **PR 단위**: 이 지시서 전체 = PR 1개

## 배경

지원자는 제출 버튼을 누른 뒤 **접수됐는지 알 방법이 없다.** 지원 현황 조회(C5)는 범위 밖이라 확인 메일 한 통이 유일한 접수 증거다.

이미 [G2 메일 큐](G2-메일-큐-워커.md)가 있으므로 **새로 만들 것이 거의 없다.** 큐에 한 종류를 더 얹는 작업이다.

## 선행 조건 — 없으면 중단

아래가 하나라도 아니면 **시작하지 말고 팀 채널에 알린다.** 없는 것을 상상해서 만들지 않는다.

- [ ] [G2 메일 큐 · 워커](G2-메일-큐-워커.md) PR이 머지돼 있다
- [ ] [C2 지원서 제출 API](C2-지원서-제출-API.md) PR이 머지돼 있다

## 가장 중요한 규칙

- **[backend/app/models.py](../../backend/app/models.py)를 수정하지 않는다.** 컬럼이 부족해 보여도 추가하지 않는다. 멈추고 팀 채널에 묻는다.
- **[docs/00_overview/01-erd.md](../00_overview/01-erd.md)·[docs/00_overview/02-api.md](../00_overview/02-api.md)를 수정하지 않는다.** 공용 문서다.
- **인증·권한 코드를 넣지 않는다.** 인증은 팀장 담당(A1~A3)이고 아직 없다. 토큰 검사를 흉내 내면 나중에 팀장 것과 충돌한다. 사용자 id 가 필요한 자리는 `# TODO(A1): 토큰의 사용자로 채운다` 주석만 남긴다.
- **`main.py` 는 `include_router` 한 줄만** 건드린다. 그 파일의 다른 부분은 손대지 않는다.
- **메일 발송을 제출 API 안에서 동기로 하지 않는다.** `enqueue` 만 호출한다. 지원자가 제출 버튼을 누르고 SES 를 기다리면 안 된다.
- **메일 발송이 실패해도 지원서 저장은 성공해야 한다.** 큐 발행 실패를 잡아 로그만 남기고 201 을 준다.

## 완료 조건

- [ ] `docs/00_overview/email-templates.md` 에 **접수 확인** 문구 1종 추가 (기존 4종 형식 그대로)
- [ ] `email_logs.stage` 에 `applied` 로 기록된다 — 단계 변경 메일과 같은 테이블·같은 워커를 쓴다
- [ ] [C2 제출 API](C2-지원서-제출-API.md) 의 커밋 직후 `enqueue(...)` 한 줄 추가
- [ ] **큐 발행이 실패해도 지원서 저장은 롤백되지 않는다** — 예외를 잡아 로그만 남긴다
- [ ] 같은 지원서로 두 번 제출하면 409 이므로 확인 메일도 한 번만 나간다

## 검증 방법

```bash
curl -s -X POST localhost:8000/api/v1/public/postings/1/applications -H 'content-type: application/json' -d '{"name":"확인메일","email":"본인주소@example.com","phone":"010-1111-2222","privacy_agreed":true}'
psql "$DATABASE_URL" -c "select id, stage, status from email_logs where stage='applied' order by id desc limit 3"
# 큐를 일부러 끊고(SQS_QUEUE_URL 을 틀리게) 다시 제출
SQS_QUEUE_URL=https://sqs.invalid/none uv run uvicorn app.main:app --port 8001 &
curl -s -o /dev/null -w '큐 끊겼을 때 %{http_code}\n' -X POST localhost:8001/api/v1/public/postings/1/applications -H 'content-type: application/json' -d '{"name":"큐끊김","email":"x@y.com","phone":"010","privacy_agreed":true}'
```

기대 결과:

- 제출 → `email_logs` 에 `stage=applied` 행이 생긴다
- 워커가 돌면 `status=sent` 로 바뀌고 **메일이 도착한다**
- **큐가 끊긴 상태에서도 제출은 201** — 지원서는 저장된다
- 그때 서버 로그에 "확인 메일 큐 발행 실패" 가 남는다
- 같은 이메일 재제출은 409 이고 확인 메일이 추가로 안 나간다
