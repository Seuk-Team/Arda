# [D6] 담당자가 지원자 직접 등록

> 담당: 팀원3 · 역할 A(도메인 백엔드) · 브랜치: `feat/d6-manual-application`
> **PR 단위**: 이 지시서 전체 = PR 1개

## 배경

지원자가 메일이나 전화로 이력서를 보내오는 경우가 있다. 담당자가 대신 등록할 수 있어야 한다.

외부 지원(C1)과 **같은 테이블에 들어가되 `source` 로 구분된다.** 나중에 "어느 경로로 들어온 지원자가 더 많이 붙었나"를 셀 수 있게 하는 것이 이 컬럼의 목적이다.

외부 지원과 다른 점이 셋 있다 — **개인정보 동의를 담당자가 대신 체크할 수 없고**, 공고 상태가 `open` 이 아니어도 등록할 수 있고, 중복 이메일이어도 막지 않을 수 있어야 한다(같은 사람이 다시 지원한 경우).

## 선행 조건 — 없으면 중단

아래가 하나라도 아니면 **시작하지 말고 팀 채널에 알린다.** 없는 것을 상상해서 만들지 않는다.

- [ ] [D1 지원자 목록 · 상세 API](D1-지원자-API.md) PR이 머지돼 있다

## 가장 중요한 규칙

- **[backend/app/models.py](../../backend/app/models.py)를 수정하지 않는다.** 컬럼이 부족해 보여도 추가하지 않는다. 멈추고 팀 채널에 묻는다.
- **[docs/00_overview/01-erd.md](../00_overview/01-erd.md)·[docs/00_overview/02-api.md](../00_overview/02-api.md)를 수정하지 않는다.** 공용 문서다.
- **인증·권한 코드를 넣지 않는다.** 인증은 팀장 담당(A1~A3)이고 아직 없다. 토큰 검사를 흉내 내면 나중에 팀장 것과 충돌한다. 사용자 id 가 필요한 자리는 `# TODO(A1): 토큰의 사용자로 채운다` 주석만 남긴다.
- **`main.py` 는 `include_router` 한 줄만** 건드린다. 그 파일의 다른 부분은 손대지 않는다.
- **`backend/app/api/applications.py` 만 고친다.**
- **`source="manual"` 로 넣는다.** 외부 지원과 구분되지 않으면 이 기능의 의미가 없다.
- **`privacy_agreed_at` 을 담당자가 대신 채우지 않는다.** 본인 동의가 아닌 것을 동의로 기록하면 안 된다. 오프라인 동의 시각을 담당자가 **명시적으로 입력**하게 하고, 없으면 등록을 거절한다.

## 완료 조건

- [ ] `POST /api/v1/postings/{id}/applications` — 담당자 등록. 성공 **201**
- [ ] `source` 는 `"manual"` 고정
- [ ] `privacy_agreed_at` 을 **요청 본문으로 받는다**(오프라인 동의 시각). 없으면 **422**
- [ ] 공고 상태가 `draft` · `closed` 여도 **등록된다** (외부 지원과 다르다)
- [ ] 중복 이메일이면 **409**, 단 응답 메시지에 기존 지원서 `id` 를 담아 담당자가 확인할 수 있게 한다
- [ ] 접수 이력 1행 기록. **`changed_by` 는 등록한 담당자** — 지금은 인증이 없으므로 `None` + `TODO(A1)` 주석
- [ ] `created_at` 을 임의로 과거로 넣지 않는다 (등록 시각이 진실이다)

## 완성 예시

**이 형태를 그대로 따른다.**

```python
# backend/app/api/applications.py (추가분)
@router.post("/postings/{posting_id}/applications",
             response_model=ApplicationDetail, status_code=http.HTTP_201_CREATED)
def create_manual(posting_id: int, body: ManualApplicationCreate,
                  db: Session = Depends(get_db)):
    if db.get(JobPosting, posting_id) is None:
        raise HTTPException(http.HTTP_404_NOT_FOUND, "공고를 찾을 수 없습니다")
    # 외부 지원과 달리 status 를 보지 않는다. 마감된 공고에도 담당자는 넣을 수 있다

    dup = db.scalar(select(Application.id).where(
        Application.job_posting_id == posting_id, Application.email == body.email))
    if dup:
        # 그냥 409 만 주면 담당자가 기존 건을 찾아 헤맨다. id 를 함께 준다
        raise HTTPException(http.HTTP_409_CONFLICT,
                            f"이미 등록된 지원자입니다 (application_id={dup})")

    row = Application(job_posting_id=posting_id, source="manual",
                      current_stage="applied", **body.model_dump())
    db.add(row)
    db.flush()
    # TODO(A1): changed_by 를 토큰의 담당자로 채운다
    db.add(StageHistory(application_id=row.id, from_stage=None,
                        to_stage="applied", changed_by=None))
    db.commit()
    return ApplicationDetail.model_validate(row)
```

동의 시각은 **받는다**. 서버가 지어내지 않는다.

```python
class ManualApplicationCreate(BaseModel):
    name: str
    email: str
    phone: str
    # 담당자가 대신 체크할 수 없다. 오프라인으로 받은 동의 시각을 명시적으로 넣게 한다
    privacy_agreed_at: datetime
```

## 검증 방법

```bash
P=localhost:8000/api/v1
curl -s -X POST $P/postings -H 'content-type: application/json' -d '{"title":"마감된공고","status":"closed"}'
curl -s -X POST $P/postings/2/applications -H 'content-type: application/json' -d '{"name":"직접등록","email":"m@x.com","phone":"010-3333-4444","privacy_agreed_at":"2026-08-20T10:00:00Z"}' | python -c 'import sys,json;d=json.load(sys.stdin);print("source:",d["source"],"stage:",d["current_stage"])'
curl -s -o /dev/null -w '동의시각없음 %{http_code}\n' -X POST $P/postings/2/applications -H 'content-type: application/json' -d '{"name":"x","email":"y@z.com","phone":"010"}'
curl -s -X POST $P/postings/2/applications -H 'content-type: application/json' -d '{"name":"직접등록","email":"m@x.com","phone":"010","privacy_agreed_at":"2026-08-20T10:00:00Z"}' | head -c 200
psql "$DATABASE_URL" -c "select source, count(*) from applications group by source"
```

기대 결과:

- **마감된 공고에도 등록된다** (201)
- `source` 가 **`manual`**
- `privacy_agreed_at` 없이 보내면 **422**
- 중복 이메일 → **409**, 메시지에 기존 `application_id` 가 보인다
- `stage_history` 에 접수 1행이 남는다
- `source` 별 집계에 `form` 과 `manual` 이 함께 보인다
