# M1 에이전트 도구 스펙

> 담당: suvisdev · 역할 에이전트 · 브랜치: `feat/m1-agent-tools`
> **PR 단위**: 도구 스펙 확정 + 서비스 레이어 인터페이스 = PR 1개

## 배경

에이전트가 자연어 명령을 받아 기존 REST API를 호출한다.
도구는 **읽기**(확인 없이 실행)와 **쓰기**(반드시 확인 카드 표시 후 사람 승인)로 나눈다.
16개 시나리오를 검증한 결과, **v1은 6개 도구**로 전체 시나리오를 커버한다.

## 도구 목록

### 읽기 도구 (3개) — 확인 없이 바로 실행

#### 1. `search_applications`

| 항목 | 내용 |
|---|---|
| **매핑** | `GET /api/v1/applications` (H1) |
| **용도** | 지원자 통합 검색. 에이전트의 핵심 도구 — 16개 시나리오 중 14개에서 호출 |

**파라미터**

| 이름 | 타입 | 설명 |
|---|---|---|
| `q` | string? | 이름 또는 이메일 검색 |
| `stage` | string[]? | 단계 필터 (applied, screening, interview, accepted, rejected) |
| `posting_id` | int? | 특정 공고로 한정 |
| `sort` | string? | created_at \| score |
| `order` | string? | desc \| asc |
| `limit` | int? | 기본 50, 최대 200 |

**시나리오 예시**
- "Python 2년 이상 추려줘" → `q` 검색
- "서류 단계 몇 명이야" → `stage` 필터 + 카운트
- "평균 3점 이상만" → `sort=score` 정렬

---

#### 2. `get_application`

| 항목 | 내용 |
|---|---|
| **매핑** | `GET /api/v1/applications/{id}` (D4) |
| **용도** | 지원자 상세 조회. 평가·메모·파일·단계 이력을 한 번에 반환 |

**파라미터**

| 이름 | 타입 | 설명 |
|---|---|---|
| `application_id` | int | 지원자 ID |

**포함 데이터**: evaluations + notes + files + stage_history (selectinload)

> 이 도구가 평가·이력·면접관을 모두 포함하므로, 별도 `get_evaluations` / `get_history` / `list_interviewers` 도구가 불필요하다.

---

#### 3. `list_postings`

| 항목 | 내용 |
|---|---|
| **매핑** | `GET /api/v1/postings` (B1) |
| **용도** | 채용공고 목록 조회. 공고 이름 → posting_id 변환 후 search_applications에 전달 |

**시나리오 예시**
- "백엔드 개발자 공고 지원자 보여줘" → 공고 찾기 → 지원자 검색
- "진행 중인 공고 뭐 있어" → 상태 필터

---

### 쓰기 도구 (3개) — 반드시 확인 카드 표시 → 사람 승인 후 실행

> **원칙**: 확인 없이 쓰기 도구가 실행되지 않음을 테스트로 강제한다 (agent.md §5 W5).
> 확인 카드는 앰버 점선(AI 제안) → 사람 클릭 → 잎초록 실선(확정) (05-design.md §1).

#### 4. `change_stage`

| 항목 | 내용 |
|---|---|
| **매핑** | `PATCH /api/v1/applications/{id}/stage` (D3) |
| **용도** | 지원자 단계 변경. 이력 자동 기록(D5) + 메일 큐 발행(G1) |

**파라미터**

| 이름 | 타입 | 설명 |
|---|---|---|
| `application_id` | int | 지원자 ID |
| `to_stage` | string | screening \| interview \| accepted \| rejected |

**확인 카드**: "김도현을 면접 단계로 옮길까요?" → 승인/거절

**시나리오 예시**
- "김도현 서류 통과시켜" → 1건 변경
- "서류 통과한 사람 전부 면접으로" → 일괄 변경 (각각 확인)
- "평균 2점 이하 전부 불합격" → 검색 → 일괄 변경

**전이 규칙**: stages.py의 validate_transition을 그대로 사용한다.
- 전진은 한 칸씩만 (applied → screening → interview → accepted)
- rejected는 어느 단계에서든 가능
- 뒤로 이동은 허용 (담당자 권한)

---

#### 5. `assign_interviewer`

| 항목 | 내용 |
|---|---|
| **매핑** | `POST /api/v1/applications/{id}/interviewers` (E3) |
| **용도** | 면접관 배정. 수동 지정 또는 자동 추천(가중 라운드로빈) 후 어드민 확인 |

**파라미터**

| 이름 | 타입 | 설명 |
|---|---|---|
| `application_id` | int | 지원자 ID |
| `interviewer_ids` | int[] | 배정할 면접관 ID 목록 |

**확인 카드**: "김도현에게 이은진을 면접관으로 배정할까요?" → 승인/거절

**권한**: 어드민만 (ADR-0013). 현재 assignments.py에 권한 체크 추가 필요.

---

#### 6. `draft_email`

| 항목 | 내용 |
|---|---|
| **매핑** | 신규 API (메일 큐 G1과 연동) |
| **용도** | 메일 초안 생성. 발송은 에이전트가 하지 않음 — 사람이 확인·수정 후 발송 |

**파라미터**

| 이름 | 타입 | 설명 |
|---|---|---|
| `application_ids` | int[] | 대상 지원자 ID |
| `template` | string? | 메일 종류 (면접 안내, 합격 통보 등) |
| `custom_message` | string? | 추가 메시지 |

**확인 카드**: 초안 미리보기 → 수정 가능 → "이대로 보낼까요?" → 승인/거절

## v1에서 제외한 도구 (필요 시 추가)

| 도구 | 제외 이유 |
|---|---|
| `get_evaluations` | get_application이 평가를 포함 |
| `get_history` | get_application이 이력을 포함 |
| `list_applications` | search_applications가 posting_id 필터 지원 |
| `list_interviewers` | get_application이 배정 면접관 포함 |

## 시나리오 검증 결과

16개 시나리오를 6개 도구로 전부 커버. 호출 빈도:

| 도구 | 호출 수 | 판정 |
|---|---|---|
| search_applications | 14/16 | 필수 |
| change_stage | 4/16 | 필수 |
| get_application | 2/16 | 유용 |
| assign_interviewer | 2/16 | 유용 |
| draft_email | 2/16 | 유용 |
| list_postings | 2/16 | 유용 |
