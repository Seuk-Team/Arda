# [B4·B6] 공고 마감일 자동 마감 + 공개 지원 링크

> 담당: 팀원3 · 역할 A(도메인 백엔드) · 브랜치: `feat/b4-deadline-public-link`
> **PR 단위**: 이 지시서 전체 = PR 1개

## 배경

지금은 담당자가 공고를 손으로 닫아야 하고, 지원 폼 주소가 `/public/postings/1` 이라 **숫자만 바꾸면 남의 공고가 열린다.**

마감일이 지나면 자동으로 닫히게 하고, 공개 링크에는 **추측할 수 없는 토큰**을 쓴다.

두 기능 다 [01-erd.md](../00_overview/01-erd.md) `job_postings` 비고에 "추가 여지"로 적혀 있던 것이다 — **컬럼 추가가 필요하므로 팀장 합의가 선행된다.**

## 선행 조건 — 없으면 중단

아래가 하나라도 아니면 **시작하지 말고 팀 채널에 알린다.** 없는 것을 상상해서 만들지 않는다.

- [ ] [B2 공고 CRUD API](B2-공고-CRUD-API.md) PR이 머지돼 있다
- [ ] **`job_postings` 에 `deadline` · `public_token` 컬럼을 추가하는 건을 팀장이 합의·반영했다** — 스키마 변경은 팀장 소관이다. 반영 전에는 시작하지 않는다

## 가장 중요한 규칙

- **[backend/app/models.py](../../backend/app/models.py)를 수정하지 않는다.** 컬럼이 부족해 보여도 추가하지 않는다. 멈추고 팀 채널에 묻는다.
- **[docs/00_overview/01-erd.md](../00_overview/01-erd.md)·[docs/00_overview/02-api.md](../00_overview/02-api.md)를 수정하지 않는다.** 공용 문서다.
- **인증·권한 코드를 넣지 않는다.** 인증은 팀장 담당(A1~A3)이고 아직 없다. 토큰 검사를 흉내 내면 나중에 팀장 것과 충돌한다. 사용자 id 가 필요한 자리는 `# TODO(A1): 토큰의 사용자로 채운다` 주석만 남긴다.
- **`main.py` 는 `include_router` 한 줄만** 건드린다. 그 파일의 다른 부분은 손대지 않는다.
- **`models.py` 와 `01-erd.md` 를 직접 고치지 않는다.** 컬럼 추가는 팀장이 한다. 이 지시서는 컬럼이 **이미 있다는 전제**로 API 만 만든다.
- **`public_token` 을 순번이나 예측 가능한 값으로 만들지 않는다.** `secrets.token_urlsafe(16)` 를 쓴다.
- **자동 마감을 별도 스케줄러로 만들지 않는다.** 배치 프로세스를 하나 더 띄우면 운영이 복잡해진다. 조회 시점에 판정한다.

## 완료 조건

- [ ] `PATCH /api/v1/postings/{id}` 가 `deadline` 을 받는다 (날짜)
- [ ] `POST /api/v1/postings/{id}/public-link` — 토큰 발급·재발급. 응답에 전체 URL
- [ ] `GET /api/v1/public/postings/by-token/{token}` — 토큰으로 공고 조회
- [ ] **자동 마감**: 조회 시 `deadline < 오늘` 이고 `status="open"` 이면 `closed` 로 바꿔 저장한 뒤 응답한다
- [ ] 마감된 공고의 공개 링크로 지원 시도 → **410 Gone** (404 와 구분한다 — "없는 것"이 아니라 "끝난 것"이다)
- [ ] 토큰 재발급 시 **이전 토큰은 즉시 무효**
- [ ] `deadline` 이 과거 날짜로 들어오면 **422**
- [ ] 목록 응답에 `deadline` 과 `D-n` 계산값 포함 (화면이 `D-12` 로 표시한다)

## 완성 예시

**이 형태를 그대로 따른다.**

```python
# backend/app/api/postings.py (추가분)
import secrets
from datetime import date

def _auto_close(db: Session, posting: JobPosting) -> JobPosting:
    """조회 시점에 판정한다. 스케줄러를 따로 띄우면 운영할 것이 하나 더 늘어난다."""
    if posting.deadline and posting.status == "open" and posting.deadline < date.today():
        posting.status = "closed"
        db.commit()
    return posting


@router.post("/{posting_id}/public-link")
def issue_public_link(posting_id: int, db: Session = Depends(get_db)):
    posting = _get_or_404(db, posting_id)
    # 순번이면 옆 번호로 남의 공고가 열린다. 추측 불가능한 값을 쓴다.
    # 재발급하면 이전 토큰은 그 순간 무효가 된다.
    posting.public_token = secrets.token_urlsafe(16)
    db.commit()
    return {"public_token": posting.public_token,
            "url": f"/apply/{posting.public_token}"}
```

마감된 공고는 **410** 으로 구분한다.

```python
if posting.status == "closed":
    # 404 는 "그런 공고 없음"이다. 지원자는 링크가 틀린 줄 안다.
    # 410 Gone 이어야 "있었지만 끝났다"가 전달된다.
    raise HTTPException(http.HTTP_410_GONE, "마감된 공고입니다")
```

## 검증 방법

```bash
P=localhost:8000/api/v1
curl -s -o /dev/null -w '과거마감일 %{http_code}\n' -X PATCH $P/postings/1 -H 'content-type: application/json' -d '{"deadline":"2020-01-01"}'
curl -s -X PATCH $P/postings/1 -H 'content-type: application/json' -d '{"deadline":"2026-12-31","status":"open"}' >/dev/null
T=$(curl -s -X POST $P/postings/1/public-link | python -c 'import sys,json;print(json.load(sys.stdin)["public_token"])')
echo "토큰 길이: ${#T}"
curl -s -o /dev/null -w '토큰조회 %{http_code}\n' $P/public/postings/by-token/$T
T2=$(curl -s -X POST $P/postings/1/public-link | python -c 'import sys,json;print(json.load(sys.stdin)["public_token"])')
curl -s -o /dev/null -w '옛토큰 %{http_code}\n' $P/public/postings/by-token/$T
psql "$DATABASE_URL" -c "update job_postings set deadline='2020-01-01' where id=1"
curl -s $P/postings/1 | python -c 'import sys,json;print("자동마감 후 status:",json.load(sys.stdin)["status"])'
curl -s -o /dev/null -w '마감공고 지원 %{http_code}\n' $P/public/postings/by-token/$T2
```

기대 결과:

- 과거 `deadline` → **422**
- 토큰 길이가 20자 이상이고 순번이 아니다
- 토큰으로 조회 → **200**
- 재발급 후 **옛 토큰 → 404**
- `deadline` 이 지난 공고를 조회하면 `status` 가 **`closed` 로 바뀌어 있다**
- 마감 공고의 공개 링크 → **410** (404 가 아니다)
