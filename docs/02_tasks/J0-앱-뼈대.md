# [J0] FastAPI 앱 뼈대

> 담당: 팀장 · 브랜치: `feat/j0-app-skeleton`
> **PR 단위**: 이 지시서 전체 = PR 1개
> **번호 J0**: 기능 목록에 없는 작업이다. [J1 Docker](J1-docker-compose.md) · [J2 AWS 배포] · [J3 Swagger]의 **공통 선행**이라 0번을 붙였다. J3(Swagger)는 FastAPI가 `/docs`를 자동 생성하므로 이 작업으로 함께 끝난다.

## 배경

`backend/`에 지금 있는 것은 `models.py`(테이블 9개)와 `db.py`(엔진·세션)뿐이다. **`pyproject.toml`에 `fastapi`가 없고 `main.py`도 없다.** 앱이 뜨지 않으므로 [B2 공고 API](B2-공고-CRUD-API.md)도 [J1 Docker](J1-docker-compose.md)도 시작할 수 없다.

**지금 이 프로젝트에서 가장 앞을 막고 있는 것이 이 파일 하나다.** 30분짜리이고, 여기서 정한 라우터 등록 방식·에러 형태를 이후 모든 API가 따라 쓴다.

팀장이 직접 한다 — 다른 사람이 만들면 그 위에 올라갈 라우터 규약이 사람마다 달라진다.

## 이걸 Claude에게 시킨다

작업 폴더에서 Claude Code를 열고 **아래를 순서대로 하나씩** 붙여넣는다.

```
0단계.
backend/pyproject.toml, backend/app/db.py, backend/app/models.py 의 앞부분 40줄,
backend/.env.example, docs/00_overview/02-api.md 를 읽어라.

읽은 뒤 아래 세 가지를 알려줘라. 아직 파일을 만들지 마라.
- 모든 API 경로 앞에 붙는 접두사가 무엇인지
- db.py 가 세션을 어떤 이름의 의존성으로 넘기는지
- 테이블을 만들 때 마이그레이션을 쓰는지 create_all 을 쓰는지, 그 근거가 어디에 적혀 있는지
```

```
1단계.
backend 에서 fastapi 와 uvicorn[standard] 를 uv add 로 추가해라.
pyproject.toml 을 직접 편집하지 말고 uv add 명령을 써라.
추가 후 uv.lock 이 갱신됐는지 확인해서 보여줘라.
```

```
2단계.
backend/app/main.py 를 만들어라. 아래 내용만 넣는다.

- lifespan 에서 Base.metadata.create_all(engine) 을 호출한다.
  app.models 를 import 해야 테이블이 등록되니 함께 import 하고 noqa 주석을 단다.
- FastAPI(title="Arda ATS API", version="0.1.0", lifespan=lifespan)
- GET /health 하나. {"status": "ok"} 를 반환한다. 접두사 없이 루트에 둔다.
- 라우터는 하나도 등록하지 마라. 대신 "여기에 include_router 를 한 줄씩 추가한다" 라는
  주석만 남겨라.

그리고 backend/app/api/__init__.py 와 backend/app/schemas/__init__.py 를 빈 파일로 만들어라.

하지 말 것:
- CORS, 인증, 미들웨어, 예외 핸들러, 로깅 설정을 넣지 마라. 지금 필요 없다.
- backend/app/models.py 와 db.py 를 수정하지 마라.
- Alembic 을 추가하지 마라.
```

```
3단계.

그리고 DB 에 테이블이 9개 만들어졌는지 확인해서 목록을 보여줘라.
실패하면 고치기 전에 원인을 먼저 설명해라.
```

```
마지막 단계 — 여기서 멈추지 마라.

위 작업을 끝내고 PR 을 올렸으면, 이어서 다음 할 일을 스스로 찾아 그대로 수행해라.

1. docs/00_overview/04-team.md 에서 내 도메인을 확인하고, docs/01_role/<내 도메인>.md 의 작업 큐를 읽어라.
   (작업 큐는 로드맵에만 있다. docs/00_overview/06-weekly.md 는 주 마감 게이트·도메인 간 일정용이다)
2. 큐에서 선행이 풀린 다음 작업을 찾아라. 큐가 비었거나 전부 막혀 있으면
   멈추고 무엇이 막혔는지 팀 채널에 알려라.
3. 찾은 작업의 지시서가 docs/02_tasks/ 에 링크돼 있으면 열고, 선행 조건을 먼저 확인해라.
   선행 조건이 안 채워졌으면 거기서 멈추고 무엇이 막혔는지 알려줘라.
4. 선행 조건이 채워졌으면 새 브랜치를 만들고 그 지시서의 "Claude에게 시키기" 를

지키는 것:
- 지시서가 있는 작업만 한다. 큐 항목에 지시서가 없으면 "지시서 없음 — 오너가 직접 쪼갤 것"

- 지시서에 적힌 산출 파일 밖을 고치지 않는다. 다른 도메인 파일과 공용 파일은 건드리지 않는다.
  (공용: frontend/mockups/mockup.html · docs/00_overview/01-erd.md · docs/00_overview/02-api.md · backend/app/models.py)
- 작업 사이마다 git status 를 확인해서 지시서에 없는 파일이 있으면 되돌린다.
```

**주의**: Claude가 CORS·인증·미들웨어·예외 핸들러·Alembic·라우터 등록을 "겸사겸사" 제안하면 **전부 거절한다.** 이 파일은 작을수록 좋다. 나중에 필요해지면 그때 해당 지시서에서 추가한다.

## 완성 예시

**결과가 이것과 크게 다르면 다시 시킨다.**

```python
# backend/app/main.py
"""Arda ATS API — 앱 진입점.

라우터는 각 기능 지시서에서 include_router 한 줄로 등록한다.
여기에 비즈니스 로직을 두지 않는다.
"""

from contextlib import asynccontextmanager

from fastapi import FastAPI

from app import models  # noqa: F401 — 테이블을 메타데이터에 등록하려면 import 가 필요하다
from app.db import Base, engine


@asynccontextmanager
async def lifespan(app: FastAPI):
    # 스키마가 굳기 전까지는 마이그레이션 없이 create_all 로 만든다 (app/db.py 참고)
    Base.metadata.create_all(engine)
    yield


app = FastAPI(title="Arda ATS API", version="0.1.0", lifespan=lifespan)


@app.get("/health", tags=["system"])
def health():
    return {"status": "ok"}


# 라우터는 여기에 한 줄씩 추가한다. 각 라우터가 자기 prefix 를 갖는다.
# 예: from app.api.postings import router as postings_router
#     app.include_router(postings_router)
```
