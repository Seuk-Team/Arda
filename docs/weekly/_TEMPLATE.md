## 5. 충돌 방지

**원칙: 한 사람 = 자기 파일. 두 사람이 같은 파일을 열지 않는다.**

| 팀원 | 이번 주에 만드는/고치는 파일 |
|---|---|
| 팀원1 | |
| 팀원2 | |
| 팀원3 | |
| 팀원4 | |

- 위 표에 **같은 파일이 두 번 나오면 계획이 틀린 것**이다. 배분을 다시 짠다.
- **공용 파일은 아무도 고치지 않는다.** 고쳐야 하면 팀 채널 → 팀장이 처리.
  - 공용: `frontend/mockups/mockup.html` · `docs/01-erd.md` · `docs/02-api.md` · `backend/app/models.py`
- 자기 지시서에 없는 파일이 `git status`에 뜨면 되돌리고 팀 채널에 알린다.

## 7. 추가 작업 규칙

주중에 새 작업이 생기면 **이 파일을 고치지 않는다.** 계획서를 고치면 "원래 계획이 뭐였는지"가 사라져서 나중에 왜 늦었는지 알 수 없게 된다.

**대신 파일을 하나 더 만든다.**

```
docs/weekly/
├─ _TEMPLATE.md
├─ W1.md    ← 주 시작 시 확정. 고치지 않음
├─ W1-2.md  ← 주중 2번째 문서
└─ W1-2.md  ← 주중 3번째 문서
```

추가 파일에는 이것만 적는다.

```markdown
# W1-2 — <제목>

> **발생** MM/DD · **요청** (누가) · **담당** 팀원N · **분량** N점
> **본 계획서**: [W1.md](W1.md)

## 왜 생겼나
(한두 줄. 계획에 없던 이유)

## 할 일
- [ ] 지시서: [](../tasks/)
- [ ] 산출 파일: ``
- [ ] 브랜치: `feat/`

## 누구 몫을 줄였나
추가는 **공짜가 아니다.** 이 사람이 원래 하려던 것 중 무엇을 뺐는지 적는다.
- 뺀 것: (없으면 "없음 — 초과 근무로 흡수"라고 솔직히 적는다)

## 충돌 확인
- [ ] 이 작업이 만지는 파일이 W1.md 5장 표의 다른 사람 파일과 겹치지 않는다
```

**한 주에 문서가 4장을 넘으면** 그 주 계획이 틀렸다는 뜻이다. 다음 주 계획서를 쓸 때 원인을 한 줄 적는다.
