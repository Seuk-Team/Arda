- **초기 버전: 09/04(금) · 1차 완성: 09/30(수).** 초기 버전의 정의는 [00-overview.md](../00_overview/00-overview.md) 진행 순서 절 — **앱은 초기 버전 범위 밖**이고, 그 시점까지의 기여는 전환기 백엔드 분담(B2·D1)과 스택 ADR-0010이다. 주차 기준: W1 08/24~28 · W2 08/31~09/04 · W3 09/07~11 · W4 09/14~18 · W5 09/21~25 · 09/28~30 통합 버퍼.

- **팀장 머지·검수·뒷처리는 매주 금요일 최소 1회** (필요시 주 2~3회 수시). 팀장 승인이 필요한 PR(스키마·02-api·공용 문서·타 도메인 파일)은 금요일 검수에 걸리도록 **목요일까지 올린다.** 자기 도메인 내부 PR은 이 사이클과 무관하게 수시 셀프 머지.

## 1. 미션

담당자·면접관용 **모바일 네이티브 앱**. 이동 중에 지원자를 확인하고 단계를 바꾸고 평가를 남긴다. 웹과 **같은 API**를 쓰는 두 번째 클라이언트 — "API를 제대로 설계하면 클라이언트가 몇 개든 붙는다"를 증명하는 트랙이다.

## 2. 스택 (확정 — [ADR-0010](../03_decision/0010-앱-expo-확정.md))

**Expo (React Native) + TypeScript.**

- 웹이 React·TS 확정([ADR-0006](../03_decision/0006-프론트-react-확정.md))이라 팀 역량·컴포넌트 사고방식 재사용
- 디자인 토큰·화면 지도(05-design)를 그대로 이식 가능
- 1인이 09/30 기한 안에 데모까지 가능한 현실적 선택지 — Expo Go로 빌드 없이 팀 전원 폰에서 실행
- 대안 비교(Flutter: 새 언어 학습 비용 / PWA: "앱 승격" 취지에 미달)를 ADR에 기록하고 팀장 확정 후 시작

## 3. 범위

**포함** — 로그인(JWT) · 공고 리스트 · 지원자 리스트(단계 탭 필터 + 압축 퍼널 바) · 지원자 상세(지원 정보·단계 이력 타임라인·평가 목록) · **단계 변경 버튼**(드래그 대신 — 기획 §2-3) · 평가 작성 · 이력서 열람(presigned URL). 화면 설계 기준: [planning/00_summary_ko.md](../04_planning/00_summary_ko.md) 8장 + `frontend/mockups/mockup-mobile.html`.

**제외** — 지원 폼(지원자용 외부 링크는 웹 전용) · 칸반(모바일 금지 원칙) · 앱 내 푸시 알림 G7(△ 여유 — 하게 되면 별도 합의) · 스토어 배포(데모는 Expo Go, 여유 시 EAS 빌드 APK까지).

## 4. 인터페이스 계약

**의존** — 백엔드 API 전부 ([02-api.md](../00_overview/02-api.md)). **앱 때문에 API를 바꾸지 않는 것이 원칙** — 부족한 게 발견되면 백엔드 오너와 인터페이스 PR로 합의(그 자체가 발표 소재다). 인증 A1이 M2의 선행. **제공** — 없음 (순수 소비자. 그래서 격리가 가장 높다 — 앱이 실패해도 다른 파트가 안 죽는다).

**해결된 확인 (2026-08-25)**

- **D1 relationship** — 지시서 예시가 `selectinload(Application.stage_history)` 를 쓰는데 `models.py` 에 `relationship()` 이 하나도 없었다. 수정 금지 파일이라 팀 채널에 확인 요청했고, 팀장이 자식 4종을 #45 로 추가해 해결. 이후 지시서 예시대로 진행했다.
- **ADR-0010 스택** — Flutter 비교 검토 후 Expo 확정(#53, 확정자 bestcow). 판단 기준을 학습 비용이 아니라 데모 배포 경로(팀 기기 iOS 1 · Android 4)로 잡았다.

**대기 중인 확인 (2026-08-25)**

- **D6 인증 적용 여부** — 지시서는 "인증·권한 코드를 넣지 않는다(아직 없으므로)"고 하지만, #61(A3)로 인증이 들어와 대상 파일 `applications.py` 에 이미 적용돼 있다. [02-api.md](../00_overview/02-api.md) 는 D6 을 `recruiter+` 로 명시한다. 지시서대로 두면 같은 파일에서 이 엔드포인트만 열린다. `require_roles("admin","recruiter")` 적용 여부를 팀장에게 확인 중이며, **답을 받은 뒤 착수한다.**

## 7. 리스크

- **개인 폰·개발 환경 편차** (iOS는 Expo Go 제약 가능) → M1에서 팀 전원 기기로 Expo Go 실행을 먼저 확인하고, 안 되는 기기는 데모 대상에서 뺀다.
- **웹과 룩이 어긋남** → 토큰을 코드로 이식하고(임의 색 금지), 완료 기준에 목업 대조 포함.
- **백엔드 지연** → M1이 전부 API 무관. 전환기 큐로 본인이 선행을 만든다.

## 8. 면접 스토리

- **같은 API로 웹·앱 두 클라이언트** — 클라이언트 추가가 서버 변경 0으로 끝났는가, 아니면 무엇이 부족해 무엇을 바꿨는가
- 모바일에서 칸반을 버리고 리스트+단계 변경 버튼으로 간 **UX 재설계 근거** (기획 §2-3을 본인 언어로)
