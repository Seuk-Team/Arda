## 1. 미션

목업 8장을 실제 React 제품으로. **"UI가 스펙이다"의 그 UI를 최종 제품까지 끌고 간다.** 칸반 드래그·낙관적 업데이트가 이 프로젝트의 얼굴이다.

## 2. 범위

**포함**

- React 앱 뼈대: Vite·TS·라우팅·토큰 CSS 변수 이식·공통 컴포넌트(사이드바·테이블·뱃지·버튼·인풋·토스트) — *팀장 전담에서 이관*

- 전 화면의 페이지 컴포넌트화 + API 연동
- 칸반 뷰 D2 · 드래그 단계 이동 D3 · 낙관적 업데이트·롤백 — *팀장 전담에서 이관*
- 일괄 단계 변경 D9 · 업로드 진행률 F4 · 반응형(768px 모바일 웹)

- Vercel 배포 설정 (인프라와 협업 — 프로젝트 연결은 인프라, 빌드 설정은 프론트)

**제외**

- `frontend/mockups/mockup.html` 색 리터럴 정리 — 팀장 (W1-2 별건, 금요일). **그 전까지 토큰 `:root` 블록 복사 규칙 유지**
- 대시보드 화면 — 보류 유지 (W1-2 결정. 3주차 이후 여유 시)

## 3. 인터페이스 계약

**의존** — 백엔드 API ([02-api.md](../00_overview/02-api.md)). M1·M2는 목데이터로 진행하므로 백엔드를 기다리지 않는다. **목데이터 필드명은 [01-erd.md](../00_overview/01-erd.md)와 동일하게** — 연동이 필드 교체만으로 끝나게.

### 10번 메모 — 프로필 사진 (2026-08-31 보류)

사이드바 좌하단 프로필은 실데이터(이름·역할)로 붙었지만 **사진은 없다** — `users` 테이블에 사진 컬럼이 없어 지금은 이름 첫 글자 이니셜 아바타다. 팀장이 더미 AI 사진을 만들어 두면 그때 붙인다.

- **필요 장수**: 5장이면 설정 → 사용자·권한 탭 목데이터(5명)까지 채워진다. 좌하단 본인 자리만 쓰면 로그인 계정 수(보통 2장).
- **규격**: 정사각형 1:1 · 512×512 · png/webp · 장당 200KB 이하. 표시는 44px 원형이라 얼굴이 가운데 와야 한다.
- **붙이는 방식 (미정 — 팀장이 사진 줄 때 확정)**
  - A안(권장): `users.avatar_url` 컬럼 추가 + 파일은 `frontend/app/public/avatars/`. 계정마다 다른 사진이 붙고 업로드 기능으로 확장 가능. **스키마 변경이라 [01-erd.md](../00_overview/01-erd.md)를 같은 커밋에서 갱신 + 팀 채널 공지** 필요.
  - B안: 컬럼 없이 프론트에서 이메일→파일명 매핑 하드코딩. 빠르고 되돌리기 쉽지만 계정이 늘 때마다 코드를 고쳐야 한다.
- 어느 쪽이든 사진 없는 계정은 지금의 이니셜 아바타로 폴백한다.

- 지시서 없는 항목은 오너가 직접 쪼개 진행한다 (지시서 작성 여부는 오너 판단 — [04-team.md](../00_overview/04-team.md)).
- **React 이식 시에도 05-design §0-5 조각 루프의 정신을 유지한다**: 화면 하나 = PR 하나, 목업에 없는 요소·토큰에 없는 값이 필요하면 멈추고 팀장에게.

## 6. 리스크

- **목업→React 이식에서 룩이 미묘하게 틀어지는 것.** 완료 기준을 "나란히 놓고 구분 안 됨"으로 고정하고, PR마다 스크린샷 비교를 붙인다.
- **칸반 낙관적 업데이트가 마지막 주에 몰림.** M4를 W3 후반에 시작하도록 M3에서 상세 패널까지 끝내둔다.
- 색 리터럴 정리(팀장) 전에 공통 CSS 파일을 만들면 두 번 일한다 — **정리 머지 후에 토큰 파일화한다.**

## 7. 면접 스토리

- 정적 목업 8장을 컴포넌트로 이식한 전략 — 공통 조각을 어떻게 추출했고 토큰이 왜 전부 CSS 변수인가
