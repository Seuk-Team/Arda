# 발표 뼈대 · 핵심 소주제

> 작성: 2026-08-31 · [발표-뼈대 지시서](02_tasks/발표-뼈대.md) 이행 + 핵심 소주제 5개 정리
> 원칙: **완료한 것은 과거형 + 근거 링크, 계획은 "계획"으로 명시한다.** 발표·이력서에서 시제가 뒤집히면 안 된다.

## 핵심 소주제 5개

발표와 각자 면접 스토리의 공통 뼈대. 상태 표시 — ✅ 구현 완료 · 🔨 구현 중 · 📋 계획(미착수).

### 1. 채용 프로세스 통합 관리 파이프라인 ✅

"합불 등 핵심 결정은 항상 사람이 한다"([ADR-0003](03_decision/0003-ai-추천만.md))는 원칙 위에서, 공고 등록 → 접수 → 단계별 심사 → 결과 통보까지를 하나의 시스템으로 통합했다. 지원자 관리의 중심 뷰는 칸반 보드(#140, 목록과 토글)로, 카드를 드래그해 단계를 옮기면 이력이 자동 기록되고 안내 메일이 큐 기반 비동기(SQS+재시도, G2·G3)로 발송된다. JWT 3역할(관리자·채용담당자·면접관) 접근 제어(A1~A3)와 더미 10만 건 기준 검색 튜닝(111ms → 7.8ms, [perf-search.md](perf-search.md))을 포함한다.

### 2. 보안 강화 로컬 AI 에이전트 📋 (v2 검토 — 미확정)

이력서·면접 기록 등 지원자 개인정보가 외부 API로 나가지 않도록, sLLM·STT를 온프레미스로 구동하는 구성. **현재 확정 스택은 Claude API다**([ADR-0011](03_decision/0011-에이전트-모델-비용.md)) — 이 소주제는 그것을 뒤집는 게 아니라, 민감 작업은 로컬·일반 작업은 API로 나누는 **하이브리드 후속 트랙 제안**이다. 품질·비용 트레이드오프는 기능별 실측으로 검증한다. 1차 완성(09/30) 범위 밖. 발표에서는 "향후 계획"으로만 말한다.

### 3. 지원자가 24시간 접근하는 면접 일정 자동화 🔨 ([ADR-0016](03_decision/0016-면접-일정-자동화.md), 08/31 착수)

면접관 가용 시간에서 후보 슬롯을 만들어 지원자에게 제안하고, 지원자가 공개 링크(로그인 없음, B6 토큰 패턴)로 24시간 언제든 접속해 슬롯을 선택하면 즉시 확정·통보된다. 통보는 기존 SES·SQS 비동기 메일 파이프라인 재사용 — 수 회의 메일 왕복을 링크 1회로 줄인다. 챗봇 질의응답은 이 범위에서 분리(에이전트 RAG 트랙에서 별도 판단).

### 4. LLM 도구 호출 에이전트 + AI 원가 관측 ✅ / STT 면접 분석 📋

"김도현 찾아줘 → 면접 안내 이메일 만들어줘" 같은 자연어로 검색·조회·단계 변경·메일 초안을 수행하는 도구 호출 에이전트를 구현했다(#83). 실행성 작업은 `pending_action` 초안까지만 만들고 사람의 확인(`/agent/confirm`)을 거친다. 채팅·요약·STT 전 기능에 토큰·비용 로깅을 통일해 **E2E 4단계 실측 $0.045**의 원가 관측 체계를 갖췄다([ADR-0011](03_decision/0011-에이전트-모델-비용.md) 실측 표). — 여기까지 완료.
STT→RAG→sLLM 면접 분석 파이프라인(면접 전사 → 이력서·직무 요건·평가 기록에서 근거 검색 → 근거 인용 요약)은 **계획**이다. 근거 문서 없이 모델이 단독 판단하지 않는 구조가 설계 원칙.

### 5. 웹/모바일 멀티 클라이언트 · 운영 체계 ✅

React(Vite·TS) 웹과 Flutter 앱이 같은 FastAPI를 쓰는 계약 중심 설계 — API/ERD 문서를 코드와 같은 리듬으로 갱신해 5인 병렬 개발의 정합성을 유지했다. Docker·AWS(EC2·S3·SES·SQS)·Vercel 실배포(08/27, [07-deploy](00_overview/07-deploy.md)), GitHub Actions CI/CD는 W3. 도메인 오너제([ADR-0007](03_decision/0007-도메인-오너제-전환.md)), ADR 16건, 파일 소유 기반 무충돌 협업 — 산출물만이 아니라 협업 체계도 설계 대상이었다.

## 시연 시나리오 (4분)

1. 공개 지원 폼(`/apply/:token`)에서 지원 제출 → 이력서 업로드(presigned 직행)
2. 담당자 화면: 접수 확인 → AI 요약 표시 → 칸반 드래그로 `screening` 이동 → 안내 메일 수신 화면
3. 일정 자동화: 제안 생성 → 지원자 공개 페이지에서 슬롯 선택 → 확정 메일 (🔨 구현 완료 시)
4. 에이전트: ⌘K 콘솔 "○○○ 서류 통과로 옮겨줘" → 확인 카드 → 실행
5. 모바일 앱에서 같은 지원자 단계 변경 → 웹 칸반에 반영 (같은 API 증명)
6. 검색: 10만 건에서 즉답 — 성능 수치 슬라이드로 연결

**사고 대비**: 각 단계 성공 화면을 사전 녹화한 영상 1개 + 스크린샷 세트를 준비하고, 실패 시 해당 구간만 영상으로 대체한다.
