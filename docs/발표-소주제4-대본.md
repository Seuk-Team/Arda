## 무엇을 말할까 — 고른 이야기

**"측정해보니 내 가정이 틀렸다"** 를 중심에 놓는다.

기능 자랑("도구 12개를 붙였습니다")은 3초짜리고 다음 질문이 안 나온다. 반면 **믿었던 것이 실측에서 깨진 이야기**는 준비된 답변처럼 들리지 않고, 면접관이 파고들 자리를 만든다. ADR-0004 가 같은 판단을 이미 적어 뒀다 — *"Whisper 붙였다"는 3초짜리지만 "음성 인식 오류가 도구 호출로 전파되는 걸 어떻게 막았나"는 10분 설명 가능.*

## 대본 (1.2분)

> **① 구조 한 줄** (15초)
>
> "자연어 한 문장이 검색 → 조회 → 단계 변경 → 메일 초안으로 분해됩니다. 도구는 12개인데, **읽기 7개는 바로 실행하고 쓰기 5개는 실행하지 않습니다.** 초안까지만 만들고 멈춥니다."
>
> **② 왜 쓰기만 멈추나** (20초)
>
> "되돌릴 수 있느냐로 갈랐습니다. 검색은 틀려도 다시 하면 되지만 **메일은 나가면 끝입니다.** 그래서 실행 루프에서 쓰기 도구 이름을 만나면 실행하지 않고 `pending_action` 으로 되돌립니다. 화면이 확인 카드를 띄우고, 사람이 누르면 그때 별도 엔드포인트가 실행합니다. **모델이 확인을 건너뛸 방법이 없습니다** — 프롬프트로 부탁한 게 아니라 코드가 막습니다."
>
> **③ 원가 관측** (20초)
>
> "채팅·요약·STT 전 기능에 토큰과 비용을 같은 형식으로 남깁니다. E2E 4단계 실측이 **$0.045**입니다. 캐시 적중도 따로 셉니다 — `cache_read_tokens` 가 계속 0이면 캐시가 안 걸린 겁니다."
>
> **④ 여기서 틀렸던 것** (25초) ← **핵심**
>
> "요약이 너무 길어서 두 겹으로 줄였습니다. 프롬프트로 한 번, **JSON 스키마 상한으로 한 번.** 스키마로 막으면 확실하다고 봤습니다.
>
> 어제 배포하고 23건을 다시 생성해서 재봤더니 — **절반만 듣습니다.** 개수 제한은 100% 지켜지는데 **글자수 제한은 188개 항목 중 43개가 초과했습니다.** 최대 74자, 상한은 40자였고요.
>
> 즉 도구 호출 스키마에서 **배열 개수는 강제되고 문자열 길이는 권고에 그칩니다.** 재보지 않았으면 '스키마로 규격을 강제했다'고 발표했을 겁니다."
>
> **⑤ 다음 단계** (10초)
>
> "STT 면접 분석은 계획입니다. 면접 전사에서 근거를 찾아 인용하는 구조인데, **근거 문서 없이 모델이 단독 판단하지 않는다**는 게 설계 원칙입니다."

## 예상 질문과 답

**Q. 확인 단계를 왜 프롬프트가 아니라 코드로 막았나**
프롬프트는 지키면 좋은 것이고 코드는 지킬 수밖에 없는 것이다. 모델이 바뀌거나 로컬 sLLM 으로 갈아끼워도 이 경계는 그대로 선다. 실제로 백엔드 어댑터(`AGENT_CHAT_BACKEND`)로 모델을 바꿀 수 있게 만들어 뒀는데, 그래서 더더욱 경계가 모델 밖에 있어야 했다.

**Q. 그럼 확인을 다 거치면 느리지 않나**
지금은 쓰기 5개가 전부 확인을 거친다. **되돌릴 수 있는 쓰기(면접관 배정·슬롯 제안)는 즉시 실행하고 사후 취소를 주는 쪽이 맞다**고 보고 있고, 되돌릴 수 없는 것(메일 발송·단계 확정)만 확인을 남기는 안을 검토 중이다. 아직 안 했다.

**Q. 스키마 길이 제한이 안 걸리면 어떻게 할 건가**
저장 전에 자르거나 화면에서 줄이는 두 가지뿐이다. 다만 **자르면 문장이 깨지므로** 프롬프트를 더 조이는 쪽을 먼저 본다. 지금 분량(중앙값 252자)은 화면에서 문제가 없어서 급하지 않다.

**Q. $0.045 는 무엇을 4단계로 잰 건가**
검색 → 조회 → 상태 변경(거부되는 경우) → 이메일 초안이다. 조회가 가장 비싼데 도구를 두 번 부르고 이전 대화가 입력에 누적되기 때문이다.

**Q. 요약이 실패하면 어떻게 되나**
`insufficient` 로 저장되고 화면에 "제출물이 부족하다"고 뜬다. 운영에서 실제로 2건 있는데 **프로필이 빈 테스트 행이라 모델 판단이 맞다.** 다만 이게 잘못 뜨면 거짓 진술이 남으므로, 잘려서 JSON 이 깨진 것을 `insufficient` 로 저장하던 버그를 09/01 에 고쳤다(`96204f9`).

## 하지 말 것

- **"AI 가 뽑아줍니다"로 들리게 말하지 않는다.** [ADR-0003](03_decision/0003-ai-추천만.md) 이 차별점이다
- **"RAG 했습니다"라고 말하지 않는다.** 출하된 것은 **서류 시맨틱 검색**이고 면접 전사 RAG 는 계획이다. 같은 단어가 둘을 가리켜 청중이 계획 쪽으로 알아듣는다([rag-범위-정리](rag-범위-정리.md) §3)
- **낡은 $0.045 를 현재형으로 말하지 않는다.** 재측정 전이면 "08/28 기준"을 붙인다
