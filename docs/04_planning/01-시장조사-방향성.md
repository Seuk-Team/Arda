# 01. ATS 시장 조사와 Arda 방향성

> 작성 2026-08-27 · 초안(미커밋) — 팀 확인 후 반영
> 목적: "인사팀이 왜 이걸 사는가"에 답하지 못하면 포트폴리오 발표도 못 판다. 시장 조사로 그 답을 만들고, 기능 우선순위와 발표 스토리를 재정렬한다.

---

## 1. 한 줄 결론

**ATS는 지원자 DB가 아니라 채용담당자의 시간을 사는 제품이다.** Arda의 정체성은 이렇게 정리한다:

> **"반복 업무는 에이전트가 대신하고, 판단의 근거는 사람에게 보여주는 ATS."**
> — 비싼 것(기록·정리·취합·발송)을 자동화하고, 위험한 것(합불 판단)은 사람에게 남긴다.

---

## 2. 인사팀이 ATS를 사는 이유 (검증된 pain)

| # | Pain | 근거 · 수치 |
|---|---|---|
| 1 | **엑셀+메일함+채용플랫폼 3중 관리 붕괴** | 지원자 증가·담당자 2인 이상·개인정보 규정이 겹치는 순간 엑셀이 무너진다 (나인하이어·zuzu 분석) |
| 2 | **행정 업무가 시간을 잡아먹음** | 코디네이터 업무의 **46%가 일정 조율 등 행정**. 면접 1건 수동 조율 평균 **243분**. 이력서 1장 30~90초, 지원자 1명 연락 5~15분 |
| 3 | **협업 불가** | "누가 언제 어느 단계로 옮겼나", "면접관 3명 평가가 어디 있나"가 엑셀엔 없다 → Arda의 단계 이력(D5)·평가(E)가 정확히 이 문제 |
| 4 | **응답 지연 = 후보 이탈 = 회사 평판** | 단계 변경 자동 메일(G1)이 해법 |
| 5 | **컴플라이언스** | 채용절차법·개인정보보호법상 서류 보관·파기 의무 — 엑셀로 관리 불가 |

**pain이 실재한다는 가장 강한 증거**: 정부가 중소기업 ATS 도입에 **연간 이용료 80%(최대 40만원)를 지원**하는 사업을 운영 중(그리팅이 공급기업). 국가가 돈을 대는 문제라는 뜻 — 발표 오프닝에 인용할 것.

---

## 3. 시장 지형

### 3-1. 제품별 포지션

공통 골격은 하나다: **공고 → 지원 수집 → 파이프라인(칸반) → 평가 → 커뮤니케이션 → 오퍼 → 분석**. 제품별로 힘주는 곳이 다르다.

| 제품 | 포지션 | 핵심 셀링 포인트 |
|---|---|---|
| Greenhouse (해외 1위) | 엔터프라이즈 | **구조화 채용** — 직무별 면접 키트·스코어카드로 면접관 편차 축소 |
| Lever | 미드마켓 | ATS+CRM — 탈락자·과거 지원자 인재풀 재발굴(nurture) |
| Ashby (신흥) | 데이터 중심 팀 | 올인원(ATS+CRM+일정+분석). "면접 일정 40% 단축"을 수치로 판다 |
| 그리팅 (국내 1위, 6,000+사) | 국내 전 규모 | 채용 홈페이지 빌더 + 통합 관리 + 협업 평가 + 일정 조율 + 인재풀(TRM) |
| 나인하이어 (국내) | 자동화 특화 | **트리거→액션 자동화** (단계 진입/점수 충족/과제 제출 → 메일·단계 이동·합불·평가 요청·팀챗 알림) |

### 3-2. 인접 시장 — 면접 인텔리전스 (Metaview · BrightHire)

면접을 **녹음 → 전사 → AI 노트 → ATS 동기화**. 면접관이 타이핑 대신 대화에 집중하게 한다. BrightHire는 여기에 **면접관 분석**(말하기/듣기 비율, 면접관 스킬 갭, 프로세스 병목)을 얹어 판다. **Arda가 이미 보유한 STT+엔티티 해석 자산이 이 시장으로 직행한다** — §5 참고.

### 3-3. 2026 트렌드 — 에이전틱 AI

단순 트리거-액션 자동화에서 **목표 지향 에이전트**(한 문장 → 검색·선별·연락·일정·ATS 갱신을 다단계 수행)로 이동 중. 채용담당자 71%가 ATS 사용, 79%가 채용 일부 자동화. Arda의 도구 호출 에이전트는 이 트렌드의 정중앙에 있다.

## 4. Arda의 강점 분석 (팔리는 이유)

기능 개수로 정면승부하지 않는다. 3층으로 정리한다: **포지셔닝(어디에 설 것인가) → 자산(무엇을 이미 가졌는가) → 우산 명제(한 문장으로 무엇을 파는가)**.

### 4-1. 포지셔닝 각도 4개

1. **에이전트 네이티브** — 기존 제품은 버튼 UI에 AI를 덧붙이는 중. Arda는 *"Python 2년 이상 AWS 경험자 추려서 서류합격 처리하고 면접 안내 메일 초안"* 한 문장이 코어 UX. 나인하이어식 트리거-액션보다 한 세대 앞선 개념.
2. **사람이 확정한다 = 신뢰를 판다** — EU AI Act는 채용을 고위험으로 분류, 국내 채용절차법 존재. "AI는 제안(앰버 점선), 사람이 확정(청록 실선)"([ADR-0003](../03_decision/0003-ai-추천만.md))은 기술 제약이 아니라 **구매자가 법무팀을 설득할 근거**다.
3. **데이터 주권** — 그리팅·나인하이어는 SaaS라 지원자 개인정보가 벤더 서버에 있다. Arda의 "로컬 우선 + AWS 이중 배포"([07-deploy.md](../00_overview/07-deploy.md))를 **셀프호스팅 옵션**으로 승격하면 국내 ATS가 비워둔 포지션이 된다 (공공·규제 산업이 SaaS ATS를 못 쓰는 이유).
4. **저가 구간의 빈틈** — 그리팅 베이직 플랜은 이메일·문자 커뮤니케이션이 잠겨 있다. "자동 메일까지 기본 포함된 가벼운 ATS"는 초소형 기업 시장의 실제 갭.

### 4-2. 이미 가진 자산에서 나오는 강점 (경쟁자가 따라오기 어려운 것)

| 자산 (구현 상태) | 왜 강점인가 |
|---|---|
| **한국어 엔티티 해석 레이어** — 한글 수사→숫자, 기술 용어 음차 정규화(`패스트에이피아이`→`FastAPI`), 이름 유사도 매칭 (`entity_resolver.py`, 테스트 18개) | Greenhouse·Ashby는 한국어 음성·구어 명령을 처리하지 못한다. **"한국어 채용 도메인 특화 에이전트"는 해외 제품이 구조적으로 비워둔 자리**이고, 국내 제품은 아직 에이전트 자체가 없다 |
| **LLM 비용 로깅** — 호출별 cost_usd 기록, 더미 10만 건 비용 가드 (`runtime.py`, 테스트 13개) | "AI 기능 켜면 비용이 얼마 나오나"는 실제 구매 차단 질문. 원가가 보이는 AI 기능은 어떤 ATS도 안 보여준다 → §6 아이디어 2로 제품화 |
| **중앙화된 도구 실행 루프** — 에이전트의 모든 행동이 한 지점을 통과 | 감사 로그·미리보기·실행취소를 얹을 지점이 하나뿐이라 싸게 붙는다 → §6 아이디어 1 |
| **STT + 요약 파이프라인** (Whisper 스모크 테스트 완료, summarizer 가동) | 면접 인텔리전스(§5-2)로 직행하는 기반. 명령 입력용으로 만든 것이 면접 데이터 파이프라인의 시작이 된다 |
| **웹+앱+에이전트가 같은 API의 3클라이언트** | 대기업 ATS도 모바일이 부실하다. 5인 팀이라 가능한 수직 통합 — 칸반에서 한 일이 즉시 앱·에이전트에서 일관되게 보인다 |
| **결정 기록 문화 (ADR 15건)** | 제품 강점이자 발표 강점. "왜 안 만들었나"에 문서로 답하는 팀은 드물다 |

### 4-3. 우산 명제 — "AI 거버넌스를 파는 ATS"

경쟁사는 **AI 기능**을 판다. Arda는 **AI를 안심하고 켜게 하는 장치**를 판다.

> 고객은 "AI를 쓰고 싶지만 무서운 회사"다. 법무 리스크(EU AI Act·채용절차법), 비용 불확실성, 오작동 공포 — 이 셋이 구매를 막는다. Arda는 이 셋을 각각 시스템으로 제거한다:
> **① 사람 확정** (ADR-0003) · **② 감사 로그 + 실행 미리보기** (AI가 한 일을 추적·회수 가능) · **③ 비용 상한 + 원가 대시보드** (지출이 보이고 통제됨) · 여기에 **④ 근거 표시** (AI 판단마다 출처 하이라이트)까지.
>
> 이 넷은 따로 놀지 않고 하나의 명제가 된다: **"Arda에서 AI는 언제나 — 이유를 보여주고, 기록을 남기고, 비용이 보이고, 사람이 확정한다."**

이 명제가 강한 이유: 2026년 구매 담당자의 진짜 질문은 "AI 되나요?"가 아니라 **"AI 켜도 사고 안 나나요?"**이기 때문이다. 기능 데모는 모두가 하지만, 거버넌스를 시스템으로 보여주는 팀은 없다.

## 5. 면접 분석 기능 — 제안 검토와 방향 확정

### 5-1. 원안: "면접관 성향 학습 모델"

> 면접 내용을 분석해 면접관별 성향·합격 조건·합격 이유를 모델이 학습하고, 여러 번 학습하면 다른 사람이 면접을 보더라도 그 면접관 기준으로 합격 여부가 추려지게 한다.

**문제의식은 정확하다** — 면접관마다 기준이 달라 채용이 복불복이 되는 것(면접관 편차)은 실재하는 pain이고, Greenhouse가 "구조화 채용"으로 파는 바로 그 문제다. 그러나 **"모방 모델" 형태 그대로는 채택 불가**:

| # | 리스크 | 내용 |
|---|---|---|
| 1 | **편향 증폭** | 면접관 성향을 학습한다 = 그 사람의 편향(학벌·성별·말투 선호)까지 복제한다. Amazon이 2018년 과거 채용 데이터로 학습시킨 채용 AI가 여성 지원자를 감점해 폐기한 사례가 정확히 이 구조. 심사에서 이 질문이 반드시 나온다 |
| 2 | **법·규제 정면 충돌** | 사람 검토 없는 자동 합불은 EU AI Act 고위험 + 미국 EEOC 경고 + [ADR-0003](../03_decision/0003-ai-추천만.md) 위반. 표정분석을 뺀 것과 같은 이유([ADR-0002](../03_decision/0002-표정분석-제외.md))로 방어 불가 |
| 3 | **데이터가 없다** | 면접관 1명의 연간 면접은 수십 건. 개인별 파인튜닝에 필요한 표본이 안 나오고, 우리 더미 10만 건에는 면접 녹취 자체가 없다 |
| 4 | **정답 라벨이 없다** | "합격 이유"는 기록되지 않고, 합격자가 실제로 일을 잘했는지(성과)와도 연결 안 된다. 모델은 "채용 품질"이 아니라 "그 면접관 흉내"에 최적화된다 |
| 5 | **비용-효익 역전** | 면접(비싼 활동)은 그대로 하면서 판단(사람이 해야 하는 유일한 부분)만 자동화한다. 줄어드는 업무는 없는데 리스크만 최대 |

### 5-2. 뒤집기: 성향을 "복제"하지 말고 "드러내라" — 면접 캘리브레이션

같은 문제의식을 시장이 검증한 형태로 뒤집으면 BrightHire가 실제로 돈 받고 파는 기능이 된다:

> **면접관 성향을 학습해 판단을 대신한다 (✗) → 면접관 성향을 드러내 편차를 보정하고, 판단은 구조화된 기준으로 수렴시킨다 (○)**

구체 기능 (기존 자산·기능 목록과의 연결):

| 기능 | 내용 | 연결 |
|---|---|---|
| **면접 전사·요약** | 면접 녹음 → STT → 구조화 요약 → 평가 초안 (확정은 면접관) | 기존 STT+엔티티 해석 재활용, Metaview 검증 시장 |
| **면접관 캘리브레이션 리포트** | 면접관별 점수 분포 — "A는 평균 2.1점(엄격), B는 4.2점(후함)" → 보정 계수 제시 | 기능 목록 **I5** 승격 |
| **질문 커버리지 분석** | "이 면접관은 기술만 묻고 컬처핏 질문이 0건" — 전사에서 질문 유형 분류 | 전사 데이터 2차 활용 |
| **면접관 간 불일치 감지** | 같은 지원자에 평가가 크게 갈리면 알림 → 논의 유도 | E2 평균 계산 확장 |
| **합격 패턴 리포트** | "최근 합격자들의 공통 요소" — 조직 단위·서술적 리포트, 개인 모방 아님. 해석과 결정은 사람 | 대시보드(I) 확장 |
| 편향 방지 장치 | 타 면접관 평가 숨김(제출 후 공개) | 기능 목록 **E6** |

이 형태가 우월한 이유:

1. **원안이 노린 가치를 그대로 담는다** — "면접관이 달라도 기준이 일정해진다"를, 모방이 아니라 **보정과 구조화**로 달성한다.
2. **ADR-0003을 위반하는 게 아니라 강화한다** — "사람이 확정"에 "더 나은 근거를 들고 확정"이 얹힌다.
3. **더미 데이터로 데모 가능** — 점수 분포·불일치는 평가 시드 데이터로 시연 가능. 녹취가 없어도 캘리브레이션 리포트는 돌아간다.
4. **발표 자산이 하나 더 생긴다** — "면접관 모방 모델을 검토했고, Amazon 사례와 EU AI Act 때문에 캘리브레이션으로 설계를 뒤집었다"는 표정분석 제외와 같은 급의 스토리다. "못 만들어서 안 한 것"과 "안 만드는 게 맞다고 판단한 것"의 차이.

→ 확정 시 **ADR-0016 (면접관 모방 모델 제외, 캘리브레이션 채택)** 으로 기록 권장.

## 6. 추가 차별화 아이디어 후보 (우선순위 순)

§4-3 우산 명제("이유를 보여주고, 기록을 남기고, 비용이 보이고, 사람이 확정한다")를 기능으로 구체화한 후보들. **모두 기존 자산에 얹는 것이지 새 판을 벌이는 게 아니다.**

### Tier 1 — 코어에 싸게 얹힘 (지금 일정 안에서 소형 작업)

| # | 아이디어 | 해결하는 pain | 왜 Arda가 잘하나 |
|---|---|---|---|
| 1 | **에이전트 감사 로그 + 실행 미리보기** — "23명 서류합격 처리" 전에 대상 목록을 보여주고 확인받고, 실행 후엔 누가·언제·무엇을 했는지 기록, 단계 변경은 되돌리기 가능 | AI 오작동 공포 (구매 차단 1순위) | 도구 실행 루프가 중앙화돼 있어 로그·확인 지점이 한 곳. 기능 목록 J10(감사 로그)의 에이전트판 |
| 2 | **AI 원가 대시보드** — 관리자 화면에 "이번 달 AI 비용 ₩X, 기능별(추출/요약/에이전트) 원가, 호출당 평균" | "AI 켜면 얼마 나와요?" (구매 차단 2순위) | cost_usd 로깅이 **이미 구현돼 있다**. 화면만 붙이면 됨. 이걸 보여주는 ATS는 시장에 없음 |
| 3 | **추출 근거 하이라이트** — AI가 "경력 3년·FastAPI"라고 추출하면 이력서 원문의 근거 문장을 하이라이트로 연결 | AI 불신 ("어디서 나온 숫자냐") | 구조화 추출 파이프라인에 근거 스팬 필드 추가. 설명가능성을 UX로 만든 사례 — 면접 얘깃거리 상급 |

### Tier 2 — 여유 시 (중형, 차별화 효과 큼)

| # | 아이디어 | 해결하는 pain | 왜 Arda가 잘하나 |
|---|---|---|---|
| 4 | **파이프라인 병목·SLA 알림** — "서류 검토 단계에 7일 이상 체류 중인 지원자 12명" 대시보드 경고 | 지원자 방치 → 이탈·평판 하락 | 단계 이력(D5)에 데이터가 이미 쌓임. I2(체류일)의 실전판. Ashby가 이런 ops 지표로 크는 중 |
| 5 | **면접관 캘리브레이션 리포트** (§5-2) | 면접관 편차 = 채용 복불복 | 평가 데이터(E) + 더미 시드로 데모 가능. BrightHire 검증 시장 |
| 6 | **앱 "면접관 모드"** — 면접 30분 전 푸시: 지원자 요약 브리핑 + 이전 단계 평가 + 추천 질문 카드 | 면접관이 준비 없이 들어감 | 요약 파이프라인 재활용. 앱 트랙의 존재 이유가 "두 번째 클라이언트"에서 "면접관의 주머니 속 브리핑"으로 격상 |
| 7 | **시맨틱 스킬 검색** — "React 잘하는 사람" 검색 시 Vue·프론트 경력자도 의미 기반으로 후보에 (pgvector) | 키워드 검색의 미스매치 | 검색 도메인(10만 건 튜닝)과 시너지. 임베딩은 1회 배치 + 비용 가드 전제 |

### Tier 3 — 로드맵 (발표용 비전, 구현은 다음 단계)

| # | 아이디어 | 해결하는 pain | 근거 |
|---|---|---|---|
| 8 | **지원자 Q&A 봇 + 상태 조회** — 공고 기반 RAG로 지원자 질문(절차·근무지·스택) 응대 | 무응답 = 회사 평판 (잡플래닛 시대) | RAG(보조 트랙)의 재배치. C5 연결. 판단 없음 = 규제 안전 |
| 9 | **미니 면접 일정 조율** — 가능 시간 3개 제안 → 지원자가 링크로 확정 | 면접 1건 조율 243분 — 최대 시간 낭비 직격 | G6 연결. Ashby "일정 40% 단축"에 대응하는 우리 답 |
| 10 | **JD 편향 문구 검사** — 공고 저장 시 차별 소지 표현(연령·성별) 감지·대안 제안 | 채용절차법 리스크 | 공고(B)에 검사 훅 하나. 사회적 신뢰 스토리 보강 |

**선정 원칙**: ① 판단을 대신하는 기능은 없다(전부 보조·기록·표시) ② 더미 데이터로 데모 가능 ③ 기존 담당 도메인에 자연스럽게 귀속(감사 로그→에이전트, 병목 알림→검색·데이터, 면접관 모드→앱).

## 7. 포트폴리오 전략

### 7-1. 지금 로드맵(~09/30)은 그대로

조사 결과 필수 27기능이 시장 ATS 표준 골격과 일치한다 — 공고(B)·지원폼(C)·칸반(D)·평가(E)·자동 메일(G)·검색(H). **바꿀 것은 기능이 아니라 파는 방법.**

### 7-2. 데모는 "채용담당자의 하루"로 판다

기능 나열이 아니라 시나리오:

> "지원자 120명. 엑셀이면 이력서 훑기만 1시간, 안내 메일은 한 통씩 수동. 업무의 46%가 이런 행정이다. → Arda에서는 지원과 동시에 구조화 추출·자동 메일, 그리고 한 문장으로 검색부터 메일 초안까지."

### 7-3. 여유 시 추가 우선순위

§6 아이디어 표 기준으로: **Tier 1(감사 로그·원가 대시보드·근거 하이라이트)을 먼저** — 작고, 우산 명제를 데모에서 증명한다. 그다음 여력에 따라:

1. **퍼널 전환율·단계 체류일 대시보드** (I1·I2) + 병목 알림(§6-4) — 구매 결정자가 보는 화면
2. **면접관 캘리브레이션 리포트** (I5 승격, §5-2) — 차별화 기능이자 발표 스토리
3. **트리거-액션 자동화 최소 1개** — "서류합격 진입 시 면접 안내 메일 자동 발송" (나인하이어 콘셉트 최소 구현)
4. 메일 템플릿 편집 (G4)

### 7-4. 발표용 확장 로드맵 ("완성 못 해도 방향을 보여준다")

| 방향 | 내용 | 기반 자산 |
|---|---|---|
| 면접 인텔리전스 | 녹취→전사→요약→평가 초안. STT의 존재 이유가 "명령 입력"에서 "면접 데이터 파이프라인의 시작"으로 격상 | STT·엔티티 해석·요약 파이프라인 |
| 인재풀(TRM) | 탈락자 다음 공고 재발굴 (D11) — Lever·그리팅 검증 | 기존 스키마 자연 확장 |
| 채용 사이트 연동·멀티테넌시 | 사람인/원티드 공고 배포, 조직 분리(A8) → SaaS화 | API 구조 |
| 셀프호스팅 배포판 | 데이터 주권 포지션의 제품화 | Docker·이중 배포 전략 |
