## 오너가 하는 일

- **자기 큐를 위에서부터 소화한다.** 선행이 안 풀렸으면 건너뛰고 다음 것. 큐가 비면 오너가 로드맵을 갱신해 채운다(마일스톤 범위 안에서 — 범위 자체를 바꾸는 건 팀장 합의).
- **자기 도메인 지시서는 자기가 쓴다.** 쓸지 말지도 오너 판단 — Claude에게 시킬 작업은 지시서([tasks/_template.md](../02_tasks/_template.md))로 만들어두는 편이 결과가 안정적이다.
- **자기 도메인 PR은 자기 책임으로 머지한다.** 조건은 [03-conventions.md](03-conventions.md) 리뷰 절 — 요약: 남의 폴더·공용 파일이 안 섞였고, PR 본문에 검증 결과가 있고, CI(생긴 뒤)가 초록이면 스스로 머지.
- 다른 도메인에 문제를 발견하면 고치지 말고 이슈로 남긴다 ([CLAUDE.md](../../CLAUDE.md) 범위 규칙).

## 팀장 전담 (축소됨)

- 스키마([01-erd.md](01-erd.md)) · 아키텍처 결정
- **인터페이스 리뷰** — 스키마·[02-api.md](02-api.md)·공용 문서·도메인 경계를 넘는 PR
- 파트 간 통합 · 주간 계획 · 발표 총괄

## 운영 리듬

- **1차 완성 기한: 09/30(수).** 각 도메인은 자기 로드맵의 주간 계획(W1~W5 + 09/28~30 버퍼)대로 스스로 진행한다.
- **팀장 머지·검수·뒷처리는 매주 금요일 최소 1회** (필요시 주 2~3회 수시). 팀장 승인이 필요한 PR은 **목요일까지** 올린다. 다른 도메인이 대기 중인 급한 PR은 팀 채널로 수시 검수를 요청한다.
- 도메인 내부 PR의 셀프 머지는 이 사이클과 무관하게 수시.

*이관된 것: 프론트 뼈대·칸반 → cloverky, 인증(A1~A3)·단계 전환 로직(D3) → woojeongalex.*
