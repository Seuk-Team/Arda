# 03. 협업 규칙 (커밋 · push · 사후 공지)

> **2026-08-28 개정**: 사람 리뷰·승인 게이트 전면 폐지 — 전원 main 직접 push. 배경: 전원이 Claude로 작업해 사람 검수가 형식화됨. 이전 규칙(이슈→브랜치→PR→리뷰)은 git 이력 참조.
> **2026-09-04 개정**: main 직접 push 금지 — **브랜치→PR→자체 머지**(CI 초록 필수, 승인 불요). GitHub 브랜치 보호가 실제로 막는다. 승인 게이트는 여전히 없다 — 바뀐 것은 "main 에 닿는 경로가 PR 하나"라는 점뿐이다. 저장소는 `Seuk-Team/Arda` 로 이관 완료. 팀장 suvisdev(인프라·총괄)는 게이트가 아니다. 셋업은 [10-team-setup.md](10-team-setup.md).

## 원칙

- **브랜치에서 작업하고 PR 로 main 에 넣는다. 사람 승인 게이트는 없다 — 자기 PR 은 CI 초록이면 자기가 머지한다.** 각자 Claude가 검증(실행·테스트)까지 마친 상태로 올리는 것을 전제로 한다.
- **main은 항상 동작하는 상태** — 이 책임이 리뷰어에서 머지하는 사람에게 넘어왔다. **main 머지 = 2분 후 프로덕션 배포**다([07-deploy.md](07-deploy.md)). 깨진 main을 발견한 사람은 묻지 않고 고치거나(fix-forward) revert한다.
- CI 빨간불인 PR 은 머지하지 않는다. **main 이 빨간불이면 다른 작업보다 우선 수정.**
- 이의는 사후에: 변경이 마음에 안 들면 팀 채널에서 얘기하고, 합의가 안 되면 revert가 기본값.

## 반영 절차 (브랜치→PR→자체 머지)

1. main 을 최신으로 받고 브랜치를 판다 — `git switch -c <type>/<주제>`
2. 자기 파트 실행/테스트 — 결과는 커밋 메시지에 한 줄
3. push 후 PR 오픈. **CI 초록 확인 → 자기가 머지.** 리뷰가 필요하면 담당 도메인 오너에게 요청(선택) — 팀장 게이트 없음
4. main 직접 push·force push 는 GitHub 이 차단한다. 충돌하면 브랜치에서 main 을 받아 풀고 다시 push

## 커밋 — 리뷰가 없으므로 이력이 곧 기록이다

- 형식: `<type>(<기능번호|도메인>): <요약>` — 예: `feat(J7): 더미 지원서 10만 건 생성기`, `feat(front): React 라우팅 뼈대`
- type: `feat` `fix` `docs` `test` `chore` `refactor`. 요약은 한국어로, 무엇이 왜 바뀌었는지.

## PR · 이슈

- PR 은 main 에 닿는 유일한 경로다(2026-09-04). 승인 없이 셀프 머지 — 피드백을 받고 싶으면 본문에 적거나 리뷰어를 지정한다. **PR 이 곧 기록**이라 본문에 무엇을 왜 바꿨는지 남긴다.
- 이슈는 버그·요청·타 도메인 개선 제안 기록용으로 유지. 제목에 기능 번호.

## 진행 상태 — 팀 칸반 (2026-08-28 도입)

- 각자의 **진행 상태(todo/doing/done)와 받은 피드백**은 팀 칸반 사이트에 기록한다. 갱신은 Claude에게 "지킬 업데이트 해줘" 한 마디 — 절차는 지킬 담당(suvisdev)이 배포한 `Arda-칸반-클로드-지시서.md`.
  - 칸반 <https://ats.suvisdev.cloud/kanban/> · 피드백 <https://ats.suvisdev.cloud/feedback/>
  - 사람마다 자기 `_data/kanban/<아이디>.yml`·`_data/feedback/<아이디>.yml`만 수정한다.
- **역할 분담**: 칸반 = 지금 무엇을 하고 있나(진행 상태). 로드맵(`docs/01_role/<도메인>.md`) = 범위·마일스톤·큐 순서. 진행 표시는 칸반으로 일원화하고, 로드맵 큐에 진행률을 중복 관리하지 않는다.
- **저장소는 현재 개인 소유**(`suvisdev/ats.suvisdev.cloud`)라 협업자 초대 수락이 필요하다. **이관한다면 `Seuk-Team` 조직으로** (구 `Team-Seuk` 조직은 2026-09-04 에 삭제됐다 — Arda 저장소는 이미 `Seuk-Team/Arda`) — 이관 시 초대 관리가 사라진다.
