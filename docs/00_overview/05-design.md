## 0. 대원칙

0. **브랜드 (확정)**: 자라나는 **새싹 연두 + 흰색**. 폰트 **IBM Plex Sans KR 단일** (별도 mono 없음).
1. **모든 값은 토큰(CSS 변수)으로.** 색·간격·폰트 크기·테두리·radius·그림자·텍스트 그림자·모션 시간·z-index 전부. 토큰에 없는 값은 팀장 확인 후 토큰으로 추가.
2. **폰트는 임의 결정 금지** — 변경 제안 시 후보 2~3개를 이유와 함께 제시하고 팀장이 확정한다.
3. **모든 색에는 선택 이유 필수.** 이유를 설명할 수 없는 색 금지. 비슷한 색을 구분 목적으로 여러 개 두지 않는다 — 구분용 색은 한눈에 구분돼야 하며, 안 되면 개수를 줄인다.
4. **테마: 라이트 온리.** 토큰은 시맨틱 네이밍으로 다크 확장 가능 구조 유지.
5. **부분 구현 + 피드백 — 손으로 하나씩 깎는 속도로.** 반드시 이 루프로만: **① 다음 조각 하나를 한 줄로 선언 → ② 그 조각만 구현 → ③ 보여주고 정지(다음 조각 미리 제작 금지) → ④ 팀장 승인 후에야 ①로.** 조각 = 요소 딱 하나(블록의 첫 조각은 위치·크기·바탕색만 잡는 빈 영역, 로고·텍스트·버튼·목록은 각각 별도 조각). 애매하면 더 작게 쪼갠다. 한 응답에 조각 하나. **시킨 것 외 추가 금지(자리 표시 문구 포함).** 상태·극단값 등 "완성의 정의"는 후속 조각으로 누적해 채운다.
6. **플랫폼 공식 디자인 문서 참고 필수**: 터치 타깃·모션·타이포·상태 등은 Apple HIG·Google Material Design 권고를 근거로 정하고, 불확실하면 추측 말고 문서 확인 후 출처를 남긴다.

## 0.5 화면 지도 (확정)

1000명+ 규모 전제. **테이블이 메인, 칸반은 보조 뷰** (근거: Greenhouse=목록+단계 요약, Airtable/Jira=같은 데이터 뷰 전환, 칸반은 카드 수십 장까지만 유효. Lever만 칸반 네이티브인데 그마저 대량 구간은 큐로 처리).

| 메뉴 | 화면 |
|---|---|
| 대시보드 | 요약+진입점: 숫자 카드(내 리뷰 대기·면접 진행·진행중 공고) + **지원자 현황 블록**(2026-08-31 개편 — 리스트 ↔ 칸반 토글이 좌상단, 두 뷰는 같은 데이터. 불합격 제외 4단계, 단계당 5명 + "외 n명 →" 진입점, 면접 행에는 확정 시각/제안 중 칩. **칸반은 보기 전용** — 드래그는 공고의 지원자 화면에서만, 모바일(≤768px)은 §9 원칙대로 리스트만) + 공고별 미니 퍼널 레일 카드(클릭→해당 공고). 기존 "면접 일정"·"전형 현황" 카드는 이 블록으로 통합. 통계 차트는 범위 외 |
| 채용 공고 | 공고 목록 테이블(상태·지원자 수·마감) → **공고 클릭 = 그 공고의 지원자 화면** |
| └ 공고의 지원자 화면 | **본 작업 화면.** 테이블 메인(검색·정렬·페이지네이션·체크박스 일괄 단계 변경) + 칸반 뷰 토글(소수 인원 단계용, 드래그 유지). 퍼널 레일 = 단계 필터. 상세는 페이지 이동 없는 우측 사이드 패널 + "다음 지원자 →" 연속 심사. 지원자 직접 등록(D6) 버튼은 이 화면에만 — 수동 폼이 기본, 여유 시 "파일로 자동 채우기". **제출 파일은 이력서+자기소개서 2종(pdf·docx·hwp)**: 형식별 텍스트 추출(텍스트 PDF만, 스캔본 제외·HWP 실패 시 수동 폴백) → 에이전트가 두 파일을 종합해 구조화 필드 + **담당자용 요약문** 생성(앰버 점선 제안) → 검수·확정 후 지원 접수. 요약문은 상세 패널 상단에 배치 — 내용은 **자소서 요지 + 공고 요건 대비 적합·우려 지점**만(학력·경력·기술처럼 지원 정보 필드로 읽히는 내용 반복 금지). 접수 시 1회 생성·저장하고 패널은 저장값을 즉시 표시, 재생성은 명시적 버튼으로만(스키마: [01-erd.md](01-erd.md) applications.ai_summary). 담당자 메모(서술형)는 첨부 파일 섹션 아래에 "작성자 · 날짜 + 본문" 시간순 목록으로 배치 |
| 지원자 | **전 공고 통합 검색 테이블** — 10만 건 검색·복합 필터 무대(B 성능 스토리, 응답 시간 표기). 칸반 없음 |
| 캘린더 | 담당자 관점 **월 그리드**(2026-08-31 팀장 결정 — 메뉴 이름을 "면접 일정"에서 **"캘린더"**로 바꿨다. 경로는 `/interviews` 그대로 — 기존 링크·북마크를 깨지 않는다). 기본 뷰는 월 그리드: 오늘 강조 · 이전/다음 달 이동 · 날짜 셀에 **면접 3건까지, 나머지는 `+N건`** · **날짜를 클릭하면 그날 목록**이 그리드 아래 펼쳐진다(기존 시간축 테이블을 그대로 재사용 — 시각·지원자·공고·면접관, 행 클릭 = 그 공고의 지원자 화면). **"캘린더 그리드는 범위 외"(하루 15건이 월 셀에 안 들어간다)던 확정은 이 결정으로 뒤집혔다** — 셀은 3건에서 끊고 넘치는 만큼은 `+N건`으로 접으며, 15건 전체는 아래 그날 목록 테이블이 그대로 받는다(테이블이 메인이라는 원칙은 유지된다. 캘린더는 달 단위 밀도를 보는 입구일 뿐). **데이터는 확정된 일정 제안**(ADR-0016)뿐이고 **이 화면에서 등록·수정·삭제는 없다** — `GET /schedules` 조회 전용이다. 조회는 로그인한 사람이면 전원 가능하고, 자기 건만 보려면 **"내 면접만" 체크**를 쓴다(역할로 목록을 잘라 주던 A3 는 폐지). 시간대 필터는 캘린더에 맞지 않아 그날 목록 쪽에 남겼다. 회차 컬럼은 뺐다 — 스키마에 면접 라운드가 없어 지어낼 수 없다. **≤768px 은 월 그리드가 안 들어가므로 주간 스트립(선택한 날이 든 한 주 7칸, 건수만) + 그날 목록**으로 떨어뜨린다(모바일 칸반 금지와 같은 근거 — 가로 스크롤로 밀어 넣지 않는다). 대시보드 "면접 일정" 카드의 "외 N건 더 →" 착지점이다. 같은 시간대는 슬롯으로 묶고 대표는 **그 슬롯에서 가장 이른 면접**(가나다순 같은 임의 기준 금지 — §11) |
| 평가 현황 | 면접관 관점: 내게 배정된 평가 대기 큐 + 우측 평가 패널, 등록 시 자동 다음 지원자 |
| 설정 | 내 계정 · 면접 가능 시간(전원) / 사용자·권한 · 메일 템플릿(admin 전용). **사이드바 하단 프로필은 표시 전용**(2026-08-31 — 로그인한 사용자의 이름·역할 라벨·이니셜 아바타를 실데이터로 그린다. 클릭 진입은 두지 않는다: 설정은 내비에 이미 항목이 있어 두 번째 진입점이 필요 없다). 프로필 사진은 없다 — `users` 테이블에 사진 컬럼이 없어 이니셜 아바타로 대신한다([01-erd.md](01-erd.md) users) |

사이드바 하단 **아르 정사각형**(3D 캐릭터)이 전 화면 공통 에이전트 진입점이다 — 누르면 사이드바 오른쪽으로 360px 패널이 늘어나고 본문은 겹치지 않고 좁아진다(768px 이하는 덮는 오버레이). [ADR-0009 2026-08-31 개정](../03_decision/0009-에이전트-UI-위치.md).

D9(일괄 단계 변경)는 이 구조상 필수로 승격.

## 2. 타이포그래피 (확정)

- 폰트: `--sans` **IBM Plex Sans KR** 단일. 수치·날짜·건수도 같은 폰트로 쓰되 `--font-num` 크기 + `font-variant-numeric: tabular-nums`(자리 폭 고정)를 적용한다. 별도 mono 폰트 금지.
- **스케일 7단계 외 크기 금지. 페이지마다 임의 크기 절대 금지.**

스케일은 Material Design 3 타입 스케일 기준 (Body Large 16 = 본문 권장선, Title Large 22, 내비 항목 높이 48dp):

| 토큰 | 값 | 용도 |
|---|---|---|
| `--font-display` | 26px | 화면 제목 |
| `--font-h1` | 22px | 섹션 제목 · 로고 |
| `--font-h2` | 18px | 카드·패널 제목 |
| `--font-body` | 16px | 본문 · **메뉴(w600, 항목 높이 48px)** |
| `--font-sm` | 14px | 보조 |
| `--font-caption` | 12px | 뱃지·메타 |
| `--font-num` | 14px | 수치·날짜 (tabular-nums) |

- **줄바꿈 (한글·영어 공통)**: 본문 `word-break: keep-all`, 제목 `text-wrap: balance`. **한 줄이어야 하는 텍스트(버튼·뱃지·메뉴·컬럼 제목·수치)는 `white-space: nowrap` 고정 — 폭 부족으로 두 줄이 되면 버그.** 컴포넌트는 내용 최소 폭 보장(`min-width`).
- 표기 통일: 날짜 `2026.09.02` · D-day `D-12` · 건수 `48명`.
- **텍스트 그림자 (확정)**: 그림자는 **글자에 딱 붙는 블러 0 하드 오프셋** — 떠 있는 그림자 금지.
  - `--ts-heading: 0 1px 0 rgba(27,33,23,.34)` — display·h1·h2와 밝은 배경 위 어두운 버튼 글자에 **항상**.
  - `--ts-onfill: 0 1px 0 rgba(0,0,0,.62)` — 색 채움 배경 위 밝은 글자(버튼·토스트)에 크기 무관 **거의 항상**.
  - `--stroke-display`: **대형 타이틀 전용** — 색 채움 배경 위 흰 글자에 8방향 1px 검정 외곽 + 이어지는 2px 밑단. 본문·중소형 금지.
  - 본문·캡션 등 작은 글씨엔 그림자 금지. 이 토큰들 외 텍스트 그림자 금지.

## 3. 간격·배치 (확정)

- `--sp-1~8` = 4·8·12·16·24·32·40·48px. **4px 배수 토큰만** — 통일감은 같은 토큰을 쓰는 것으로 달성한다.
- 동종 요소 동일 규격(카드 패딩·입력 높이 등). 한 화면의 여백·간격은 하나의 그리드 기준선에서.
- 사이드바 폭 `--sidebar-w` 216px · 본문 좌우 여백 `--content-x` 48px (확정). 컨테이너 최대 폭은 두지 않는다 — 테이블이 메인이라 넓은 화면에서 폭을 다 쓴다.
- **깨짐 금지**: 어떤 뷰포트에서도 요소 겹침·삐져나옴 금지. 가로 스크롤은 칸반 보드 영역에만 허용.

## 4. 테두리·radius·그림자 (확정)

- `--border-w` 1px 단일. `--r-card` 8px / `--r-ctl` 6px / `--r-pill` 999px.
- 박스 그림자 2종만: `--sh-card`(옅은 카드) / `--sh-overlay`(hover·오버레이). 남발 금지.

## 5. 모션 (확정)

- `--dur-fast` 120ms / `--dur-base` 200ms / `--dur-slow` 320ms · `--ease` cubic-bezier(.2,0,0,1) — HIG·Material 권장 범위 내.
- hover 절제(색·그림자·1~2px 이동), press 즉각(120ms). 모바일은 hover 없음 전제 — hover 의존 정보 금지.
- 등장 애니메이션은 시그니처 한 곳(퍼널 레일)에만. **`prefers-reduced-motion` 대응 필수.**

## 6. 상태 (완성의 정의)

- 인터랙티브 컴포넌트: **default / hover / press / focus / disabled** 전부 정의.
- 데이터 화면: **loading(스켈레톤 우선) / empty(안내 문구) / error** 전부 정의.
- 드래그 중: 원본 자리 표시 + 고스트 + 드롭 영역 표시. 단계 이동 성공/실패는 **토스트**로 — 실패 롤백이 조용히 지나가면 안 된다.

## 7. 오버플로 (10만 건 극단값 전제)

- 1줄 영역 `ellipsis` / 여러 줄 `line-clamp` / 태그 다수 "N개 + +3". 검증은 극단값(긴 이름·태그 10개·자소서 5천 자)으로.

## 8. 레이어 (확정)

`--z-base 0 < --z-sticky 10 < --z-dropdown 20 < --z-modal 30 < --z-toast 40 < --z-drag 50` — 이 외 z-index 직접 지정 금지.

## 9. 반응형

- 모바일은 칸반 금지 → 단계 탭 + 리스트. 단계 이동은 상세 화면 버튼.
- 터치 타깃 최소 44×44px(HIG).
- **브레이크포인트 (확정) — 이 세 값 외 임의 미디어 쿼리 금지.**

| 값 | 경계에서 바뀌는 것 |
|---|---|
| `1100px` | 상세 패널이 옆에 나란히 → 화면을 덮는 오버레이로 (목업에 적용됨) |
| `768px` | 여기부터 모바일. 사이드바 접기 · 칸반 대신 단계 탭 + 리스트 · 테이블은 카드형 |
| **PC 최소 1280px** | 설계·검증 기준선. 이보다 좁아져도 깨지지 않아야 한다 |

## 10. 접근성

- 텍스트 대비 WCAG AA(4.5:1, 큰 글씨 3:1) — 단계 뱃지 포함. `:focus-visible` 포커스 링 항상. 드래그 대체 수단 = 단계 변경 버튼.
