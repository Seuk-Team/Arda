## 0. 대원칙

0. **브랜드 (확정, 2026-09-04 개정)**: **딥 네트워크** — 어두운 우주 바탕 위 시안 → 블루 → 바이올렛으로 흐르는 노드망. 로고는 노드 다섯 개와 그 연결선이 이루는 형태가 곧 A 다(네트워크이면서 이니셜). 폰트는 **Pretendard Variable**(본문) + **JetBrains Mono**(숫자) 2종.
   - 새싹 연두를 버린 이유: 마크의 의미(유기체)·색온도(웜 옐로우그린)·재질(불투명한 사각 타일)이 화면의 나머지(데이터망·쿨 네온·전부 빛)와 세 가지 모두 어긋났다.
1. **모든 값은 토큰(CSS 변수)으로.** 색·간격·폰트 크기·테두리·radius·그림자·텍스트 그림자·모션 시간·z-index 전부. 토큰에 없는 값은 (2026-09-02 부터 팀장 없음 — 프론트 오너 판단으로) 토큰으로 추가.
2. **폰트는 임의 결정 금지** — 변경 제안 시 후보 2~3개를 이유와 함께 제시하고 ~~팀장이~~ 팀이 확정한다(2026-09-02 부터 팀장 없음). **2026-09-04 확정: Pretendard Variable + JetBrains Mono 2종**(IBM Plex Sans KR 단일에서 변경). mono 를 새로 들인 이유는 §2 에 적었다.
3. **모든 색에는 선택 이유 필수.** 이유를 설명할 수 없는 색 금지. 비슷한 색을 구분 목적으로 여러 개 두지 않는다 — 구분용 색은 한눈에 구분돼야 하며, 안 되면 개수를 줄인다.
4. **테마: 다크 온리** (2026-09-04 — 라이트 온리에서 뒤집었다). 토큰이 시맨틱 네이밍이라 `tokens.css` 의 `:root` 한 블록 교체로 전환됐다 — 26개 CSS 모듈 중 색을 직접 박아 둔 곳이 없었기 때문. 라이트 재확장도 같은 방식으로 열려 있다.
5. **부분 구현 + 피드백 — 손으로 하나씩 깎는 속도로.** 반드시 이 루프로만: **① 다음 조각 하나를 한 줄로 선언 → ② 그 조각만 구현 → ③ 보여주고 정지(다음 조각 미리 제작 금지) → ④ 요청자 확인 후에야 ①로.** 조각 = 요소 딱 하나(블록의 첫 조각은 위치·크기·바탕색만 잡는 빈 영역, 로고·텍스트·버튼·목록은 각각 별도 조각). 애매하면 더 작게 쪼갠다. 한 응답에 조각 하나. **시킨 것 외 추가 금지(자리 표시 문구 포함).** 상태·극단값 등 "완성의 정의"는 후속 조각으로 누적해 채운다.
6. **플랫폼 공식 디자인 문서 참고 필수**: 터치 타깃·모션·타이포·상태 등은 Apple HIG·Google Material Design 권고를 근거로 정하고, 불확실하면 추측 말고 문서 확인 후 출처를 남긴다.

| 캘린더 | 담당자 관점 **월 그리드**(2026-08-31 팀장 결정 — 메뉴 이름을 "면접 일정"에서 **"캘린더"**로 바꿨다. 경로도 `/calendar` 로 옮겼다 — 옛 `/interviews` 는 쿼리(`?slot=`)를 달고 새 경로로 리다이렉트해 북마크·메일 링크가 깨지지 않는다). 기본 뷰는 월 그리드: 오늘 강조 · 이전/다음 달 이동 · 날짜 셀에 **면접 3건까지, 나머지는 `+N건`** · **날짜를 클릭하면 그날 목록**이 열린다(**2026-09-01 개편** — 그리드 아래에 펼치던 것을 **우측 패널**로 옮겼다. 아래에 두면 1280×800 에서 목록 머리가 `top:914px` 라 화면 밖이고, 칸을 눌러도 아무 일이 없는 것처럼 보였다. **같은 날을 다시 누르면 닫히고**, 다른 날이면 열린 채로 그 날로 바뀐다. 일정 없는 날도 열어 "면접 없음"을 말한다 — 고를 시간대가 없으면 시간대 필터는 내놓지 않는다. 360px 에 4열 표가 안 들어가 **행 형태**로 바꿨다: 왼쪽에 시각, 오른쪽에 지원자명 + `공고 · 면접관`. **행 클릭 = 그 지원자의 상세 패널** — `/postings/{공고}?applicant={지원}` 으로 보내면 공고의 지원자 화면이 그 사람을 연 채로 뜬다. `GET /schedules` 가 공고 id 를 주지 않아 상세를 한 번 받아 알아낸 뒤 넘어간다). **대시보드 캘린더 축소판의 행·`외 N건 →` 을 누르면 `/calendar?date=YYYY-MM-DD` 로 와서 그 날이 열린 채로 시작한다** — 축소판에서 4건까지 보다가 넘어가는 것이라 같은 목록이 이어져야 한다. 파라미터 없이 들어오면 패널은 닫힌 채다(한 달을 훑으러 온 경우 그리드를 좁히지 않는다). **"캘린더 그리드는 범위 외"(하루 15건이 월 셀에 안 들어간다)던 확정은 이 결정으로 뒤집혔다** — 셀은 3건에서 끊고 넘치는 만큼은 `+N건`으로 접으며, 15건 전체는 아래 그날 목록 테이블이 그대로 받는다(테이블이 메인이라는 원칙은 유지된다. 캘린더는 달 단위 밀도를 보는 입구일 뿐). **데이터는 확정된 일정 제안**(ADR-0016)뿐이고 **이 화면에서 등록·수정·삭제는 없다** — `GET /schedules` 조회 전용이다. 조회는 로그인한 사람이면 전원 가능하고, 자기 건만 보려면 **"내 면접만" 체크**를 쓴다(역할로 목록을 잘라 주던 A3 는 폐지). 시간대 필터는 캘린더에 맞지 않아 그날 목록 쪽에 남겼다. 회차 컬럼은 뺐다 — 스키마에 면접 라운드가 없어 지어낼 수 없다. **≤768px 은 월 그리드가 안 들어가므로 주간 스트립(선택한 날이 든 한 주 7칸, 건수만) + 그날 목록**으로 떨어뜨린다(모바일 칸반 금지와 같은 근거 — 가로 스크롤로 밀어 넣지 않는다). 대시보드 **캘린더 축소판**의 착지점이다 — 축소판(주간 스트립 + 그날 목록 4건 + `외 N건 →`)을 누르면 다른 대시보드 블록이 페이드아웃되고 **축소판 카드 도형이 이 월 그리드 자리·크기로 확장되며 이어진다**(같은 전환에서 사이드바 활성 메뉴도 캘린더로 옮겨간다). 되돌아올 때는 모션 없이 즉시이고, `prefers-reduced-motion` 이면 전환 없이 이동한다. 달을 옮기면 **그 달 1일이 자동으로 선택**된다 — 화면에 없는 날의 목록이 아래 남지 않게. 같은 시간대는 슬롯으로 묶고 대표는 **그 슬롯에서 가장 이른 면접**(가나다순 같은 임의 기준 금지 — §11) |
| 평가 현황 | 면접관 관점: 내게 배정된 평가 대기 큐 + 우측 평가 패널, 등록 시 자동 다음 지원자. 평가 패널도 아래 **오른쪽 패널 한 자리**를 나눠 쓴다 |
| 설정 | 내 계정 · 면접 가능 시간(전원) / 사용자·권한 · 메일 템플릿(admin 전용). **사이드바 하단 프로필은 표시 전용**(2026-08-31 — 로그인한 사용자의 이름·역할 라벨·이니셜 아바타를 실데이터로 그린다. 클릭 진입은 두지 않는다: 설정은 내비에 이미 항목이 있어 두 번째 진입점이 필요 없다). 프로필 사진은 없다 — `users` 테이블에 사진 컬럼이 없어 이니셜 아바타로 대신한다([01-erd.md](01-erd.md) users) |

사이드바 하단 **아르 정사각형**(3D 캐릭터)이 전 화면 공통 에이전트 진입점이다 — 누르면 360px 패널이 늘어나고 본문은 겹치지 않고 좁아진다(768px 이하는 덮는 오버레이). [ADR-0009 2026-08-31 개정](../03_decision/0009-에이전트-UI-위치.md).

오른쪽 패널 한 자리 — 아르 · 캘린더의 그날 일정 · 지원자 상세 · 평가, 이 넷이 모두 화면 오른쪽 끝에 서고 한 번에 하나만 열린다(나중에 연 쪽이 이기고 먼저 열려 있던 것은 닫힌다). 아르는 사이드바 오른쪽에 있던 것을 이날 오른쪽 끝으로 옮겼다 — 넷이 같은 자리를 두고 겹쳐 서 있었기 때문이다. 새 패널을 만들면 여기 목록에 넣는다: 빠뜨리면 그 화면에서만 둘이 나란히 뜬다(평가 패널이 실제로 그랬다).

- **폭은 하나 — `--right-panel-w` 360px** (§3 동종 요소 동일 규격). 아르 360 / 상세·평가 420 으로 갈려 있던 것을 합쳤다. 360 인 이유: 사이드바 216 + 420 = 636 이면 §9 PC 최소 1280 에서 본문 좌우 여백(`--content-x` 48×2)을 빼고 548px 밖에 안 남아 메인인 테이블이 눌린다. 360 이면 608px 이 남는다. **토큰은 `tokens.css` 에 둔다** — 컴포넌트 모듈 안에 두면 다른 모듈이 못 읽어 또 갈린다.
- **여닫는 모션은 없다.** 폭은 레이아웃 값이라 애니메이션하면 매 프레임 본문이 다시 흐르고 테이블 컬럼까지 재배치된다(200ms·320ms 둘 다 "화면이 왼쪽으로 밀렸다 돌아오는" 느낌이 남았다). 즉시 열고 닫아 리플로우를 한 번으로 줄였다. §5 "등장 애니메이션은 시그니처 한 곳(퍼널 레일)에만" 과도 맞다. 내용 페이드(`opacity`)만 남긴다 — 레이아웃을 안 건드리는 값이다.
- **닫으면 고른 것도 버린다.** 자리를 다른 패널에 뺏길 때도 같다 — 목록의 행 강조가 남아 있으면 밑에 깔아 둔 것처럼 되고, 그 패널이 닫힐 때 되살아난 것처럼 보인다.
- **아르만 언마운트하지 않는다** — 대화 이력이 날아가므로 폭 0 + `inert` 로 가릴 뿐이다. 나머지 셋은 언마운트한다.
- **문서에 가로 스크롤은 두지 않는다** (§3 — 가로 스크롤은 칸반 보드 영역에만). `html, body { overflow-x: hidden }`. 넘치는 요소가 없는데도 껍데기 가로 스크롤바가 떠 있었고, `.shell` 이 `100vh` 인데 `100vh` 는 가로 스크롤바 높이를 빼지 않아 세로 스크롤바까지 따라 생겼다. 세로는 `.page-content` 와 각 패널이 맡는다.

D9(일괄 단계 변경)는 이 구조상 필수로 승격.

## 2. 타이포그래피

- 폰트 (2026-09-04 개정): `--sans` **Pretendard Variable** + `--mono` **JetBrains Mono**.
  - **mono 를 새로 들인 이유**: 계기판·표의 숫자는 자리 폭이 고정돼야 값이 갱신될 때 흔들리지 않는다. `tabular-nums` 만으로는 폰트마다 자릿수 폭이 달라 열이 미세하게 어긋났다. 숫자에는 `.n` 유틸(`--mono` + `tabular-nums`)을 붙인다.
  - **한글은 그대로 Pretendard 로 떨어진다** — JetBrains Mono 에 한글 글리프가 없어 폴백이 자동이다. 그래서 `.n` 을 "09.04 09:12" 처럼 섞인 문자열에 붙여도 안전하다.
  - `.n` 을 **안 쓰는 곳에는 mono 가 내려받아지지도 않는다**(지연 로드). 본문에 mono 를 쓰지 않는다.
  - **한글 단어가 섞이는 자리에는 쓰지 않는다** (2026-09-04 실측으로 추가). 한글 글리프는 Pretendard 로 떨어지지만 **공백·괄호·가운뎃점은 mono 가 그린다** — 고정폭이라 프로포셔널보다 넓다. `"09.04 (금) 14:00"` 칩이 18px, `"일정 제안 중"` 이 8.7px 부풀어 대시보드 파이프라인 카드가 26px 더 넘쳤다. 표 머리글(`시각`·`배정일`)이 숫자 셀과 클래스를 공유해 같이 mono 가 되는 경우도 있으니 확인할 것.
  - 판단 기준: **숫자가 실제로 들어가는 자리에만.** 단위 한 글자(`10명`·`6건`)까지는 붙여도 된다 — 숫자 바로 옆이라 같은 메트릭을 쓰는 편이 자연스럽다.
- **스케일 7단계 외 크기 금지. 페이지마다 임의 크기 절대 금지.**

스케일은 Material Design 3 타입 스케일 기준 (Body Large 16 = 본문 권장선, Title Large 22, 내비 항목 높이 48dp):

| 토큰 | 값 | 용도 |
|---|---|---|
| `--font-display` | 26px | 화면 제목 |
| `--font-h1` | 22px | 섹션 제목 · 로고 |
| `--font-h2` | 18px | 카드·패널 제목 |
| `--font-body` | 16px | 본문 · **메뉴(w600, 항목 높이 48px)** |
| `--font-sm` | 14px | 보조 |
| `--font-caption` | 12px | 뱃지·메타 |
| `--font-num` | 14px | 수치·날짜 (tabular-nums) |

- **줄바꿈 (한글·영어 공통)**: 본문 `word-break: keep-all`, 제목 `text-wrap: balance`. **한 줄이어야 하는 텍스트(버튼·뱃지·메뉴·컬럼 제목·수치)는 `white-space: nowrap` 고정 — 폭 부족으로 두 줄이 되면 버그.** 컴포넌트는 내용 최소 폭 보장(`min-width`).
- 표기 통일: 날짜 `2026.09.02` · D-day `D-12` · 건수 `48명`.
- **텍스트 그림자 (확정)**: 그림자는 **글자에 딱 붙는 블러 0 하드 오프셋** — 떠 있는 그림자 금지.
  - `--ts-heading: 0 1px 0 rgba(0,0,0,.62)` — display·h1·h2 에 **항상**. 다크로 뒤집히며 먹의 농도를 올렸다(어두운 바탕에서 옅은 그림자는 안 보인다).
  - `--ts-onfill: none` (2026-09-04) — 주 동작이 **흰 채움 + 어두운 글자**로 바뀌어 얹을 그림자가 없다. 그림자를 넣으면 탁해지기만 한다. 토큰 이름은 호출부가 많아 남겨 두고 값만 비웠다.
  - `--stroke-display`: **대형 타이틀 전용** — 색 채움 배경 위 흰 글자에 8방향 1px 검정 외곽 + 이어지는 2px 밑단. 본문·중소형 금지.
  - 본문·캡션 등 작은 글씨엔 그림자 금지. 이 토큰들 외 텍스트 그림자 금지.

## 3. 간격·배치 (확정)

- `--sp-1~8` = 4·8·12·16·24·32·40·48px. **4px 배수 토큰만** — 통일감은 같은 토큰을 쓰는 것으로 달성한다.
- 동종 요소 동일 규격(카드 패딩·입력 높이 등). 한 화면의 여백·간격은 하나의 그리드 기준선에서.
- 사이드바 폭 `--sidebar-w` 216px · 본문 좌우 여백 `--content-x` 48px (확정). 컨테이너 최대 폭은 두지 않는다 — 테이블이 메인이라 넓은 화면에서 폭을 다 쓴다.
- **깨짐 금지**: 어떤 뷰포트에서도 요소 겹침·삐져나옴 금지. 가로 스크롤은 칸반 보드 영역에만 허용.

## 4. 테두리·radius·그림자

- `--border-w` 1px 단일. `--r-card` **4px** / `--r-row` 3px / `--r-ctl` 6px / `--r-pill` 999px.
  - **radius 를 8px 에서 4px 로 좁혔다** (2026-09-04): 유리 + 얇은 선 + 모서리 틱으로 가는 계기판 쪽 언어라 라운드가 크면 물러 보인다. 표의 행에는 더 작은 `--r-row`.
- 박스 그림자 3종: `--sh-card` / `--sh-overlay` / `--sh-glow`. 남발 금지.
- **유리(`backdrop-filter: var(--glass)`)는 큰 껍데기·싱글턴에만.** 셸 크롬(사이드바·머리띠·하단 탭)과 카드/패널 껍데기까지다. **`rows.map()` 안에서 데이터 수만큼 늘어나는 것(지원자 카드·공고 카드·문항 카드·채팅 말풍선)에는 걸지 않는다** — blur 는 요소마다 별도 합성 패스라 개수에 비례해 비싸진다. 제외한 것들도 `--bg-elev`(반투명) 색은 그대로 받으므로 톤은 어긋나지 않는다.
- **모서리 틱**(귀퉁이 ㄱ자 선)은 화면의 머리 블록 하나에만. 네 귀퉁이를 다 두르면 카드가 액자가 되어 안의 표·숫자보다 테두리가 먼저 읽힌다.
  - **다크에서 `--sh-card` 는 드롭 섀도가 아니라 `--glass-inset`(윗면 빛)이다.** 어두운 바탕 위의 먹색 그림자는 보이지 않는다 — 면을 띄우는 일은 테두리와 윗면 빛이 한다.
  - `--sh-glow` 는 활성 상태 전용 (§1).
- 모달 뒤를 덮는 막은 `--scrim` 하나. 그림자와 같은 먹색 계열이다 — 화면마다 다른 검정을 쓰지 않는다

## 5. 모션

- `--dur-fast` 120ms / `--dur-base` 200ms / `--dur-slow` 320ms · `--ease` cubic-bezier(.2,0,0,1) — HIG·Material 권장 범위 내.
- **접속 시퀀스(로그인 → 대시보드)의 흰빛은 `--wash`, 층은 `--z-wash` 60.** 순백이 아니라 시안 쪽으로 튼 흰색이다 — 화면의 모든 빛이 시안 → 블루 계열인데 여기만 순백이면 다른 화면에서 온 것처럼 튄다. `--z-wash` 는 §8 스케일의 맨 위: 화면 교체 순간을 가리는 것이 목적이라 그 위에 뜨는 것이 있으면 안 된다.
- **로그인 다이브 전용 2종** (2026-09-04): `--dur-dive` 1600ms / `--dur-land` 280ms. 위 3종의 권장 범위를 넘으므로 **이 연출 외에는 쓰지 않는다.** 다이브는 로그인 응답을 기다리는 동안 진행하다가(`--dur-dive` 속도로 60%까지) 응답이 오면 `--dur-land` 에 착지하는 구조라, 로딩 표시를 연출이 대신한다. 착지가 280ms 보다 짧으면 전환이 눈에 안 읽힌다.
- hover 절제(색·그림자·1~2px 이동), press 즉각(120ms). 모바일은 hover 없음 전제 — hover 의존 정보 금지.
- 등장 애니메이션은 시그니처 한 곳(퍼널 레일)에만. **`prefers-reduced-motion` 대응 필수.**

## 6. 상태 (완성의 정의)

- 인터랙티브 컴포넌트: **default / hover / press / focus / disabled** 전부 정의.
- 데이터 화면: **loading(스켈레톤 우선) / empty(안내 문구) / error** 전부 정의.
- 드래그 중: 원본 자리 표시 + 고스트 + 드롭 영역 표시. 단계 이동 성공/실패는 **토스트**로 — 실패 롤백이 조용히 지나가면 안 된다.

## 7. 오버플로 (10만 건 극단값 전제)
