# 11. 구조 이관 안내 — 백엔드·에이전트 오너용 (2026-09-12)

> 결정 근거는 [ADR-0035](../03_decision/0035-헥사고날-부분적용-Bounded-Context.md). 이 문서는 **"내 코드를 어떻게 고쳐야 하나"** 만 다룬다.
> 대상: 백엔드 오너([01_role/backend.md](../01_role/backend.md)) · 에이전트 오너([01_role/agent.md](../01_role/agent.md)).

## 2. 내 코드를 고치는 방법

### 2-1. import

```python
# 전
from app.screening import weights
from app.mail import publish
from app.api.applications import router

# 후
from app.application.screening import weights
from app.shared.mail import publish
from app.application.api.applications import router
```

`from app.models import Application, User` **는 바뀌지 않았다** — `app/models/__init__.py` 가 전부 다시 내보낸다. 모델을 **새로 추가**할 때만 어느 파일에 넣을지 고르면 된다(§3-1).

### 2-2. DB 조회 — Repository 를 쓴다

```python
# 전
app = db.get(Application, application_id)

# 후
from app.adapter.outbound.pg.application_pg_repository import PgApplicationRepository
app = PgApplicationRepository(db).get(application_id)
```

서비스 함수는 **주입 가능하게** 쓴다 — 그러면 DB 없이 단위 테스트가 된다:

```python
def latest_interview_score(
    db: Session, application_id: int, *,
    interview_repo: InterviewRepository | None = None,   # 기본 None
) -> int | None:
    if interview_repo is None:                            # 호출부는 안 바뀐다
        interview_repo = PgInterviewRepository(db)
    return interview_repo.latest_ai_score_for_application(application_id)
```

```python
# 테스트 — DB 안 띄운다
fake = MagicMock(spec=InterviewRepository)
fake.latest_ai_score_for_application.return_value = 42
assert latest_interview_score(db, 1, interview_repo=fake) == 42
```

**포트에 메서드를 추가할 때**: `ports/output/X_repository.py` 의 ABC 에 추가 → `adapter/outbound/pg/X_pg_repository.py` 에 구현. 둘 중 하나만 하면 `TypeError: abstract method` 로 부팅이 막힌다(의도한 안전장치).

### 2-3. 테스트 patch 경로 — **여기서 가장 많이 깨진다**

`patch()` 는 **"쓰는 쪽 모듈"** 을 바꿔야 한다. 함수가 옮겨갔으면 patch 문자열도 따라와야 하고, 라우터가 `from X import f` 로 가져왔으면 **라우터 모듈 경로**를 patch 해야 한다.

```python
# 전
patch("app.mail.publish")
patch("app.api.interviews._generate_followup_bg")

# 후
patch("app.shared.mail.publish")
patch("app.interview.api.interviews._generate_followup_bg")   # 라우터 경로 그대로
```

라우터가 서비스 함수를 `_` 별칭으로 다시 들고 있는 곳이 있다(`app/application/api/agent.py` 의 `_handle_direct`, `app/interview/api/interviews.py` 의 `_seed_questions_bg` 등). **일부러 남긴 것이다** — 테스트가 그 경로로 patch 하기 때문이다. 지우지 마라.

## 3. 새 규칙 (앞으로 코드를 추가할 때)

### 3-1. 모델 추가
| 무엇 | 어디 |
|---|---|
| 지원자·평가·메모·인적성 | `app/models/application.py` |
| 면접 세션·턴·일정·배정 | `app/models/interview.py` |
| 공고·회사·메일 템플릿 | `app/models/hiring.py` |
| 사용자·인증 | `app/models/talent.py` |
| 파일·앵커·사슬·메일 로그 | `app/models/shared.py` |
| 단계 상수 등 | `app/models/constants.py` |

추가하면 `app/models/__init__.py` 의 재수출에 한 줄 넣는다(안 넣으면 `from app.models import X` 가 깨진다). **스키마를 바꿨으면 같은 커밋에 alembic 리비전 + [01-erd.md](01-erd.md) 갱신** — 기존 규칙 그대로.

### 3-2. 라우터 추가
자기 컨텍스트의 `<context>/api/` 에 파일을 만들고 `app/main.py` 에 `include_router` 한 줄. **어느 컨텍스트인지 헷갈리면**: 그 엔드포인트가 주로 읽고 쓰는 표가 속한 컨텍스트.

### 3-3. 외부 기술을 새로 붙일 때
직접 부르지 말고 `ports/output/` 에 필요한 것만 선언하고 `adapter/outbound/` 에 구현한다. 이유는 메일이 증명했다 — SQS→n8n 교체가 `MAIL_DISPATCH` 환경변수 한 줄이 됐다(코드 수정 0).

### 3-4. 컨텍스트 경계
`application/` 이 `interview/` 의 내부 함수를 직접 부르는 것은 피한다. 필요하면 포트(`ports/output/interview_repository.py`)로 받는다. **`shared/` 는 누구나 쓴다**(메일·파일·라벨·무결성). `app/agent/` 는 예외적으로 여러 컨텍스트를 가로지른다 — 아르는 원래 그런 도구다.

## 4. 에이전트 오너용 (app/agent/)

**폴더 구조·프롬프트·도구 정의·런타임은 그대로다.** 바뀐 것만:

1. **라우터가 얇아졌다.** `app/application/api/agent.py` (약 1,100줄 → 325줄). 규칙 라우터 로직 7개(`handle_direct` `choices_from_tool_results` `choice_for_app` `build_per_choice_pendings` `stage_rule_reply` `router_reply` `format_reply` 등)는 `app/application/agent_service.py` 로 옮겼다.
2. **Pydantic 스키마 11개**가 `app/schemas/agent.py` 로 나갔다 (`ChatRequest` `ChatResponse` `ChoiceOut` `PendingActionOut` `ToolCallOut` `Confirm*` `Stt*` `SummaryOut` `ProbeClaim` `ProbesOut`). 스키마를 고칠 땐 이 파일.
3. **도구 안에서 DB 를 볼 때** Repository 를 쓴다 — `app/agent/tools/*.py` 의 `db.get()` 은 이미 치환됐다.
4. **`WRITE_TOOL_NAMES` 재수출**은 `from .write import WRITE_TOOL_NAMES as WRITE_TOOL_NAMES` 형태로 둔다(중복 별칭). 린터가 미사용으로 지우지 않게 하는 표시다.
5. **부수효과는 REST 와 같은 함수를 쓴다** — 도구가 단계를 바꿀 때 자체 로직을 쓰지 않고 `app/application/stage_service.py` 를 부른다. 규칙이 두 곳에 있으면 반드시 어긋난다.
6. LLM 백엔드는 `app/ports/output/llm_port.py` 로도 노출돼 있다(현재는 `app.agent.backends` 재수출). 도메인 코드가 LLM 을 부를 일이 생기면 이쪽을 쓴다.

리팩터 뒤 전 코드를 점검했다. **테스트로는 안 잡히던 것 3건이 실제 고장이었다.**

그 밖에: 미사용 import 약 150개 제거, `shared/mail.py` 의 죽은 SQS 코드(어댑터로 옮긴 뒤 남은 `_sqs`·`_queue_url`·`_publish_to_n8n`) 제거, 주석·독스트링의 옛 경로 15곳 수정.

### 왜 못 잡았나 → 무엇을 깔았나

1·2·3 은 **그 코드 줄을 타는 테스트가 없어서** pytest 초록이었다. 그래서 두 가지를 추가했다:

- **CI 린트 게이트** (`.github/workflows/ci.yml` 의 `lint` 잡): `uvx ruff@0.16.7 check --select F app tests`. `F821`(미정의 이름)·`F401`(미사용 import) 만 본다 — 2·3 은 이걸로 1초에 잡힌다. 스타일 규칙은 켜지 않았다(기존 코드가 통째로 빨개져 아무도 안 보는 CI 가 된다).
- **종단 파이프라인 테스트** (`backend/tests/test_pipeline_e2e.py`, 10개): 컨텍스트 **사이의 배선**만 본다 — 포트 4개가 어댑터로 실제 조회하는지, 단계 전환이 메일 로그·큐까지 가는지, 어댑터 교체가 되는지, **라우터 전체가 등록돼 OpenAPI 오퍼레이션이 80개 넘는지**, `/health` 200 · 보호 경로 401.

배포 진입점(compose·systemd)은 린트가 못 본다. **모듈을 옮기면 `infra/` 를 직접 grep 해라** — 1번이 그렇게 프로덕션까지 갔다.

## 8. 안 한 것 (일부러)

Full DDD 는 도입하지 않았다 — Aggregate Root, Domain Event, 전면 Value Object, DTO↔스키마 이중화, Entity/ORM 분리, 단일 스타 온톨로지, 엄격한 4계층. 6주 프로젝트에서 비용이 이득을 넘는다는 판단이고 근거는 ADR-0035 에 있다. **다음 단계 후보**: 라우터의 남은 UseCase 분리(`interviews.py` 677줄은 현재가 자연스러운 최소), 입력 포트(`ports/input/`) 도입 — 필요해지면 그때.
