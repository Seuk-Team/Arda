# 06. 주차별 계획

> **이 문서는 주차별 계획이지 작업 지시가 아니다.** 각자의 작업 큐는 자기 도메인 문서([role/](../01_role))에만 있다.
> 예전 `docs/weekly/` 폴더(주차당 파일 여러 개)를 이 파일 하나로 통일했다 (2026-08-24, [ADR-0007](../03_decision/0007-도메인-오너제-전환.md) 후속). 옛 문서 원문은 아래 기록 절에 그대로 있다.

## 규칙

- 주 시작 시 [양식](#양식)을 복사해 새 주차 절을 **기록 절 맨 위에** 추가한다. **한 번 쓴 절은 고치지 않는다** — 원래 계획이 남아야 나중에 왜 늦었는지 알 수 있다.
- 주중에 계획이 바뀌면 그 주차 절 아래에 `#### WN-2 — <제목>` 하위 절을 덧붙인다. **번호가 큰 것이 우선한다.**
- **도메인 안에서만 도는 추가 작업은 여기 쓰지 않는다** — 오너가 자기 role 문서의 큐에 넣으면 끝(그게 오너제다). 여기 쓰는 것은 도메인 경계를 넘거나 주 마감 게이트에 영향을 주는 변경뿐이다.
- 한 주에 하위 절이 3개를 넘으면 그 주 계획이 틀렸다는 뜻이다. 다음 주차 절에 원인을 한 줄 적는다.
- **초기 버전 09/04(금) · 1차 완성 09/30(수)** · 주차: W1 08/24~28 ~ W5 09/21~25 + 09/28~30 버퍼. **팀장 머지·검수는 매주 금요일 최소 1회**(필요시 2~3회) — 팀장 승인이 필요한 PR은 목요일까지 올린다.

## 주간 계획 프롬프트 — 오너용

주 시작(월요일)에 각 오너가 자기 작업 폴더에서 Claude Code를 열고 아래를 붙여넣는다. 첫 줄의 빈칸만 채우면 된다. Claude가 지난주 점검 → 이번 주 계획 → role 문서 갱신까지 해준다.

```
주간 계획을 세워라. 내 GitHub 아이디: ___

1. CLAUDE.md 와 docs/00_overview/04-team.md 를 읽고 내 도메인과 role 문서를 확인해라.
2. docs/01_role/<내 도메인>.md 를 읽어라. 주간 계획 표와 작업 큐가 기준이다.
3. 지난주를 점검해라 — git log, 머지된 PR, 열린 PR을 보고:
   - 지난주 계획 행의 완료 기준이 실제로 충족됐는지 항목별로 대조해라.
   - 큐에서 끝난 것과 밀린 것을 구분해라.
4. 이번 주 계획을 세워라:
   - 이번 주차 행을 기준으로, 밀린 것을 앞에 넣어 이번 주 할 일 목록을 만들어라.
   - 다가오는 게이트에서 역산해 이번 주에 반드시 끝나야 하는 것을 표시해라.
     게이트: **09/04 초기 버전** (정의는 docs/00_overview/00-overview.md 진행 순서 절) → 09/30 1차 완성.
   - 선행이 안 풀린 항목은 무엇이(누구 도메인이) 막고 있는지 적어라.
5. 계획을 내게 보여주고 확인받은 뒤, docs/01_role/<내 도메인>.md 의 주간 계획 표와
   작업 큐를 실제에 맞게 갱신해라 (완료 ✅ · 밀림 표시 · 순서 조정).
   브랜치를 만들어 커밋하고 PR을 올려라 — 자기 role 문서 갱신은 셀프 머지 대상이다.
6. 다른 도메인에 걸리는 것(내가 기다리는 것 / 나를 기다리게 하는 것)이 있으면
   docs/00_overview/06-weekly.md 이번 주차 절의 조율 표에 넣을 내용을 제안만 해라 —
   공용 문서라 직접 고치지 않는다. 팀 채널에 올릴 요약 한 줄도 만들어줘라.
7. 끝나면 이번 주 첫 작업(큐 최상단)을 바로 시작할지 물어라.

지키는 것:
- 주차 조정은 자유지만 범위·마일스톤 자체를 바꾸는 것은 팀장 합의가 필요하다 — 바꾸지 말고 제안으로 표시해라.
- 다른 도메인 파일과 공용 파일은 건드리지 않는다.
```

```
mockup.html (이미 있음, 아무도 안 건드림)
├── A1 로그인 ──┬── A2 설정   (.tfield .tinput 복사)

├── E1 평가현황      (독립)
├── H1 통합검색      (독립)
└── 모바일 리스트    (독립)
```

- 각 지시서의 선행조건은 **복사 원본 파일 기준**이다. 위 그림에서 들어오는 화살표가 없는 6개 화면(A1 · B1 · E1 · H1 · 대시보드 · 모바일)은 **기다릴 것 없이 Day 1에 바로 시작한다.** A2 · C1만 A1 머지를 기다린다.

#### 6. 충돌 방지

**원칙은 그대로다 — 한 사람 = 자기 파일.**

| 팀원 | 이번 주 파일 |
|---|---|
| 팀원1 | `mockup-login.html`✅ · `mockup-apply.html` · `docs/00_overview/email-templates.md` · `backend/app/api/applications_public.py` · `backend/app/api/files.py` · `backend/app/worker.py` |
| 팀원2 | `mockup-applicants.html`✅ · `mockup-mobile.html`✅ · `backend/scripts/seed/` · `backend/app/api/search.py` |
| 팀원3 | `mockup-postings.html` · `backend/app/api/postings.py` · `backend/app/api/applications.py` · `backend/app/api/notes.py` |
| 팀원4 | `mockup-evaluations.html` · `mockup-settings.html` · `docker-compose.yml` · `backend/Dockerfile` · `backend/app/api/evaluations.py` · `backend/tests/` |

- `backend/app/api/` 아래는 **파일 단위로 나뉜다.** 라우터 하나 = 파일 하나 = 한 사람.
- **`backend/app/main.py`는 예외다.** 라우터를 등록하려면 모두가 한 줄씩 추가해야 한다. **`include_router` 한 줄만** 건드리고, 충돌이 나면 양쪽 줄을 다 남기면 된다.
- **공용 파일은 아무도 고치지 않는다**: `mockup.html` · `01-erd.md` · `02-api.md` · `models.py`. 고쳐야 하면 팀 채널 → 팀장.

##### 09/02 — C7 첨부 포함 제출 관통 실측 (백엔드 오너)

> [09/01 밤 인계 표](#0901-밤--인계-항목-마감-팀장)의 C7 을 닫은 결과다. **코드 변경 없음 — 브라우저로 실제 경로를 한 번 통과했다.**

기존 공고를 안 쓴 이유 둘 — C6 `UNIQUE(job_posting_id, email)` 에 걸릴 수 있고, `POST /postings/{id}/public-link` 는 **재발급이라 그 공고의 기존 토큰이 즉시 무효**가 된다.

| 단계 이력 | `(없음) → applied` |

**업로드가 실제로 됐다는 근거**: [`Apply.tsx`](../../frontend/app/src/pages/Apply.tsx) 가 **업로드 실패 시 예외를 던져 제출 자체를 중단**시킨다. (실측 당시 코드는 `if (!put.ok) throw` 였고, 같은 날 10:11 `123cac0` 이 진행률 바를 넣으며 XHR 로 바꿨다 — `xhr.status < 300` 이 아니면 reject, `onerror` 도 reject 라 **불변조건은 그대로다.** 근거가 코드 한 줄이 아니라 이 성질이라는 뜻이다.) **제출이 끝났다는 것이 곧 브라우저→S3 PUT 이 2xx 였다는 뜻이다.** 08/31 에 막혀 있던 CORS 경로가 열려 있음이 실측으로 확인됐다. `s3_key` 도 서버가 정한 UUID 경로(`applications/<uuid>/resume.pdf`)로 들어갔다 — 설계대로다.

~~**🔴 걸린 것 — 담당자가 첨부를 볼 화면이 없다.**~~ **같은 날 해소됐다.** 실측 시점에는 `presign`·`s3_key` 가 프론트 전체에서 `Apply.tsx` 하나에만 있어 **지원자가 올리는 쪽만 있고 받아보는 쪽 화면이 없었다.** 프론트 오너에게 넘겼고 **10:22 `f4d7a1b` 로 지원자 상세에 첨부 파일 블록이 들어왔다.**

**첨부까지 열리는 것을 실측했다** — 지원자 상세에 `c7-verification-resume.pdf · 이력서 · 826 B` 가 뜨고, 발급(`presign-download` 200) 후 그 URL 로 PDF 원문이 그대로 렌더된다(업로드한 내용과 일치). **이로써 게이트 문구의 "담당자 쪽에서 확인까지"가 첨부를 포함해 실측으로 닫혔다.**

> 검증 방법 메모: 첨부를 눌러도 브라우저 창에서 아무 일이 없어 보일 수 있다 — 파일 열기가 막힌 환경이면 그렇다. **기능 실패와 구분하려면 같은 URL 을 iframe 으로 불러 렌더되는지 본다**(iframe 로드는 CORS 검사를 안 받는다). 오류 표시(`role=alert`)와 콘솔이 비어 있는데 화면만 안 바뀌면 환경 쪽을 의심할 것.

⚠️ **첨부 보기 화면을 만들 때 `fetch` 로 내려받으면 안 된다.** 버킷 CORS 의 `AllowedMethods` 가 **`PUT` 뿐**이라([07-deploy](07-deploy.md) S3 버킷 CORS 절) 브라우저 `fetch` GET 은 막힌다 — 실제로 이번 검증에서 `Failed to fetch` 를 봤다. 링크 이동(`<a href>`·`location`) 방식이면 CORS 검사를 안 받는다. **`fetch` 로 짜면 08/31 과 같은 함정에 다시 빠진다** — 서버는 멀쩡하고 로그에도 안 남는다.

**부수 관찰 두 개**

- **AI 요약이 `insufficient`("제출물 부족")로 나왔다.** 자소서에 "실제 지원이 아니다"라고 적었고 기술이 비어 있어서다 — 모델 판단 자체는 맞다.
