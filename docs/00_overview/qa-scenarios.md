# QA 시나리오 — 필수 기능 확인

> **상태**: 초안 · 작성일 2026-08-24
> 화면이 아직 없으므로 [05-design.md](05-design.md) §0.5 화면 지도를 기준으로 작성.
> 확정되지 않은 UI 디테일은 **(화면 확정 후 갱신)** 으로 표시.

각 시나리오: **전제** (어떤 상태에서) → **절차** (누가 뭘 클릭·입력) → **기대 결과** (무엇이 보이면 성공)

---

## A. 인증 · 권한

### A1. 회원가입 / 로그인 (JWT)

- **전제**: 계정이 없는 상태. 로그인 화면이 열려 있다.
- **절차**: 회원가입 폼에 이름·이메일·비밀번호를 입력하고 가입 버튼을 누른다. 가입 완료 후 로그인 폼에 이메일·비밀번호를 입력하고 로그인 버튼을 누른다.
- **기대 결과**: 대시보드 화면으로 이동한다. 사이드바 하단에 로그인한 사용자 이름과 역할이 표시된다.

### A2. 역할 구분: 관리자 / 채용담당자 / 면접관

- **전제**: 관리자(admin) 계정으로 로그인되어 있다.
- **절차**: 설정 → 사용자 관리 화면에서 사용자 목록을 확인한다. 한 사용자의 역할을 "멤버"에서 "관리자"로 변경하고 저장한다. **(화면 확정 후 갱신)**
- **기대 결과**: 해당 사용자의 역할이 "관리자"로 바뀌어 표시된다. 역할은 **관리자 / 멤버 2종**뿐이다 ([ADR-0017](../03_decision/0017-등급-이분화.md)).

### A3. ~~역할별 접근 제어 (면접관은 배정된 지원자만)~~ → **조작 제어** (2026-08-31 개정)

옛 A3(조회 제한)는 폐지됐다 ([ADR-0017](../03_decision/0017-등급-이분화.md)). 이제 확인할 것은 "무엇이 열렸는가"와 "무엇이 남았는가"다.

**A3-1. 조회는 전원 열려 있다**

- **전제**: 멤버 계정으로 로그인되어 있다. 이 멤버에게 배정된 지원자가 2명, 배정되지 않은 지원자가 10명 있다.
- **절차**: 지원자 목록·평가 현황·검색 화면을 확인하고, 배정되지 않은 지원자의 상세를 연다.
- **기대 결과**: **12명 전원이 보인다.** 배정되지 않은 지원자의 상세·이력·평가·메모·이력서도 정상 열람된다. 로그아웃 상태에서 같은 URL 을 열면 로그인 요구(401).

**A3-2. 멤버는 배정된 건만 평가를 쓴다**

- **절차**: 배정된 지원자와 배정되지 않은 지원자 각각에서 평가 작성을 시도한다.
- **기대 결과**: 배정된 건은 저장된다. 배정되지 않은 건은 **접근 거부(403)** 와 "본인에게 배정된 지원자만 평가할 수 있습니다" 안내.

**A3-3. 관리자 전용 조작**

- **절차**: 멤버 계정으로 ① 면접관 배정/해제 ② 남의 가용 시간 등록·삭제 를 시도한다.
- **기대 결과**: 둘 다 **403**. 같은 조작을 관리자 계정으로 하면 성공한다. 단 **본인 가용 시간**은 멤버도 등록·삭제할 수 있다.

## B. 채용 공고

### B1. 공고 생성 / 수정 / 삭제

- **전제**: 채용담당자 계정으로 로그인되어 있다. 채용 공고 화면이 열려 있다.
- **절차**: "공고 생성" 버튼을 누르고, 제목·설명·요구사항을 입력한 뒤 저장한다. 저장된 공고를 열어 제목을 수정하고 저장한다. 이후 해당 공고를 삭제한다. **(화면 확정 후 갱신)**
- **기대 결과**: 생성한 공고가 목록에 나타난다. 수정 후 변경된 제목이 표시된다. 삭제 후 목록에서 사라진다.

### B2. 공고 상태: 임시저장 / 진행중 / 마감

- **전제**: 임시저장 상태의 공고가 하나 있다.
- **절차**: 해당 공고를 열고 상태를 "진행중"으로 변경한다. 이후 다시 "마감"으로 변경한다.
- **기대 결과**: 상태 변경할 때마다 공고 목록의 상태 뱃지가 갱신된다. "진행중" 공고만 지원자가 접근할 수 있는 공개 링크가 활성화된다.

### B3. 공고별 지원자 수 집계

- **전제**: "백엔드 개발자" 공고에 지원자 5명이 있다.
- **절차**: 채용 공고 목록 화면을 연다.
- **기대 결과**: "백엔드 개발자" 공고 행에 지원자 수 "5명"이 표시된다. 새 지원자가 접수되면 숫자가 즉시(또는 새로고침 시) 증가한다.

## C. 지원 (지원자용 화면 — 로그인 없이 외부 링크)

### C1. 지원서 제출 폼

- **전제**: 지원자가 채용 공고의 공개 지원 링크(`/public/postings/{id}`)를 브라우저에 열었다. 로그인하지 않은 상태.
- **절차**: 공고 정보를 확인한다. 이름·연락처·이메일·최종학력 등 지원 폼 항목을 입력하고 "지원서 보내기" 버튼을 누른다.
- **기대 결과**: 제출 완료 화면이 표시된다. 채용담당자가 해당 공고의 지원자 목록을 열면 방금 제출한 지원자가 "지원 접수" 단계로 나타난다.

### C2. 이력서 파일 업로드

- **전제**: 지원 폼이 열려 있다. 이력서 파일(PDF, 5MB 이하)을 준비했다.
- **절차**: "이력서 첨부" 영역에 파일을 드래그하거나 파일 선택 버튼을 눌러 파일을 선택한다.
- **기대 결과**: 업로드 진행률이 표시되고, 완료되면 파일 이름과 용량이 표시된다. 채용담당자가 해당 지원자 상세에서 "다운로드" 버튼을 누르면 같은 파일을 받을 수 있다.

### C3. 개인정보 수집 동의

- **전제**: 지원 폼의 모든 항목을 입력한 상태. 개인정보 수집 동의 체크박스가 있다.
- **절차**: 동의 체크박스를 체크하지 않은 채 "지원서 보내기"를 누른다. 이후 체크박스를 체크하고 다시 누른다.
- **기대 결과**: 미체크 시 제출이 되지 않고 동의 안내가 표시된다. 체크 후 제출이 정상 완료된다.

## D. 지원자 관리

### D1. 지원자 목록 (테이블 뷰)

- **전제**: 채용담당자 로그인. "백엔드 개발자" 공고에 지원자 20명 이상이 있다.
- **절차**: 채용 공고 목록에서 "백엔드 개발자"를 클릭한다.
- **기대 결과**: 해당 공고의 지원자 목록이 테이블 형태로 표시된다. 이름·단계·경력·스펙·평점·지원일 컬럼이 보이고, 페이지네이션으로 전체를 탐색할 수 있다.

### D2. 칸반 보드 (단계별 컬럼)

- **전제**: 지원자 목록 화면이 열려 있다.
- **절차**: 보기 방식을 "칸반"으로 전환한다.
- **기대 결과**: 지원 접수 / 서류 검토 / 면접 / 최종 합격 / 불합격 컬럼이 가로로 나열되고, 각 지원자가 현재 단계에 해당하는 컬럼에 카드로 표시된다.

### D3. 드래그로 단계 이동

- **전제**: 칸반 보드가 열려 있고, "지원 접수" 컬럼에 지원자 카드가 있다.
- **절차**: 해당 카드를 마우스로 드래그하여 "서류 검토" 컬럼에 놓는다.
- **기대 결과**: 카드가 "서류 검토" 컬럼으로 이동한다. 단계 변경 이력이 기록되고(D5), 지원자에게 메일이 발송된다(G1). 실패 시 원래 위치로 돌아가고 토스트 알림이 표시된다.

### D4. 지원자 상세 페이지

- **전제**: 지원자 목록(테이블 또는 칸반)이 열려 있다.
- **절차**: 지원자 이름(또는 카드)을 클릭한다.
- **기대 결과**: 우측 상세 패널이 열린다. 지원자 이름·현재 단계·지원 정보(연락처·이메일·학력·경력·기술)·첨부 파일·메모가 표시된다.

### D5. 단계 변경 이력 기록

- **전제**: 지원자 "김도현"의 단계를 "지원 접수 → 서류 검토 → 면접"으로 두 번 변경한 상태.
- **절차**: 김도현의 상세 화면에서 단계 이력을 확인한다. **(화면 확정 후 갱신)**
- **기대 결과**: 각 변경 건이 "누가 / 언제 / 어디서 어디로" 형태로 시간순 표시된다. 두 건의 이력이 보인다.

### D6. 담당자가 지원자 직접 등록

- **전제**: 채용담당자 로그인. "백엔드 개발자" 공고의 지원자 화면이 열려 있다.
- **절차**: "+ 지원자 직접 등록" 버튼을 누르고, 이름·연락처·이메일 등을 수동 입력한 뒤 등록한다.
- **기대 결과**: 새 지원자가 "지원 접수" 단계로 목록에 추가된다. 공고의 지원자 수가 1 증가한다.

## E. 평가

### E1. 평가 코멘트 작성 (점수 + 텍스트)

- **전제**: 면접관 계정으로 로그인. 평가 현황 화면에서 배정된 지원자가 보인다.
- **절차**: 지원자를 선택하고, 우측 평가 패널에서 점수(1~5)를 선택하고 코멘트를 입력한 뒤 "등록" 버튼을 누른다.
- **기대 결과**: 평가가 저장되고, 점수와 코멘트가 기록된다. 점수를 선택하지 않으면 등록 버튼이 비활성 상태다.

### E2. 평가 목록 조회, 평균 점수 계산

- **전제**: 지원자 "김도현"에 대해 면접관 2명이 각각 점수 4, 5를 등록한 상태.
- **절차**: 김도현의 상세 화면에서 평가 목록을 확인한다.
- **기대 결과**: 두 건의 평가(작성자·점수·코멘트)가 표시되고, 평균 점수 4.5가 계산되어 표시된다.

## F. 파일

### F1. 이력서 업로드 → S3 저장

- **전제**: 지원 폼이 열려 있다. PDF 이력서 파일을 준비했다.
- **절차**: 파일 첨부 영역에서 파일을 선택한다.
- **기대 결과**: presigned URL을 통해 브라우저에서 S3로 직접 업로드된다. 업로드 진행률이 표시되고 완료 시 파일명이 나타난다. API 서버를 경유하지 않는다.

### F2. presigned URL 다운로드

- **전제**: 채용담당자 로그인. 이력서가 첨부된 지원자의 상세 화면이 열려 있다.
- **절차**: 첨부 파일 섹션의 "다운로드" 버튼을 누른다.
- **기대 결과**: 브라우저가 파일 다운로드를 시작한다. 다운로드한 파일이 지원자가 올린 원본과 동일하다.

## G. 알림 · 메일

### G1. 단계 변경 시 지원자에게 메일 발송

- **전제**: 지원자 "김도현"의 이메일이 등록되어 있다. 칸반 또는 상세 화면이 열려 있다.
- **절차**: 김도현의 단계를 "서류 검토"에서 "면접"으로 변경한다.
- **기대 결과**: 김도현의 이메일로 "면접 단계로 전환되었습니다" 내용의 메일이 발송된다. 발송 기록이 남는다. **(메일 내용은 화면 확정 후 갱신)**

### G2. 메일 발송 비동기 처리 (SQS + 워커)

- **전제**: 단계 변경이 발생했다.
- **절차**: 단계 변경 API 호출 후 응답 시간을 확인한다. 백그라운드 워커 로그를 확인한다.
- **기대 결과**: 단계 변경 API는 메일 발송 완료를 기다리지 않고 즉시 응답한다(200ms 이내). SQS 큐에 메시지가 들어가고, 워커가 이를 처리하여 메일을 발송한다.

### G3. 발송 실패 시 재시도

- **전제**: 메일 워커가 동작 중이다. 의도적으로 잘못된 이메일 주소로 발송을 유도한다.
- **절차**: 발송 실패 후 워커 로그와 `email_logs` 테이블을 확인한다.
- **기대 결과**: 실패 기록이 남고, 일정 시간 후 재시도가 실행된다. 재시도 횟수와 상태가 로그에 기록된다.

## H. 검색 · 필터

### H1. 이름 / 이메일 검색

- **전제**: 채용담당자 로그인. 공고의 지원자 화면이 열려 있고, 지원자가 20명 이상이다.
- **절차**: 검색창에 "김도현"을 입력한다. 이어서 검색어를 지우고 "dohyun@example.com"을 입력한다.
- **기대 결과**: 각각 해당 이름 또는 이메일과 일치하는 지원자만 필터링되어 표시된다. 검색어를 지우면 전체 목록이 다시 나타난다.

### H2. 단계별 필터

- **전제**: 지원자 화면이 열려 있다. "면접" 단계 지원자가 3명 있다.
- **절차**: 퍼널 레일에서 "면접" 구간을 클릭한다. **(화면 확정 후 갱신)**
- **기대 결과**: 테이블에 면접 단계 지원자 3명만 표시된다. 필터를 해제하면 전체 목록이 다시 나타난다.

## J. 시스템 · 운영

### J1. Docker 컨테이너 구성

- **전제**: 프로젝트를 클론한 직후. Docker가 설치되어 있다.
- **절차**: 터미널에서 `docker compose up`을 실행한다.
- **기대 결과**: API 서버·DB·워커 컨테이너가 기동된다. `http://localhost:<포트>/health`에 접속하면 정상 응답이 온다. DB에 접속 가능하다.

### J2. AWS 배포

- **전제**: AWS 인프라가 구성되어 있다.
- **절차**: 배포 파이프라인을 실행한다(GitHub Actions push 또는 수동 트리거).
- **기대 결과**: AWS 환경에 애플리케이션이 배포되고, 공개 URL로 접속 시 로그인 화면이 표시된다. 헬스체크 엔드포인트가 정상 응답한다.

### J3. API 문서 (Swagger)

- **전제**: API 서버가 기동되어 있다.
- **절차**: 브라우저에서 `http://localhost:<포트>/docs`에 접속한다.
- **기대 결과**: Swagger UI가 열리고, 모든 엔드포인트 목록이 표시된다. 각 엔드포인트의 요청·응답 스펙을 확인할 수 있고, "Try it out"으로 실제 호출이 가능하다.

## 실패 케이스

### F-1. 중복 지원 (같은 공고에 같은 이메일)

- **전제**: 지원자가 "백엔드 개발자" 공고에 이미 지원서를 제출한 상태. 같은 공개 링크를 다시 열었다.
- **절차**: 같은 이메일 주소로 지원서를 다시 제출한다.
- **기대 결과**: "이미 지원한 공고입니다" 안내가 표시되고 제출이 거부된다(409). 기존 지원 기록은 변경되지 않는다.

### F-2. 허용되지 않는 파일 형식 업로드

- **전제**: 지원 폼이 열려 있다. `.exe` 파일을 준비했다.
- **절차**: 파일 첨부 영역에서 `.exe` 파일을 선택한다.
- **기대 결과**: "허용되지 않는 파일 형식입니다" 안내가 표시되고 업로드가 거부된다. 허용 형식(pdf, docx, hwp) 안내가 함께 표시된다.

### F-3. 큰 파일 업로드 (용량 초과)

- **전제**: 지원 폼이 열려 있다. 50MB 크기의 PDF 파일을 준비했다.
- **절차**: 파일 첨부 영역에서 해당 파일을 선택한다.
- **기대 결과**: "파일 크기가 제한을 초과했습니다" 안내가 표시되고 업로드가 시작되지 않는다. 최대 허용 용량이 함께 안내된다.

### F-4. 권한 없는 접근 (면접관이 미배정 지원자 조회)

- **전제**: 면접관 계정으로 로그인. 본인에게 배정되지 않은 지원자 ID를 알고 있다.
- **절차**: 브라우저 주소창에 해당 지원자의 상세 URL(`/applications/{id}`)을 직접 입력한다.
- **기대 결과**: "접근 권한이 없습니다" 메시지가 표시되고 지원자 정보는 노출되지 않는다(403).

### F-5. 마감된 공고에 지원 시도

- **전제**: "프론트엔드 개발자" 공고가 "마감" 상태다. 해당 공고의 공개 지원 링크를 열었다.
- **절차**: 지원 폼 항목을 입력하고 제출을 시도한다.
- **기대 결과**: "마감된 공고입니다" 안내가 표시되고 지원서 제출이 불가하다. 지원 폼 자체가 비활성 상태이거나 접수 불가 안내 화면이 표시된다.

### F-6. 로그인 실패 (잘못된 비밀번호)

- **전제**: 로그인 화면이 열려 있다. 올바른 이메일과 잘못된 비밀번호를 준비했다.
- **절차**: 이메일을 입력하고 잘못된 비밀번호를 입력한 뒤 로그인 버튼을 누른다.
- **기대 결과**: "이메일 또는 비밀번호가 올바르지 않습니다" 안내가 표시되고 로그인되지 않는다. 어떤 항목이 틀렸는지는 구분하지 않는다(보안).

### F-7. 필수 항목 미입력 지원 제출

- **전제**: 지원 폼이 열려 있다.
- **절차**: 이름을 비우고 나머지만 입력한 뒤 제출을 시도한다.
- **기대 결과**: "이름을 입력해 주세요" 등 누락 항목에 대한 안내가 표시되고 제출이 되지 않는다.
