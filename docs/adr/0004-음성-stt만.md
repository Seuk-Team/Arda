# ADR-0004. 음성은 STT + 기존 텍스트 에이전트 (speech-to-speech 제외)

- 상태: 확정 (기획 단계) · 미결: 음성 입력을 어느 화면에 붙일지

## 맥락

음성 기능은 입력(STT) / 판단(에이전트) / 출력(TTS) 세 층으로 나뉜다. speech-to-speech(실시간 음성 API)는 세 층을 벤더가 통째로 가져가며, 특히 **tool calling이 벤더 런타임 안으로 들어간다** — 우리 에이전트의 핵심(문장 → 검색·필터·상태변경 도구 순차 호출)이 벤더 세션 안에서 일어나고 우리는 도구 스펙만 등록하는 껍데기가 된다. 포트폴리오 관점에서 최악. 비용도 캐싱 없이 실제 에이전트 기준 분당 $0.18~$0.46.

## 결정

- **Whisper API로 STT → 기존 텍스트 에이전트 → 텍스트 응답.** TTS는 여유 시 한 줄 추가.
- 로컬 Whisper 대신 API: 성능이 아니라 **배포** 문제 — AWS 필수 요건에서 GPU 인스턴스는 비용, CPU는 지연으로 데모 불가. "내 컴퓨터에서만 되는 기능"을 만들지 않는다.
- 실제 구현 대상은 STT 호출이 아니라 **엔티티 해석 레이어**: 이름 유사도 매칭(후보 여럿이면 되묻기), 기술 용어 음차 정규화(패스트에이피아이→FastAPI), 한글 수사→숫자(이년→2), **파괴적 작업은 반드시 확인 단계**("김도현을 불합격으로 옮길까요?").
- 응답이 텍스트인 이유: **조회 결과는 화면이 이기고, 명령은 음성이 이긴다.**

## 결과

면접 답변거리: "Whisper 붙였다"는 3초짜리지만 "음성 인식 오류가 도구 호출로 전파되는 걸 어떻게 막았나"는 10분 설명 가능.
