# ADR-0027. 인적성 검사는 한다 — 단 AI 는 응답을 요약만 하고 성격을 판정하지 않는다

> **상태: 초안 · 2026-09-02** · 작성 에이전트 도메인 — **팀 확정 대기** (총괄 공석, ADR-0025)
> 관련: [ADR-0002 표정분석 제외](0002-표정분석-제외.md) · [ADR-0003 AI는 추천까지만](0003-ai-추천만.md) · [ADR-0016 면접 일정 자동화](0016-면접-일정-자동화.md) · [ADR-0026 AI 면접](0026-AI-면접-음성분석-제외.md)

## 문제

**지원자에게 인적성 검사를 하자는 제안이 나왔다.** 접수된 지원자에게 메일로 검사 링크를 보내고, 응답을 AI 가 분석·요약해 붙여 준다는 안이다. **발송은 서류검토(`screening`) 전에 한다 — 응답이 서류검토 때부터 참고자료로 쓰이는 것이 목적이다.** 면접 단계에서는 같은 요약을 면접 준비 자료로 다시 쓴다.

ADR-0026 때와 같은 구조다 — **"검사를 실시한다"와 "AI 가 분석한다"는 성격이 다른 두 기능**이 한 제안에 묶여 있다. 앞은 폼과 메일의 문제고, 뒤는 심리 추론의 경계 문제다. 나눠서 결정한다.

## 결정

**1. 인적성 검사는 만든다 — 서류검토 전에 발송한다.** 접수(`applied`) 지원자에게 공개 토큰 링크 메일(ADR-0016 의 일정 제안과 같은 패턴) → 지원자가 리커트 척도 문항에 응답 → 저장 → AI 요약이 지원자 상세에 붙는다. **서류검토자가 서류와 나란히 보고, 면접 단계에서도 같은 자료를 참고한다.**

**2. 문항은 기본 자체 문항으로 시작한다.** MBTI·DISC 같은 상표 있는 검사를 쓰지 않고, 흉내 내지도 않는다. 협업·업무 선호·스트레스 대처 같은 **직무 관련 행동 성향** 문항 10개 내외 리커트 5점 척도. 문항 세트는 코드 상수로 시작한다 — 문항 편집 UI 는 만들지 않는다.

**3. AI 는 요약만 한다 — 성격 유형을 판정하지 않는다.** 출력은 두 가지뿐이다:
- **응답 통계** — 척도 평균·분포, 응답 원문 그대로의 표
- **관찰 요약 한 문단** — "협업 관련 문항에 일관되게 높게 응답했다"처럼 **응답 사실의 재서술**만

"내향적이다", "팀워크에 부적합하다", "리더형이다" 같은 **유형 판정·적합성 판단·점수화는 만들지 않는다.** 판단은 서류검토자·면접관이 한다 (ADR-0003 그대로).

**4. 미응답은 검토를 막지 않는다.** 응답이 오기 전에도 서류검토는 그대로 진행한다 — 지원자 상세에 "미응답"으로 보일 뿐이다. **미응답·응답 지연을 자동으로 불이익화하는 로직(정렬 가중치·필터 기본값 포함)을 만들지 않는다.** 응답은 지원자의 협조이지 의무가 아니다.

**5. AI 면접 파이프에 얹지 않는다.** `interview_sessions`·`interview_turns` 는 음성 전제다(`audio_s3_key`·`stt_cost_usd`, ADR-0026). 인적성은 구조화된 텍스트 응답이라 **별도 테이블**로 간다. 공유하는 것은 토큰 공개 접근 패턴뿐이다.

**6. 결과는 담당자 화면에만 붙는다.** 지원자 상세의 요약 옆 새 섹션. 지원자 본인에게 결과·해석을 돌려주지 않는다 — 돌려주는 순간 "검사 결과 통보"가 되고 정확성 책임이 생긴다.

## 왜 3번인가 — 요약과 판정의 경계

### 이미 두 번 자른 논리다

[ADR-0002](0002-표정분석-제외.md)가 표정→긴장도를, [ADR-0026](0026-AI-면접-음성분석-제외.md)이 음성→심리 추론을 잘랐다. 공통 기준: **"측정할 수 있다"와 "쓸모가 있다"는 다른 문제고, 숫자 뒤에 면접관이 할 일이 없으면 의사결정에 못 쓰는 지표다.**

자체 10문항 설문에서 "이 지원자는 내향적"이라는 판정이 나오면 그 근거를 방어할 수 없다. 표준화·신뢰도 검증이 없는 문항으로 유형을 판정하는 것은 **검증 안 된 심리검사를 만들어 파는 일**이다.

### 서류검토 앞에 놓일수록 경계가 더 중요하다

이번 결정으로 검사 결과가 **깔때기의 가장 넓은 단계(서류검토) 앞에** 놓인다. 면접 참고일 때보다 영향 범위가 크다 — 판정형 문장 하나가 수십 명의 서류검토에 스며든다. 그래서 3번(재서술만)과 4번(미응답 불이익 금지)이 이 ADR 의 몸통이다.

### 응답 재서술은 방어된다

- **설명할 수 있다.** "지원자가 이 문항에 5점으로 답했다"는 사실이다. "그래서 외향적이다"는 추론이다. 우리는 사실까지만 간다
- **지원자가 반박할 수 있다.** 응답 원문이 그대로 담당자에게 보인다 — 요약이 원문을 왜곡하면 대조로 드러난다
- **개인정보보호법의 자동화 결정 설명 요구권**(2023 개정)에 걸릴 것이 없다 — 자동으로 결정되는 것이 없다

### 명칭도 과장하지 않는다

정식 인적성 검사(GSAT 류)를 대체한다고 말하지 않는다. 발표·UI 에서는 "사전 성향 설문" 수준의 표현을 쓴다. **작게 말하고 정확하게 동작하는 쪽이 발표 §5("무엇을 안 했고 왜")의 서사와 맞는다.**

## 왜 5번인가 — 별도 테이블

`interview_turns` 에 얹으면 `audio_s3_key`·`transcript`·`stt_cost_usd` 가 전부 NULL 인 행이 생기고, 음성 코드 곳곳에 "인적성이면 건너뜀" 분기가 붙는다. 테이블 두 개(`aptitude_sessions` + 응답)가 분기 없는 코드보다 싸다. 스키마는 구현 시점에 ERD 와 같은 커밋으로 확정한다 (협업 규칙).

## 하지 않는 것

- 성격 유형 판정, 합불 추천, 점수화, 응답 기반 자동 단계 이동
- 미응답·응답 지연의 자동 불이익화
- 표준화 심리검사 제공·대체 주장
- 문항 편집 UI (상수로 시작)
- 지원자에게 결과 반환

## 미결 — 구현 전 정할 것

| 항목 | 갈림길 | 기본안 |
|---|---|---|
| 발송 트리거 | 접수 시 자동 훅 vs 담당자 발송 | **공고 단위 일괄 발송 버튼부터** (담당자가 "미발송 전원에게 보내기"). 접수 훅 자동화는 운영해 보고 — 자동 전환은 쉽고 역방향(이미 나간 메일)은 없다 |
| 응답 마감 | 서류검토 시작 전 며칠을 주나 | 토큰 만료 7일 기본, 만료 후 재발송 가능 |
| 문항 확정 | 기본 문항 초안을 누가 검수하나 | 에이전트 도메인이 초안, 팀 검수 |
| 일정 | W3(프롬프트 튜닝)·W4(STT) 중 어디에 끼우나 | **팀 결정** — 신규 3~4일 분량, 기존 큐 하나가 밀린다 |

## 지금 결정하지 않는 것

메일 템플릿 문구, 재응답 허용 여부, `evaluations` 연계 — 전부 구현 지시서에서. 이 문서는 **경계(요약까지만·미응답 불이익 금지·별도 테이블·서류검토 전 발송)** 만 고정한다.
