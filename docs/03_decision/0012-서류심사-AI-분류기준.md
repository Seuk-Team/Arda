# ADR-0012. 서류심사 AI 분류 기준

- 상태: **v1 확정** — 추후 변동 가능
- 작성: suvisdev (에이전트)
- 선행: [ADR-0003](0003-ai-추천만.md) · [ADR-0009](0009-에이전트-UI-위치.md) · [ADR-0011](0011-에이전트-모델-비용.md)
- 로드맵: [role/agent.md](../01_role/agent.md) §5 W4~W5

## 맥락

지원자가 수천 명일 때 서류심사를 사람이 한 명씩 검토하는 건 현실적이지 않다.
AI가 **채용공고 조건**과 **이력서 기본 정보**(학력·경력·기술)를 비교해 자동 분류하되, 최종 판단은 사람이 한다 (ADR-0003).

문제는 세 가지다:

1. **분류 기준**: 충족/미충족 이분법으로는 "애매하지만 우수한 인재"를 놓친다
2. **유사 능력 판별**: "Python 필수"인데 Go 경험자는? 모든 업종에서 범용적으로 작동해야 한다
3. **자기소개서/포트폴리오**: AI가 처리할 수 있는 것과 없는 것을 명확히 나눠야 한다

## 전체 프로세스 (3단계)

| 단계 | 주체 | 내용 |
|---|---|---|
| **1단계: AI 자동 분류** | AI | 이력서 스펙 매칭 + 자기소개서 축약 |
| **2단계: 담당자 검토** | 사람 | 애매한 사람 직접 확인 + 포트폴리오 검토 |
| **3단계: 면접** | 사람 | 1차(기술/직무) + 2차(컬쳐핏/임원) |

## 1. 채용조건 입력 방식

### v1: 자유 텍스트 (방법 B 채택)

공고 본문을 그대로 넣으면 AI가 조건을 자동 추출한다:
- "Python 또는 유사 언어 경험 2년 이상, AWS 우대"
- → 필수: `Python (유사 허용)`, `2년+` / 선호: `AWS`

모든 업종에서 사용 가능하다. 개발 회사는 "Python 2년, AWS", 영업 회사는 "B2B 3년, CRM 경험", 제조업은 "기계공학 학사, 3D CAD" — 어떤 조건이든 같은 방식으로 입력하고 분류한다.

> **추후 변동 가능**: 방법 A(구조화 입력 — 태그 형태로 필수/선호 직접 입력, 유사 허용 ON/OFF)를 추가할 수 있다. 두 모드 모두 최종적으로 같은 구조화 조건 목록으로 변환되는 구조.

## 2. 1단계 — AI 자동 분류 (서류심사)

### 2-1. 이력서 스펙 매칭: 3그룹 분류

| 분류 | 조건 | AI 행동 | 담당자 행동 |
|---|---|---|---|
| **✓ 통과** | 필수조건 모두 충족 | 자동으로 "1차 면접" 추천 | 확인만 누르면 됨 |
| **? 검토** | 필수 일부 미충족 BUT 유사/대체 경험 있음 OR 선호조건만 미충족 | 분석 근거 제시 ("Python 없으나 Go 2년, 유사도 82%") | 직접 판단 — 통과 or 제외 |
| **✗ 제외** | 필수조건 대부분 미충족 + 대체 경험 없음 | 자동으로 "불합격" 추천 | 확인만 누르면 됨 |

**핵심: "검토" 그룹이 AI의 가치다.** 단순 필터로는 놓칠 인재를 AI가 찾아서 담당자에게 보여준다.

### 2-2. 유사 능력 판별

**방식: 임베딩 + 임계값**

1. 조건과 이력서 항목을 임베딩 벡터로 변환 (LLM 임베딩 모델 사용)
2. 코사인 유사도 계산
3. 임계값 기반 분류:
   - 90% 이상: 동일 능력으로 간주 → 충족
   - 60~89%: 유사 능력 → "검토"로 분류 + 근거 표시
   - 60% 미만: 관련 없음 → 미충족

**업종 무관 (텍스트 임베딩 기반):**
- 개발: "Python" ↔ "Go" = 82%, "Python" ↔ "Excel" = 15%
- 영업: "B2B 영업" ↔ "기업 영업" = 91%, "B2B 영업" ↔ "소매 판매" = 35%
- 제조: "3D CAD" ↔ "SolidWorks" = 88%, "3D CAD" ↔ "포토샵" = 20%

**임계값 커스터마이징:**
- 기본값: 60%
- 회사별 조정 가능: 엄격하게 80%, 넓게 40%
- 조건별 개별 설정 가능: "기술은 90% 이상만, 학력은 60%도 OK"

**피드백 학습:**
- 담당자가 "검토" 그룹에서 판단할 때마다 데이터 축적
- "Go 경험자를 Python 대체로 통과시킨 적 3회" → 유사도 가중치 조정
- 시간이 지나면 회사별로 더 정확해짐

### 2-3. 자기소개서 분석 (있는 경우만)

자기소개서가 있으면 AI가 **채용공고 기준으로** 핵심 내용을 축약한다. 없는 회사에서는 이 단계를 건너뛴다.

**축약 방식:**
- 채용공고에서 원하는 역량(팀워크, 문제해결 등)을 기준으로 추출
- 공고 조건이 없으면 범용 항목(지원 동기, 핵심 경험, 강점)으로 추출

**"읽었다"는 증명:**
- **원문 인용**: 축약 근거가 되는 원문 문장을 함께 표시
- **하이라이트**: 자소서 원문에서 AI가 추출한 부분에 색깔 표시
- **커버리지**: 전체 중 AI가 분석한 비율 표시 (나머지는 담당자가 직접 확인)

### 2-4. 포트폴리오 — AI 분석 대상에서 제외

포트폴리오는 형식이 너무 다양해서(PDF, 노션, GitHub, 비핸스, 영상 등) AI가 분석하기 어렵다.
AI는 **"포트폴리오 첨부됨"만 표시**하고, 2단계에서 담당자가 직접 검토한다.

## 3. 2단계 — 담당자 검토

AI가 자동 분류한 결과를 바탕으로, 담당자가 직접 확인해야 할 부분만 검토한다:

- **"검토" 그룹**: AI 분석 근거를 보고 통과/탈락 직접 결정
- **포트폴리오**: 첨부된 포트폴리오 직접 확인
- **자소서 미분석 부분**: 커버리지에서 빠진 부분 직접 확인
- AI가 자동으로 통과/제외시킨 사람도 **담당자가 뒤집을 수 있다** (ADR-0003)

## 4. 3단계 — 면접

### 1차 면접 (기술/직무)
- **평가 항목**: 직무 역량, 기술 깊이, 문제 해결력
- **평가 방식**: 면접관이 E2 평가 API로 1~5점 + 코멘트
- **통과 기준**: 평균 3.0 이상 (조정 가능)

### 2차 면접 (컬쳐핏/임원)
- **평가 항목**: 팀 적합성, 성장 가능성, 커뮤니케이션
- **평가 방식**: 동일 (E2 평가 API)
- **최종 합격 기준**: 1차 + 2차 종합 평균 3.5 이상 (조정 가능)

### AI의 역할 (면접 단계)
- 서류심사 결과 요약 제공 (면접관 참고용)
- **면접 결과 판정은 AI가 하지 않는다** (ADR-0003)

## 5. UI에 보여줄 것

서류심사 화면에서:
- **분류 결과**: 통과 / 검토 / 제외 카운트
- **검토 그룹 상세**: AI 분석 근거 (유사도 %, 대체 가능성 설명)
- **자소서 축약**: 원문 하이라이트 + 커버리지
- **일괄 처리**: "통과 그룹 전체를 1차 면접으로" 버튼
- **에이전트**: ⌘K로 자연어 필터/일괄 처리

## 감수하는 것

- 임베딩 모델의 유사도가 100% 정확하지 않다 — "검토" 그룹의 존재 이유
- 피드백 학습에 시간이 필요하다 — 초기에는 기본 임베딩만으로 작동
- 면접 기준 점수(3.0, 3.5)는 회사마다 다르다 — 설정으로 조정 가능하게
- 자기소개서 축약은 정량 평가가 아니라 정성 정보 압축이다 — 점수를 매기지 않는다
- 포트폴리오는 AI 범위 밖이다 — 형식 다양성 때문이며, 추후 특정 형식(PDF 등)만 지원 가능
