# ADR-0006. 프론트엔드는 React — 서버 템플릿(Jinja) 기각

- 상태: 확정 (2026-08-23)

## 맥락

목업이 순수 정적 HTML이라 두 갈래가 가능했다.

- **Jinja(서버 템플릿)**: FastAPI가 HTML을 완성해 내려준다. 별도 프론트 서버·빌드·API 호출·CORS가 통째로 없다. 팀원이 만든 HTML을 템플릿에 거의 그대로 넣고 반복문만 씌우면 된다.
- **React**: 프론트 프로젝트를 따로 세우고 API로 데이터를 받는다. 팀원 HTML은 JSX로 다시 쓴다.

HTML → JSX 이식 비용 자체는 크지 않다(기계적 변환이라 도구로 처리된다). 실제 무게는 이식이 아니라 **딸려오는 층**이다 — 개발 서버 두 개, 빌드, CORS, 배포 대상 두 곳. 그 층이 막히면 데모 자체가 안 뜬다.

판단 기준은 하나로 잡았다: **"프론트가 안 뜰 때 혼자 고칠 수 있는가."**

## 결정

React로 간다. 팀장이 이미 React를 써왔고, 위 층들이 손에 익어 있다. 익숙하지 않은 스택을 새로 배우는 비용이 그 층을 유지하는 비용보다 크다고 봤다.

## 결과

- **팀원 지시서는 그대로 둔다.** 팀원은 계속 정적 HTML 목업을 만들고, JSX 이식은 팀장이 한다. 순수 HTML일수록 이식이 깔끔하다.
- **공통 조각(사이드바·테이블 행·버튼·입력)을 먼저 React 컴포넌트로 만든 뒤** 화면을 이식한다. 안 그러면 화면마다 같은 마크업을 네 번 다시 친다.
- 화면을 붙이기 전에 **모델·API가 먼저다.** 프론트는 붙일 것이 있어야 붙는다.
