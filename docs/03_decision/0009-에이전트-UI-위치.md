# ADR-0009. 에이전트 UI 위치 (+ 음성 입력 위치)

- 상태: **확정** (2026-08-25) — 혼합안(A 기본 + 권고 1~4) 채택
- 작성: suvisdev (에이전트) · 협업 예정: cloverky (프론트 구현)
- 선행: [ADR-0003](0003-ai-추천만.md) · [ADR-0004](0004-음성-stt만.md) · [ADR-0008](0008-에이전트-앱-정식-트랙-승격.md)
- 로드맵: [role/agent.md](../01_role/agent.md) §3 · W2 M1

## 맥락

도구 호출 에이전트(자연어 → 검색·조회 / 단계 변경·메일 초안)를 **어디에 두고 어떻게 띄울지**가 아직 없다. UI 위치가 정해져야:

- 프론트가 공통 진입점·단축키·확인 모달을 어디에 심을지 알 수 있고
- 쓰기 도구의 **확인 단계**([ADR-0003](0003-ai-추천만.md)) UI가 어느 레이어에 붙는지 정해지며
- [ADR-0004](0004-음성-stt만.md)의 미결(**음성 입력을 어느 화면에 붙일지**)을 같은 결정으로 닫을 수 있다

프로토타입([05_prototype.html](../04_planning/05_prototype.html))에는 이미 **⌘K 에이전트 콘솔**(하단 슬라이드)과 별도 **AI 서류 검토** 버튼이 있다. 시안은 이 둘을 섞지 않는다 — 서류 검토(요약·점수 제안)는 상세 패널의 앰버 점선 플로우로 두고, **이 ADR은 “도구 호출 에이전트” 진입점만** 다룬다.

## 시안 3안

공통 불변:

- 앰버 점선 = AI 제안 / 잎초록 실선 = 사람 확정 ([05-design.md](../00_overview/05-design.md) §1)
- **쓰기 도구(단계 변경·메일 초안 확정 전)는 확인 UI를 반드시 거친다** — 콘솔/패널 안에서 “김도현을 서류 검토로 옮길까요? [취소][확인]”
- 조회 결과는 가능하면 **기존 목록·상세를 갱신**하고, 에이전트 창에는 실행 로그만 남긴다 (프로토타입과 동일)
- 버튼으로 되는 일(단순 단계 변경 한 건)은 에이전트에 넣지 않는다 (ADR-0003)

### 안 A — ⌘K 커맨드 콘솔 (프로토타입 승격)

| | |
|---|---|
| **형태** | 화면 하단(또는 중앙) 오버레이. `⌘K` / `Ctrl+K`로 열고 Esc로 닫음. 한 줄 입력 + 프리셋 칩 + 단계 로그 |
| **장점** | 이미 프로토타입에 있음 → 데모·설명 비용 최소. 복합 작업(검색→필터→변경→초안)에 로그가 잘 보임. 어떤 화면에서든 동일 진입 |
| **단점** | 지원자 상세와 시선이 분리됨. 모바일(768px)에서 하단 오버레이가 키보드와 겹칠 수 있음 |
| **음성** | 콘솔 입력창 옆 마이크 버튼 1개 (STT → 같은 텍스트 입력란). **에이전트 콘솔 전용** |

### 안 B — 우측 사이드 패널 챗

| | |
|---|---|
| **형태** | 지원자 상세 패널과 비슷하게 우측(또는 좌측 사이드바 옆)에 고정 폭 챗 패널. 히스토리 유지 |
| **장점** | 대화형 UX에 익숙. 긴 답·여러 턴(되묻기: “동명이인 중 누구?”)에 유리. STT 오류 수정 턴이 자연스러움 |
| **단점** | 상세 패널과 **폭 경쟁** (테이블이 메인이라 넓은 화면이 필요 — 05-design §3). 구현·상태 관리 비용이 콘솔보다 큼. “버튼으로 되는 일”과 경계가 흐려지기 쉬움 |
| **음성** | 챗 입력창 마이크. 패널이 열려 있을 때만 |

### 안 C — 지원자 상세 인라인 제안 강화 (에이전트 진입 최소화)

| | |
|---|---|
| **형태** | 전역 에이전트 창은 얇게만 두고(또는 없음), **상세 패널 안**에서 요약·적합 우려·다음 행동 제안(앰버)을 강화. 복합 명령은 상세의 “에이전트에게 맡기기”에서만 |
| **장점** | ADR-0003 UI 규약과 한몸. 합불·요약을 “사람 확정” 동선과 붙이기 쉬움 |
| **단점** | **목록을 가로지르는 복합 작업**(“Python 2년+AWS 추려서 서류합격…”)에 약함 — 에이전트 핵심 데모 문장이 상세에 묶임. 프로토타입 ⌘K 스토리와 어긋남 |
| **음성** | 상세 패널 전용 — 전역 명령에는 부적합 |

## 권고 (오너 제안 — 확정 아님)

**안 A를 기본으로 채택**하고, 안 B의 장점만 선택 흡수한다.

1. **진입·단축키·실행 로그 = 안 A** (프로토타입 그대로 제품화)
2. **쓰기 확인·동명이인 되묻기**는 콘솔 로그 영역 안의 확인 카드로 처리 (안 B의 멀티턴을 콘솔 높이만 늘려 수용)
3. **이력서 요약·적합 우려**는 안 C처럼 **상세 패널 앰버 블록**으로 유지 — 이건 도구 호출 에이전트가 아니라 추출 파이프라인(W3 M2)의 UI
4. **음성 입력**: ADR-0004 미결을 **안 A — 콘솔 전용 마이크**로 닫는다. 상세·목록에는 마이크를 두지 않아 “어디서 말하지?” 혼란을 막는다

모바일: `768px` 이하에서는 ⌘K 대신 헤더의 “에이전트” 버튼만. 콘솔은 하단 시트(최대 높이 45vh) + 로그 접기.

## 감수하는 것

- 안 A는 “챗봇 제품”처럼 안 보일 수 있다 — 발표에서는 **실행 로그 = 도구 호출 증명**으로 말한다.
- 콘솔과 상세 패널이 동시에 열리면 좁은 화면에서 답답하다 — Esc가 둘 다 닫게 하고, 쓰기 확인 중에는 상세를 닫지 않도록 구현 규칙을 프론트와 합의한다.
