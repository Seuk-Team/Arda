# ADR-0030. 알림·메일 자동화를 n8n 워크플로로 분리한다 — AWS 를 떠나도 돌게

> **상태: 초안 · 2026-09-07** · 작성 인프라·총괄(suvisdev). 백엔드(woojeongalex) 와 공동 — 워커·큐가 백엔드 도메인이다. 오너 개정으로 확정([03-conventions](../00_overview/03-conventions.md) "결정 문서 개정").
> 배경: 강사 제안(2026-09-07) — "AWS 가 내려가는 것도 생각해서 n8n 으로 돌리는 게 어떠냐."
> 관련: [ADR-0024 §13 두 타깃 빌드](0024-sLLM-로컬-모델-전략.md) · [role/infra 큐 12~15 온프레미스 판](../01_role/infra.md) · [07-deploy 메일 절](../00_overview/07-deploy.md) · [G4 지시서](../02_tasks/G4-설정-실동작-메일-발송.md)

## 문제

메일 파이프라인은 **AWS 부품 두 개와 우리 워커 코드에 묶여 있다.**

```
단계 변경 → email_logs 행 → SQS 큐 → worker(템플릿·재시도·dry-run·MessageId) → SES → 지원자
```

이 구조는 2026-09-07 새 계정에서 끝까지 실측 통과했다(검증 주소로 최종 합격 메일 수신). 문제는 동작이 아니라 **묶여 있는 곳**이다.

- AWS 계정은 suvisdev 개인 계정이고 예산 **$400 · 2026-10-27 까지**다. 그 뒤에도 서비스를 돌리려면 SQS·SES 가 없는 곳에서 돌아야 한다.
- 개인정보(지원자 이메일·면접 기록) 때문에 **로컬에서 돌리는 것이 1순위**라는 배포 전략이 이미 있다(ADR-0024 §13, 온프레미스 판). 메일·큐가 그 전환의 두 칸이다.
- "메일 뒤에 무엇을 더 붙이자"(Discord 알림, 면접 D-1 리마인더, 담당자 요약)는 요구가 올 때마다 워커 코드를 고치고 배포해야 한다.

강사 제안의 "AWS 가 내려간다" 는 **장애**보다 **AWS 를 떠나는 상황**으로 읽는다. n8n 을 EC2 에만 두면 장애엔 같이 죽는다 — 이 문서는 그 점을 숨기지 않는다.

## 결정

**1. 알림·메일 자동화 계층을 n8n 워크플로로 분리한다.** 트리거는 우리 API 가 쏘는 **웹훅**(SQS 가 아니다), 발송은 n8n 의 **SES 노드 또는 SMTP 노드** — 노드 하나 바꾸면 공급자가 바뀐다. AWS 종료 시 n8n 컨테이너와 워크플로 JSON 을 그대로 다른 곳으로 옮긴다.

**2. 템플릿·기록은 계속 우리 쪽이다.** n8n 은 본문을 만들지 않는다. `GET /internal/email-logs/{id}/render` 같은 내부 경로로 **완성된 제목·본문**을 받아 보내고, 결과(`provider_message_id` 또는 실패 사유)를 `POST /internal/email-logs/{id}/result` 로 돌려준다. 한글 템플릿·설정값(`mail.sender_name` 등)·`email_logs` 가 진실인 구조는 그대로다. 우리 API 가 검증하지 못하는 값을 n8n 이 적는 것이므로, [ADR-0028](0028-제출물-무결성-앵커.md) 의 `publications/{id}/result` 와 같은 "영수증" 취급이다.

**3. 기존 워커는 스위치로 남긴다.** `MAIL_DISPATCH=worker|n8n` (기본 `worker`). n8n 경로가 시연·리허설을 통과하기 전까지 운영 기본값은 바꾸지 않는다. 두 경로가 같은 `email_logs` 행을 두 번 보내지 않게 **발행 지점 하나(`stage_service.publish_all`)에서 갈린다.**

**4. n8n 은 self-host 다.** n8n Cloud 는 쓰지 않는다 — 지원자 이메일·이름이 외부 SaaS 를 거친다. 1단계는 운영 EC2 에 컨테이너(compose `n8n` 서비스, Caddy `/n8n/*`, **Basic Auth 필수**, 내부 API 는 docker 네트워크로만). 2단계는 같은 compose 를 로컬 PC 에서 띄우고 발송 노드만 SMTP 로 바꿔 **"AWS 없이 돈다"** 를 한 번 실증한다.

**5. 발표 시연은 검증된 경로로 한다.** 시연 전까지 n8n 경로가 리허설 2회를 통과하지 못하면 시연은 `worker` 로 하고, n8n 은 "추가 자동화(Discord 알림 등)" 로만 보여준다.

## 대안 — 채택하지 않은 것

| 대안 | 왜 아닌가 |
|---|---|
| **워커 코드 유지 + SMTP·DB 폴링으로 교체**(큐 13·14) | 이식성은 같게 얻지만 "흐름을 바꿀 때마다 코드·배포" 는 그대로. 강사 제안의 두 번째 뜻(화면에서 보이는 자동화)을 못 챙긴다. 다만 **n8n 이 실패하면 이 길로 돌아온다** — 반나절짜리라 위험이 작다 |
| n8n 이 SQS 를 직접 소비 | AWS 를 떠날 때 트리거까지 바꿔야 한다. 웹훅이면 트리거는 그대로다 |
| n8n 이 DB 를 직접 읽고 쓴다 | 템플릿·설정 로직이 두 곳에 생기고, n8n 자격 증명에 DB 비밀번호가 들어간다. 내부 API 로 좁힌다 |
| n8n Cloud | 개인정보 외부 전송 + 월 $20~. 예산·정책 둘 다 밖 |
| 지금 워커를 그대로 두고 아무것도 안 함 | 10/27 이후와 온프레미스 판 요구에 답이 없다 |

## 결과 — 바뀌는 것

- **인프라**: compose 에 `n8n` 서비스(이미지 `n8nio/n8n`, 볼륨 `n8n_data`, 메모리 300~500MB — t3.medium 여유 안), Caddy `/n8n/*` + Basic Auth, 백업 대상에 `n8n_data` 추가, `~/status.sh`·경보에 n8n 헬스 추가. 비용 0. → **1단계 인프라 몫 PR 2026-09-07** — 설치 절차 [07-deploy "n8n"](../00_overview/07-deploy.md), 워크플로 초안 [infra/n8n/](../../infra/n8n/README.md).
- **백엔드**: 내부 경로 2개(렌더링 조회·결과 기록, 서비스 토큰으로 보호), `MAIL_DISPATCH` 스위치, `publish_all` 분기. `email_logs.provider_message_id`(#58) 는 그대로 쓴다.
- **워크플로(n8n JSON, 저장소 `infra/n8n/` 에 커밋)**: `stage-changed` 웹훅 → 렌더링 조회 → SES(또는 SMTP) 발송 → 결과 기록 → 실패 시 재시도 3회 후 결과 `failed`. dry-run 은 워크플로 변수 하나.
- **문서**: 07-deploy 메일 절, 02-api 내부 경로, 01-erd 변경 없음.
- **발표**: §3 아키텍처 구성도에 n8n 칸, §6 다음 단계의 "로컬 AI 하이브리드" 옆에 "AWS 없이 도는 자동화".

## 정하지 못한 것 — 오너가 채운다

1. **내부 API 인증** — 서비스 토큰(고정 헤더)으로 갈지, n8n 전용 admin 계정 JWT 로 갈지. 앵커 봇처럼 계정 방식이면 만료 12시간 문제가 또 생긴다 → 서비스 토큰 쪽이 맞아 보이나 백엔드 판단.
2. **재시도·중복 방지 책임** — 워커의 "3회 재시도·이미 sent 면 건너뜀" 을 n8n 쪽에서 재현하되, 결과 기록 API 가 멱등이어야 한다.
3. **2단계(로컬) 의 SMTP 계정** — 지메일 앱 비밀번호 vs 학원 도메인 메일. 발신 도메인 SPF/DKIM 이 없으면 지메일이 버린다(우정 지적 2026-09-07).
4. ~~**n8n 편집 권한** — 팀 전원 Basic Auth 공유 vs suvisdev 만.~~ → **결정됨 (2026-09-07, 팀장): 팀 전원 공유.** "공동 프로젝트로 추후 누군가가 빠지더라도 모두가 진행할 수 있게" — 09-02 이탈 때 권한이 한 사람에게 묶여 치른 대가([ADR-0025](0025-운영-권한-이관.md))를 반복하지 않는다. Basic Auth 와 n8n owner 계정 모두 팀 공유 계정 하나, 비밀번호는 팀 채널 고정 메시지. 워크플로 JSON 은 저장소가 진실이므로 화면 편집 후 반드시 export 커밋([infra/n8n/README](../../infra/n8n/README.md)).

## 일정 제안 (팀장)

| 단계 | 언제 | 무엇 | 완료 기준 |
|---|---|---|---|
| 1 | W3 남은 기간 | n8n 컨테이너 + Caddy + Basic Auth, 워크플로 1개(단계 변경 메일), `MAIL_DISPATCH=n8n` 으로 검증 주소에 실발송 | 최종 합격 메일이 n8n 경로로 도착, `provider_message_id` 기록 |
| 2 | W4 중간 점검 | 같은 compose 를 로컬 PC 에서 SMTP 로 띄워 1통 | "AWS 없이 돈다" 실증 |
| 3 | W5 리허설 | 시연 경로 확정(worker vs n8n) | 리허설 2회 통과한 쪽 |

## 이 문서의 한계

n8n 이 EC2 에 있는 한 AWS **장애**에는 같이 죽는다. 이 결정이 푸는 것은 **이식성**이다. 장애 대응은 백업·경보·자동 복구(07-deploy 모니터링 절)와 시연용 사전 녹화(발표 뼈대)가 맡는다.
