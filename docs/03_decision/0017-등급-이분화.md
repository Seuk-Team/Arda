# ADR-0017. 역할을 admin·member 2종으로 이분화 — A3(면접관 조회 제한) 폐지

- 상태: **확정** (2026-08-31) — 개정 협업 규칙에 따라 직접 반영, 사후 공지
- 작성: 백엔드 도메인
- 선행: [ADR-0013 면접관 배정 정책](0013-면접관-배정-정책.md) · [01-erd.md v1.3](../00_overview/01-erd.md) · [02-api.md](../00_overview/02-api.md)

## 맥락

역할이 `admin` > `recruiter` > `interviewer` 3종의 **위계**였고, 그 위에 A3 규칙이 얹혀 있었다:
"면접관은 본인이 배정된 지원자만 조회할 수 있다."

셋을 쓰다 보니 위계가 값을 못 했다.

- **A3 가 조회를 가리자 코드가 두 겹이 됐다.** 목록·검색은 쿼리를 좁히고(`scope_to_viewer`), 단건은 확인하고(`assert_can_view_application`) — 지원자에 딸린 것(상세·이력·평가·메모·파일·배정 현황·일정 제안)마다 둘 중 하나를 빠뜨리면 안 됐다. 새 엔드포인트를 추가할 때마다 "여기도 A3 가 필요한가"를 물어야 했고, `/schedules` 처럼 **역할로 결과를 강제로 좁히는** 분기까지 생겼다.
- **가린 실익이 없었다.** 이용자가 전원 내부 직원이라 지원서의 존재 자체를 감출 이유가 없다(그래서 404 가 아니라 403 이었다). 남은 효과는 "왜 안 보이냐"는 문의뿐이었다.
- **recruiter 와 interviewer 의 경계가 실제 일과 어긋났다.** 면접관도 공고를 보고 단계를 옮기고 메모를 남긴다. 경계를 지키려면 화면을 역할별로 갈라야 하는데, 그것은 우리가 하지 않기로 한 방향이다.
- **가용 시간에까지 번졌다.** 배정 대상이 `interviewer` 로 한정돼 있다는 이유로 가용 시간 등록도 `role=interviewer` 를 요구했다 — 담당자가 자기 면접 가능 시간을 넣을 수 없었다.

## 결정

역할을 **`admin` · `member` 2종**으로 줄인다. 위계가 아니라 **조작 권한의 유무**다.

1. **조회는 로그인만 하면 전부 허용한다.** A3 는 폐지한다 — `scope_to_viewer`·`assert_can_view_application` 을 삭제하고 호출부를 전부 걷어낸다. 로그인 자체는 그대로 필수다(토큰 없으면 401).
2. **admin 전용은 넷뿐이다.**
   - 면접관 배정/해제 ([ADR-0013](0013-면접관-배정-정책.md) 유지)
   - 계정 생성 (production 의 `signup`)
   - 메일 템플릿
   - **남의** 가용 시간 등록·삭제
3. **member 의 제한은 하나뿐이다** — 평가 **작성**은 자기에게 배정된 건만(`assert_can_evaluate`). 그 외 조작(공고 CRUD·단계 변경·일괄 변경·일정 제안·에이전트 채팅/요약)은 admin 과 동일하다.
4. **본인 가용 시간은 누구나 등록·삭제한다.** 배정 대상의 role 검사도 없앤다 — 누구나 면접관으로 배정될 수 있다.
5. 기존 `recruiter`·`interviewer` 행은 전부 `member` 로 접는다.

`interviewer_id` 컬럼명(`interviewer_assignments`·`interviewer_availability`·`schedule_slots`)은 **그대로 둔다.** 역할이 아니라 "그 건의 면접관"이라는 관계이고, 그 관계는 없어지지 않았다.

## 근거

- **막을 것이 줄면 빠뜨릴 것도 준다.** A3 는 규칙 하나가 열 곳에 흩어지는 형태였다. 남긴 제한은 전부 "한 엔드포인트, 한 검사"로 끝난다.
- **평가 작성만 배정에 묶은 이유**: 평가는 면접을 본 사람이 남기는 기록이다. 아무나 쓸 수 있으면 점수의 의미와 평균이 무너진다 — 이건 접근 통제가 아니라 데이터 정합성 문제라서 남긴다.
- **배정을 admin 에 남긴 이유**: ADR-0013 의 근거(편향 경고·이의신청·교체 판단이 전부 어드민을 전제한다)가 그대로 유효하다. 누가 누구를 보는지가 아니라 **누가 일을 맡는지**를 정하는 행위라서, 조회 개방과 충돌하지 않는다.
- **남의 가용 시간을 admin 에 남긴 이유**: 남의 일정을 대신 넣는 것은 조회가 아니라 그 사람 대신 약속을 만드는 일이다.
- **화면이 단순해진다.** 역할별 분기 없이 한 화면으로 간다 — 프론트는 `'admin' | 'member'`(관리자 / 멤버)만 안다.

## 감수하는 것

- **모든 로그인 사용자가 모든 지원자의 개인정보를 본다.** 이력서 다운로드까지 포함이다. 계정을 만들 수 있는 사람이 통제점이 되므로, **계정 생성이 admin 전용이라는 점이 이 결정의 유일한 방벽**이다(production 의 공개 가입은 계속 잠겨 있어야 한다).
- 감사(로그인 이력·조회 이력)는 지금 없다. 필요해지면 A5(`login_logs`)로 붙인다 — 접근을 다시 좁히는 쪽이 아니라 기록을 남기는 쪽으로 간다.
- 역할이 다시 세분화될 여지는 남는다. `require_roles(*allowed)` 는 인자를 받는 형태로 남겨 뒀다(현재는 `require_roles("admin")` 하나로만 쓰인다).

### ADR-0013 과의 관계

**배정 정책은 바뀌지 않는다.** 배정·교체·해제는 계속 admin 전용이다. 바뀐 것은 ADR-0013 의 전제 중 둘뿐이다.

- 배정 대상이 `role=interviewer` 인 사용자로 한정되지 않는다 → **누구나** 배정될 수 있다("면접관 등록"이 곧 계정 생성이 아니게 됐다).
- 배정이 **조회 권한을 부여하지 않는다** → 배정은 이제 "누가 이 면접을 맡는가"만 정한다. 배정이 여는 문은 평가 작성 하나뿐이다.
