# ADR-0010. 앱은 Flutter 확정

- 상태: **확정** (2026-08-26) · 확정자: bestcow — Flutter 채택. 실개발·시연은 **Android 전용**, iOS는 코드 호환만 유지
- 이력: 2026-08-25 Expo로 1차 확정 → **08/26 데모 범위에서 iOS를 제외하기로 하면서 Flutter로 재확정**

## 맥락

앱 트랙은 1인(minahdev)이 09/30까지 데모 가능한 상태로 만들어야 한다.
담당자는 모바일 개발 경험이 없다. 세 갈래가 가능했다.

- **Flutter**: Dart로 쓴다. 자체 렌더링 엔진이라 두 OS 화면이 동일하고, 위젯 카탈로그가
  넓어 서드파티 의존이 적다. 실기기에 올리려면 빌드해 설치해야 하고, **iOS는 Mac·Xcode가
  필요하다.**
- **Expo (React Native)**: JS/TS로 쓴다. 웹이 React 확정([ADR-0006](0006-프론트-react-확정.md))이라
  컴포넌트 사고방식이 넘어온다. Expo Go로 QR만 찍으면 빌드 없이 팀원 폰에서 돈다.
- **PWA**: 웹을 폰에서 열게 하는 것. "웹과 앱, 두 클라이언트"라는 트랙의 취지 자체를
  무효화하므로 검토에서 제외한다.

**학습 비용은 판단 기준으로 삼지 않았다.** AI 코딩 보조를 쓰면 새 언어의 문법 학습 비용은
예전만큼 크지 않다. Dart를 처음 본다는 것은 그 자체로 Flutter를 기각할 근거가 못 된다.

대신 기준은 **"팀 폰에서 돌아가는 데모를 09/30까지 만들 수 있는가"** 로 잡았다.

**08/25에는 이 기준이 Expo를 가리켰다.** 완료 기준이 "팀 전원 기기에서 실행 확인"이었고,
팀 기기가 **iOS 1대 · Android 4대**라 Flutter로는 그 1대를 올릴 수 없었기 때문이다.

**08/26에 팀이 데모 범위를 좁혔다** — iOS 1대를 시연 대상에서 빼고 Android로만 간다.
그러면 Expo를 골랐던 유일한 근거가 사라진다. 그 전제 위에서 Flutter로 확정한다.
**바뀐 것은 기술 비교가 아니라 데모 범위다.**

## 결정

Flutter(Dart)로 간다.

- **실개발·시연은 Android 전용이다.** 팀 Android 4대 + 에뮬레이터가 대상이다.
- **iOS는 "코드 호환"까지만 유지한다.** iOS를 지원하는 플러그인만 쓰고 Android 전용
  API·플랫폼 분기를 넣지 않는다. 다만 **Mac이 없어 `flutter build ios`를 실행할 수 없으므로
  "iOS에서 동작한다"는 검증되지 않는다. 이 문서는 그것을 주장하지 않는다.**
- 웹(React·TS)과의 언어·컴포넌트 재사용은 포기한다. 05-design 토큰은 CSS 값 →
  Dart `ThemeData`로 수동 이식한다.

## 결과

- 앱 코드는 `mobile/` 폴더에 둔다. `frontend/`와 분리한다.
- **완료 기준을 좁힌다** — [app.md](../01_role/app.md) §5 W2·W5의 "팀 전원 기기" →
  **"팀 Android 기기 전원"**. 범위 축소이므로 이 ADR의 팀장 승인으로 함께 확정한다
  ([03-conventions.md](../00_overview/03-conventions.md) 리뷰 절: 범위·마일스톤 변경은 팀장 합의).
- **iOS 1대 소유자는 시연 대상에서 빠진다.** 발표 시나리오에 iOS 기기가 들어가 있으면 뺀다.
- **iOS 호환 유지 규율 — 검증 가능한 것만 적는다.**
  - pub.dev에서 **iOS 지원이 표시된 패키지만** 쓴다
  - `Platform.isAndroid` 분기를 남기지 않는다
  - `flutter analyze` 무경고를 유지한다 — **Mac 없이 가능한 검증은 여기까지다**
- **발표·면접에서의 표현을 고정한다.**
  - ❌ "iOS도 됩니다" — 빌드해 본 적이 없어 방어가 불가능하다
  - ✅ "iOS 지원 플러그인만 써서 포팅 가능한 상태로 뒀고, 빌드 검증은 장비가 없어 못 했습니다"
- 정식 배포는 **Google Play만** 대상으로 한다 — 개발자 등록이 $25 1회로 끝난다.
  App Store는 연 $99 + Mac이라 이번 범위 밖이다. 배포 자체는 09/30 범위 밖(심사 리드타임)이고,
  여유가 있으면 Play 내부 테스트 트랙까지 밟아 본다.
- 색·간격·글꼴은 **05-design 토큰을 코드로 이식**한다. 임의 색을 만들지 않는다.
  웹이 이미 `frontend/app/src/tokens.css`로 한 번 옮겨 뒀으므로 그 값을 원본으로 삼는다.
- 모바일은 칸반을 쓰지 않는다 — 리스트 + 단계 변경 버튼 (기획 §2-3, 05-design §9).
- **M1(뼈대·정적 화면)은 API에 의존하지 않는다.** 백엔드가 늦어도 앱 트랙은 진행된다.

## 감수하는 것

Expo를 골랐던 근거가 그대로 리스크로 넘어온다. 숨기지 않고 적는다.

- **Flutter SDK 미설치 상태에서 시작한다.** Android SDK는 이미 있으나 Flutter·Dart는 없다.
  W2 첫 작업이 설치·`flutter doctor` 통과다.
- **팀에 Dart 사용자가 0명이다.** 앱은 1인 트랙이고 나머지는 React·Python을 쓴다.
  막히면 전부 혼자 푼다. AI 보조는 코드를 써주지만 "왜 내 기기에서만 안 뜨는가"를
  대신 겪어주지 않는다.
- **팀 배포는 매번 APK를 만들어 전달해야 한다.** 핫리로드는 되지만 Expo Go의 QR 즉시
  반영이 없다. 기기 실행 확인을 W2에 몰지 말고 주 1회로 정기화한다.
- **iOS 호환은 끝까지 미검증으로 남는다.** 완화되지 않는 항목이라 위 표현 규칙으로 관리한다.
