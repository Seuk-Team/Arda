# ADR-0031. AWS 를 EC2·S3 로 줄이고, 나머지는 self-host 로 교체 가능하게 둔다

> **상태: 초안 · 2026-09-08** · 작성 인프라·총괄(suvisdev). 백엔드(woojeongalex) 와 공동 — 큐·워커·메일 코드가 백엔드 도메인이다. 오너 개정으로 확정([03-conventions](../00_overview/03-conventions.md) "결정 문서 개정").
> 배경: 팀장 지시(2026-09-08) — "전체적으로 로컬 기반으로 내리고, AWS 는 EC2·S3 정도로 줄여서 이후에 AWS 가 끝났을 때 금방 변경해서 다시 서버를 돌릴 수 있게."
> 관련: [ADR-0024 §13 온프레미스 판](0024-sLLM-로컬-모델-전략.md) · [ADR-0030 알림·메일 자동화 n8n 분리](0030-n8n-알림-자동화-분리.md) · [ADR-0028 제출물 무결성 앵커](0028-제출물-무결성-앵커.md) · [role/infra 큐 12~15](../01_role/infra.md) · [07-deploy](../00_overview/07-deploy.md)

## 문제

지금 우리 운영은 AWS 서비스 **여덟 개**에 묶여 있다.

```
EC2(1대) · S3(2 버킷) · SES · SQS · CloudWatch · SNS · CloudFormation · IAM(다중 정책)
```

두 가지가 이 표면적을 좁힐 것을 요구한다.

**첫째, 예산·기한.** suvisdev 개인 결제이고 총 $400 · **2026-10-27** 까지다. 그 뒤 서비스를 이어 돌리려면 AWS 계정이 아예 없는 곳에서 돌아야 한다. 지금 형태로는 SES·SQS·CloudWatch·SNS 를 통째로 재작성해야 이전이 가능하다.

**둘째, 개인정보·로컬 우선.** [ADR-0024 §13](0024-sLLM-로컬-모델-전략.md) 이 이미 "AI 까지 오프라인은 GPU PC 온프레미스 판" 을 결정했고, [배포 전략](../../MEMORY.md) 은 "로컬 실행 1순위 — AWS 는 그 위에 얹는 구조" 다. 실제 로컬 배포에는 SES·SQS·CloudWatch 가 안 붙는다 — 이 대체품들이 필연적으로 필요하다.

지금 이 조각들이 **없어서** 못 옮기는 게 아니라, **바꿔 낄 자리**가 없어서 못 옮긴다. [ADR-0030](0030-n8n-알림-자동화-분리.md) 이 메일 계층에 처음으로 그 자리("`MAIL_DISPATCH=worker|n8n`" · SMTP 노드 교체)를 만들었다 — 이 결정은 그 원리를 큐·관측·경보로 확장한다.

## 결정

**1. AWS 표면적을 EC2·S3·IAM(S3 만) 세 개로 줄인다.** 나머지 다섯 서비스는 self-host 대안으로 교체 가능한 스위치를 만든 뒤 폐기한다. 완결된 스택 그림:

| 지금 | 대체 | 스위치 |
|---|---|---|
| SES | **n8n + SMTP 노드** (기본 시연 경로). 워커는 SMTP 20줄로 비상 폴백만 (SES 경로는 리허설 통과 뒤 삭제) | `MAIL_DISPATCH=n8n` (고정) + `MAIL_TRANSPORT=smtp` (고정) |
| SQS | Redis 컨테이너(RQ) 또는 Postgres LISTEN/NOTIFY | `QUEUE_BACKEND=sqs|redis|pg` (기본 `sqs` → 결정 후 전환) |
| CloudWatch | 자체 스크립트 로그 파일 (`~/metrics.log`) + `~/status.sh` | 폐기, `push-metrics.sh` 를 로그 파일 append 로 |
| SNS 이메일 경보 | SMTP 직접 발송 스크립트 | 관측 스크립트가 임계 넘으면 SMTP send |
| CloudFormation | (필요 없음) | 스택 삭제, YAML 파일도 저장소에서 제거 |
| IAM (arda-metrics-write · 앞으로 생길 SQS 정책) | (필요 없음) | 삭제, `arda-server` 는 S3 두 버킷 접근만 남긴다 |

**2. GPU 서버도 EC2 카테고리 안에서 처리한다.** g4dn.xlarge on/off (예산 [[project_aws_budget]]) 는 이 표면적을 늘리는 게 아니라 EC2 한 대가 잠깐 추가되는 것이다. `infra/gpu/` PR(다음 세션 첫 작업)의 `gpu-on.sh` / `gpu-off.sh` 는 처음부터 `GPU_TARGET=aws|local` 로 추상화해, AWS 종료 시 같은 스크립트가 로컬 GPU PC 를 켜고 끌 수 있게 한다.

**3. S3 는 유지하되 endpoint 는 이미 추상화돼 있다.** `backend/.env.example` 의 `S3_ENDPOINT_URL` 은 로컬 MinIO 교체용으로 이미 존재한다. AWS 종료 시 MinIO(compose 서비스 하나)로 스위치하고 버킷 이름·자격 증명만 갈아 끼우면 코드는 그대로. 이 결정은 이 스위치를 **문서에 명시**하고 로컬 실측 1회를 W5 안에 배치한다.

**4. AWS 종료 시 이전 대상은 이미 정해져 있다.** API·큐·메일·관측·GPU 전부 **compose 하나로 로컬 서버(또는 온프레미스 GPU PC)** 에서 돈다. S3 는 MinIO. 유일하게 밖에 남는 것은 **앵커 게시**([ADR-0028](0028-제출물-무결성-앵커.md)) 인데 개인키가 GitHub Actions Secret 에 있어 계정만 유지되면 그대로.

**5. 메일 시연 경로는 n8n + SMTP 하나로 좁힌다 (2026-09-08 결정).** [ADR-0030](0030-n8n-알림-자동화-분리.md) 이 마련한 그릇([PR #63](https://github.com/Seuk-Team/Arda/pull/63) 로 컨테이너·백업·경보까지 이미 붙음)을 그대로 활용. 워커는 SMTP 20줄로 최소 폴백만 (`MAIL_DISPATCH=worker` 로 급전환할 수 있게, 화면 편집 실수·n8n 컨테이너 장애 대비). **SES 경로는 리허설 통과 뒤 워커에서도 삭제.** 이 결정으로 발송 담당 하나·목적지 하나 → 실측 대상이 좁아진다.

**6. 지금 당장 폐기하지 않는다 — 순서.** SES·SQS·CloudWatch 는 이번 주 리허설까지 살아 있고, 그 위에 대체 경로를 실측으로 붙인 뒤 리허설 두 번 통과한 쪽만 남긴다. 시연은 검증된 쪽으로.

## 대안 — 채택하지 않은 것

| 대안 | 왜 아닌가 |
|---|---|
| 지금 그대로 두고 10/27 이후 재작성 | 예산 종료 시점에 서비스가 끊긴다. 대안 경로가 없어 리허설 불가 |
| 지금 다른 클라우드(GCP·Azure) 로 통째 이관 | 같은 벤더 종속을 반복. 예산·시간·학습 비용 큼. 시연 전 리스크 |
| Firebase·Supabase 같은 통합 BaaS | 개인정보(지원자 이메일·면접 기록)를 외부 SaaS 를 거치게 함. 팀 규칙([환경 설정 정책](../../CLAUDE.md))과 온프레미스 판 방향과 정반대 |
| AWS 전면 유지 + 로컬 판은 별도 분기 | 코드가 두 배로 갈라진다. 유지 비용 큼. "스위치 한 번" 원칙에서 벗어남 |
| n8n 하나로 큐·메일·관측 다 처리 | n8n 은 워크플로 엔진이지 관측 백엔드가 아니다. 관측 지표 축적·질의는 다른 도구 몫 — 이 결정은 관측을 파일+SMTP 로 단순화 |

## 결과 — 바뀌는 것

**인프라 (내 몫)**
- `infra/docker-compose.prod.yml` 에 **Redis 서비스**(포트 안쪽만, ~50MB) 추가 — 큐 대체 후보 1
- `infra/push-metrics.sh` 를 **로그 파일 append + SMTP 알림** 으로 재작성 — CloudWatch put-metric-data 제거
- `infra/cloudwatch-alarms.yml` **삭제** (CloudFormation 스택 폐기 후)
- `infra/server-status.sh` 에 큐 깊이(sqs 또는 redis) 표시 추가
- **비용 0** — Redis 는 t3.medium 4GB 안에 여유 있음(현재 여유 2.8Gi). 관측은 파일 시스템

**백엔드 (우정 몫)**
- `backend/app/worker.py` — 큐 백엔드 어댑터화 (`QUEUE_BACKEND=sqs|redis|pg`, 인터페이스는 send/receive/ack 3개)
- `backend/app/mail.py` — **SMTP 폴백 경로 20줄** (`smtplib`) 만 신설, SES 코드는 리허설 통과 뒤 삭제. 정상 흐름은 워커를 안 지나감 — n8n 이 렌더링 API 조회 → SMTP 노드 발송 → 결과 기록 API
- **내부 API 2개 신설 (ADR-0030 결정 2)** — `GET /internal/email-logs/{id}/render` (제목·본문·수신자 반환) · `POST /internal/email-logs/{id}/result` (provider_message_id 또는 실패 사유). 서비스 토큰 `ARDA_SERVICE_TOKEN` 으로 보호
- 큐 스위치 기본값은 지금 것(sqs)이라 이 결정만으로 큐 계층은 바뀌지 않는다. 메일 계층은 `MAIL_DISPATCH=n8n` 로 즉시 전환

**문서**
- [07-deploy](../00_overview/07-deploy.md) — "AWS 표면적" 절 신설, SES·SQS·CloudWatch 절에 "대체 경로" 부제 추가
- [role/infra](../01_role/infra.md) 큐 12~15 (온프레미스 판) 에 이 결정을 참조 링크
- `backend/.env.example` — 새 스위치 4개 (`MAIL_TRANSPORT`, `QUEUE_BACKEND`, SMTP 4종)

**AWS 콘솔 작업 (사용자 몫, 이전 완료 후)**
- SQS 큐 삭제 · CloudWatch 지표·알람 삭제 · SNS 토픽·구독 삭제 · CloudFormation 스택 `arda-alarms` 삭제 · IAM `arda-metrics-write` 정책 삭제

## 정하지 못한 것 — 오너가 채운다

> **1번은 오늘(09-08) 결정한다** (일정 단계 0). 나머지는 W4 안.

1. **SMTP 계정** — 오늘 결정. 세 후보, 시연 안정성·비용·이식성이 다르다.

    | 후보 | 발송 한도 | 비용 | 개인정보 경로 |
    |---|---|---|---|
    | 지메일 앱 비밀번호 | 500/일 (24h 롤링) | 0 | 지원자 이메일이 개인 지메일 계정을 지나감 |
    | 학원 도메인 메일 | 미확인 (학원에 확인 필요) | 0 | 학원 도메인 그대로 |
    | Mailgun/Brevo 무료 | Brevo 300/일 · Mailgun sandbox 인증 주소만 | 0 | 외부 SaaS 를 거침 |

2. **큐 대체 구현** — Redis(별도 컨테이너 +50MB, RQ/dramatiq 라이브러리) vs **Postgres LISTEN/NOTIFY**(추가 인프라 0, 우리가 이미 쓰는 DB). LISTEN/NOTIFY 가 최소이고 이식성 최고인데, 재시도·backoff·dead-letter 는 손으로 짜야 한다 — **우정님 판단**.

3. **관측 알림 형식** — SMTP 이메일(지금 SNS 와 같은 도착지) vs Discord `#alerts` 웹훅(이미 `#github` 웹훅 있음, 재사용) vs 둘 다. Discord 가 반응 속도 빠르고 이력 남지만 밤중 알림 놓치기 쉬움.

4. **GPU 종료 시 이전 대상** — 같은 로컬 서버(compose 안 gpu 프로파일)에 얹기 vs 별도 GPU PC(ADR-0024 §13 온프레미스 판). 로컬 서버가 GPU 를 갖췄으면 전자, 아니면 후자. 이건 W4 소연님 하네스 결과로 qwen 을 시연에 쓸지 여부가 정해진 뒤에 결정.

## 이 문서의 한계

- EC2 자체가 AWS 다. **AWS 계정을 완전히 떠나는 것은 이 결정의 범위가 아니다** — 온프레미스 판([ADR-0024 §13](0024-sLLM-로컬-모델-전략.md)) 이 그 몫을 맡는다. 이 결정은 그 이전에 "떠날 준비가 되어 있다" 를 보장하는 것.
- 큐·메일·관측 대체 경로가 **동일한 신뢰성** 을 준다는 실측은 W4 안에 나와야 한다. 못 나오면 시연은 지금 경로로.
- 앵커 게시([ADR-0028](0028-제출물-무결성-앵커.md)) 는 이 결정 범위 밖 — 이미 self-host(GitHub Actions + Sepolia RPC) 라 이관 대상 아님.
