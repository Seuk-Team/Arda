# ADR-0032. 추론 모델 3종 확정 — ViT · Whisper large-v3-turbo · Qwen3-8B

> **상태: 확정 · 2026-09-08** · 작성 에이전트 도메인(cloverky). 팀 결정(2026-09-08)을 문서로 옮긴 것이다.
> 개정 대상: [ADR-0024 sLLM 로컬 모델 전략](0024-sLLM-로컬-모델-전략.md) 2026-09-01 개정 §2 "8B는 탈락"
> 관련: [ADR-0029 표정·음성 진위 판별](0029-표정-음성-진위-판별-도입.md) · [ADR-0031 AWS 최소화](0031-aws-최소화.md) · [10-team-setup §7](../00_overview/10-team-setup.md)

## 문제

**"우리 모델을 쓴다"고 말하려면 실제로 켜져 있어야 한다.** 지금은 셋 다 그렇지 않다.

| 정한 모델 | 2026-09-08 현재 |
|---|---|
| Qwen3-8B | 코드는 있다 (`backends/ollama_backend.py` 기본값 `qwen3:8b`). **스위치가 꺼져 있다** — 실제로 도는 것은 `claude-haiku-4-5` |
| Whisper large-v3-turbo + faster-whisper | `agent/stt.py` 에 경로는 있으나 **`pyproject.toml` 에서 일부러 뺐다**(`[optional-dependencies] local`). 설치조차 되지 않는다. 모델도 `large-v3` |
| ViT (표정) | **코드가 없다.** 표정은 mediapipe 랜드마크 7개 + MLPClassifier 로 본다 |

그리고 ADR-0024 는 8B 를 **실측으로 탈락**시켜 놓았다. 문서와 팀 결정이 어긋난 채로 두면
[ADR-0029 가 정리했던 것과 같은 상태](0029-표정-음성-진위-판별-도입.md)가 반복된다.

## 결정

### 1. 모델 3종을 확정한다

| 역할 | 모델 | 라이선스 |
|---|---|---|
| 표정 | **ViT** (Vision Transformer, Google) — 얼굴 표정 분류로 파인튜닝된 가중치 | Apache 2.0 |
| 전사 | **Whisper large-v3-turbo** + **faster-whisper**(CTranslate2) | MIT |
| sLLM | **Qwen3-8B** (ollama `qwen3:8b`, Q4) | Apache 2.0 |

임베딩은 이미 로컬이다 — `jhgan/ko-sroberta-multitask`(768차원). 바꾸지 않는다.

### 2. 시연 서버는 g4dn.xlarge 한 대 — 넷이 같이 올라간다

| | VRAM |
|---|---|
| Qwen3-8B Q4 | ~5.2GB + KV 캐시 ~1GB |
| Whisper large-v3-turbo (fp16) | ~1.6GB |
| ViT-base 표정 | ~0.35GB |
| ko-sroberta 임베더 | ~0.5GB |
| **합** | **≈ 8.7GB / 16GB** |

**T4 16GB 에 7GB 남기고 들어간다.** 시스템 RAM 16GB · 4 vCPU 도 현재 t3.medium(4GB · 2 vCPU)보다 넉넉하다.

### 3. 학습은 로컬 PC, AWS GPU 는 시연 때만 돌린다

**둘을 섞지 않는다.**

| | 어디서 | 무엇을 |
|---|---|---|
| **학습** | 팀 PC (RTX 3050 8GB) | 모델을 만든다. 몇 시간 걸려도 비용 0 |
| **시연** | AWS g4dn.xlarge (T4 16GB) | 만들어 둔 모델을 **올려서 답만 낸다** |

학습된 모델은 파일 하나다(ViT 328MB · Qwen 은 ollama 가 받는다). 시연 서버는
그것을 읽어 추론만 하므로 위 2번의 VRAM 계산(≈8.7GB)이 그대로 성립한다.

**이미 그렇게 했다** — 표정 ViT 를 RTX 3050 8GB 에서 33분(5 에폭) 만에 학습해
FER2013 정확도 69.84% 를 얻었다([ai/expression-vit](../../ai/expression-vit/README.md)).
AWS 는 한 번도 쓰지 않았다.

**모델은 HuggingFace 에 있다** (2026-09-10):
[cloverky/arda-expression-vit](https://huggingface.co/cloverky/arda-expression-vit).
328MB 라 저장소에 못 넣는다 — 워커는 `VIT_MODEL=cloverky/arda-expression-vit`
한 줄로 받아 쓴다. 3차(FERPlus 라벨)까지 가서 **전체 74.91% · 표정 평균 재현율
77.90%** 다. 그 전까지 워커의 설정 예시는 **남의 모델**을 가리키고 있었다.

### 4. 그래서 GPU 비용은 시연 시간만큼이다

[10-team-setup §7](../00_overview/10-team-setup.md): AWS 예산 총 **$400 · 2026-10-27 까지**.
같은 문서의 "24시간 가동 = 월 ≈$470" 에서 역산하면 **시간당 ≈$0.65** 다.

| 쓰는 방식 | 비용 |
|---|---|
| 24시간 상시 | 월 ≈$470 → **불가능** |
| ~~8시간 × 20일~~ (학습까지 AWS 에서 한다고 봤을 때) | ≈$105 |
| **시연 + 리허설 10시간** | **≈$7** |

학습을 로컬로 내리면 GPU 서버는 **켜 두는 물건이 아니라 잠깐 켜는 물건**이 된다.
예산에서 차지하는 몫이 사실상 사라진다.

**대신 GPU 가 꺼져 있는 시간이 거의 전부다.** 그 동안에도 서비스는 돌아야 한다.

| 역할 | GPU 켜짐 | GPU 꺼짐 (기본값) |
|---|---|---|
| 채팅·요약·꼬리질문 | `qwen3:8b` | `claude-haiku-4-5` |
| 전사 | faster-whisper large-v3-turbo (비용 0) | OpenAI `whisper-1` (분당 $0.006) |
| 표정 | ViT + mediapipe | mediapipe 만 |

역할별 스위치는 [ADR-0024 §10](0024-sLLM-로컬-모델-전략.md) 이 이미 만들어 둔 구조다. 새로 만들지 않는다.

**자동 폴백은 넣지 않는다.** ADR-0024 §10 이 정한 그대로다 — 담당자가 자기 질문이 언제
외부로 나갔는지 모르게 되면 "데이터 반출 없음"이 깨진다.

### 5. ADR-0024 의 "8B 탈락"을 개정한다 — 조건이 다르다

ADR-0024 2026-09-01 개정 §2 는 다음을 실측하고 8B 를 접었다.

| 질의 | `claude-haiku-4-5` | `qwen3:4b` | `qwen3:8b` |
|---|---|---|---|
| 출력 tok/s | 106 | 45 | **7.4** |

**그 측정은 RTX 3050 8GB 에서 나왔다.** 8B Q4 는 가중치만 ~5.2GB 라 8GB 카드에서는
KV 캐시와 컨텍스트가 들어갈 자리가 남지 않는다. **7.4 tok/s 는 모델이 느린 것이 아니라
레이어 일부가 CPU 로 흘러넘친 값**으로 보인다 — 4B 의 1/6 이라는 낙차가 그 신호다.

T4 16GB 에서는 전부 VRAM 에 올라가고 메모리 대역폭도 더 넓다(320 GB/s). 그래서 **8B 를
되살린다.** 다만 **이것은 추정이고 아직 실측하지 않았다** — 「정하지 못한 것」① 이다.

### 6. 채팅부터 넘기지 않는다 — 요약·꼬리질문이 먼저다

ADR-0024 §3 이 찾은 병목은 **출력 길이**였고 그것은 장비를 바꿔도 그대로다.
같은 질의에서 `qwen3:4b` 가 3,248 토큰을 쓰는 동안 haiku 는 1,450 토큰을 썼다.

8B 가 T4 에서 40 tok/s 를 낸다 해도 3,248 토큰은 **81초**다. 담당자가 기다릴 수 없다.

| 순서 | 역할 | 왜 |
|---|---|---|
| 1 | **요약** (`AGENT_SUMMARY_BACKEND`) | 접수 때 1회, 비동기. 지연이 화면에 안 보이고 개인정보가 가장 많다 |
| 2 | **꼬리 질문** (같은 스위치) | 면접 전 미리 만든다. 역시 비동기 |
| 3 | 채팅 (`AGENT_CHAT_BACKEND`) | **출력 길이를 잡은 뒤에.** 시연에서만 켠다 |

### 7. ViT 는 판정기가 아니라 재료다

`trpakov/vit-face-expression`(ViT-base, 표정 7종)을 법정 영상에 돌린 결과다.

| 영상 | 상위 표정 |
|---|---|
| `trial_lie_001` (거짓) | happy 55% · sad 31% |
| `trial_lie_020` (거짓) | happy 64% · fear 26% |
| `trial_truth_002` (진실) | **fear 71%** · angry 15% |
| `trial_truth_015` (진실) | sad 40% · happy 26% |

**표정만으로는 갈리지 않는다.** 거짓인데 happy 고 진실인데 fear 다. 그러므로 ViT 출력은
**진위 판정이 아니라 특징 벡터의 일부**로 들어간다 — 지금의 mediapipe 7개 옆에 표정 7개가 붙는다.

**발표에서 "ViT 로 거짓말을 잡는다"고 말하지 않는다.** 위 표가 그 문장을 반증한다.

## 근거 — 실측 (2026-09-08, CPU)

측정 기계는 개발 PC(CPU) 다. GPU 수치가 아니다.

| 모델 | 로딩 | 속도 | 메모리 |
|---|---|---|---|
| Whisper large-v3-turbo (int8) | 48초 | **1.8배속** (35.6초 음성 → 19.5초) | ~1.0GB |
| ViT 표정 | 1.4초 | **130ms/장** | ~0.9GB (torch 포함) |

전사 품질은 실제로 확인했다 — 법정 영상에서 문장이 온전히 나왔다.

**이 숫자가 곧 "GPU 가 필요한 이유"다.** 백엔드 API 는 t3.micro(1GiB), 거짓말 탐지는
백엔드와 같은 t3.medium(4GB, [PR #42](https://github.com/Seuk-Team/Arda/pull/42))에 있다.
Whisper 하나가 1GB 를 쓰므로 **어느 쪽에도 들어가지 않는다.**

## 정하지 못한 것

① **T4 에서 8B 가 실제로 몇 tok/s 인가.** 위 5번은 추정이다. 7.4 tok/s 가 VRAM 부족
때문이었다는 가설이 틀렸다면 8B 는 다시 탈락하고 `qwen3:4b` 로 내려가야 한다.
**GPU 서버를 받는 즉시 ADR-0024 와 같은 질의로 재측정한다.**

② **ViT 를 어느 서비스에 넣는가.** 거짓말 탐지 이미지에 torch 를 넣으면 이미지가 ~2.5GB
커지는데, t3.medium 에서는 어차피 못 켠다. 같은 서비스에 스위치로 둘지, GPU 전용 서비스로
뺄지 정하지 않았다.

③ **ViT 표정 7개를 더한 모델을 다시 학습해야 한다.** 지금 `model.pkl` 은 100차원으로
학습돼 있어 열이 늘면 그대로는 못 쓴다. 표본은 여전히 121개고, 이는
[ADR-0029 「정하지 못한 것」①](0029-표정-음성-진위-판별-도입.md)(정확도를 무엇으로 검증하나)과 같은 자리다.

④ **G 인스턴스 쿼터.** 10-team-setup 은 "쿼터 승인 후"라고만 적고 있고 신청 기록이 없다.
신규 계정은 G 계열 vCPU 쿼터가 0 인 경우가 많고 g4dn.xlarge 하나가 vCPU 4개를 쓴다.
**승인에 수 시간~며칠이 걸리므로 시연 일정의 위험이다** — 인프라·총괄(suvisdev) 소관.
