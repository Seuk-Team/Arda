# ADR-0016. 면접 일정 자동화 — 토큰 공개 페이지 + 기존 메일 파이프라인 재사용

> **상태: 확정 · 2026-08-31** (개정 협업 규칙에 따라 직접 반영, 사후 공지) · 구현 착수
> 관련: [ADR-0013 면접관 배정 정책](0013-면접관-배정-정책.md) · [01-erd.md v1.2](../00_overview/01-erd.md) · [02-api.md 면접 일정 절](../00_overview/02-api.md)

## 문제

면접 일정 조율이 시스템 밖에 있다. 담당자가 면접관들의 가능 시간을 물어보고, 지원자와 메일을 수 회 왕복해 시간을 맞춘다. 지원자는 자기 전형이 어디까지 왔는지, 면접이 언제인지 확인할 창구가 없다(안내 메일이 전부).

## 결정

일정 조율을 시스템 안으로 들여온다. 흐름:

1. **면접관이 가용 시간을 등록**한다 (`interviewer_availability`)
2. **담당자가 제안을 생성**한다 — 배정된 면접관(E3)의 가용 시간에서 후보 슬롯 N개를 만들어 지원자에게 메일 발송 (`schedule_proposals` + `schedule_slots`)
3. **지원자가 공개 링크로 접속**해 후보 중 하나를 선택한다 — 로그인 없음, `public_token`(B6)과 같은 토큰 접근 패턴. 같은 페이지에서 자기 전형 현황도 본다
4. **선택 즉시 확정** — 담당자·면접관·지원자에게 확정 통보. 메일은 기존 `email_logs` + SQS + 워커(G2) 재사용

지원자 페이지는 24시간 열려 있고, 확정·변경·만료 판정은 스케줄러 없이 **조회 시점 판정**(B4 마감과 같은 방식)으로 한다.

## 원칙 유지

- **제안 생성은 사람(담당자)의 명시적 액션**이다. 시스템은 교집합 계산과 왕복 제거만 한다 — "핵심 결정은 사람" 원칙(ADR-0003 계열) 그대로.
- 지원자의 슬롯 선택은 지원자 본인의 결정이므로 즉시 확정이 맞다.

## 범위에서 뺀 것

- **챗봇 질의응답(24시간 문의 응대)** — RAG 여유 항목([agent.md](../01_role/agent.md))과 겹친다. 일정 조율만으로 스키마+백엔드+프론트 3층이라, 챗봇은 에이전트 트랙에서 별도 판단.
- 외부 캘린더 연동(Google Calendar 등) · 자동 리마인더 · 반복 가용 규칙 — 여유 시.
- 면접관 다대일 슬롯(패널 면접) — 슬롯당 면접관 1명으로 시작. 필요하면 slots에 행 추가로 확장 가능.

## 근거

- **신규 층이 한 층뿐이다.** 토큰 공개 접근(B6)·메일 큐(G2)·면접관 배정(E3)·조회 시점 판정(B4)이 전부 이미 있다. 새로 만드는 것은 테이블 3개와 그 위의 API·페이지다.
- 발표 소재: "수 회 메일 왕복 → 링크 1회"의 정량 서사 + 기존 인프라 재사용 설계.

## 리스크

- **09/04 게이트 주간과 병행** — 게이트 임계경로(공개 지원 폼·재배포)와 파일이 겹치지 않는 것을 확인하고 시작한다. `App.tsx` 라우트만 공유하므로 지원 폼 머지 후 얹는다.
- ERD 변경이라 `models.py` 반영 시 **로컬 DB 리셋 전파 필요** — 반영 커밋에 공지를 같이 낸다. 신규 테이블만 추가라 기존 데이터 파괴는 없다(create_all이 신규만 생성).
