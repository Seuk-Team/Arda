# ADR-0034. 에이전트 자동 심사 — 서류·면접은 아르가 판정하고, 최종 합불만 사람이

> **상태: 확정 · 2026-09-10** · 작성 인프라·총괄(suvisdev, 팀장 결정). 개정 경로: 오너가 개정 ADR 을 쓰면 바뀐다([03-conventions](../00_overview/03-conventions.md) "결정 문서 개정").
> **개정 대상**: [ADR-0003 AI 는 추천까지](0003-ai-추천만.md) — "확정은 사람" 의 범위를 **최종 합격·불합격 한 곳**으로 좁힌다. [ADR-0029 표정·음성 진위 판별](0029-표정-음성-진위-판별-도입.md) 결정 2 "결과를 저장하지 않는다" — 면접 점수 재료로 **집계값만** 저장한다. [ADR-0013·0016 면접관 배정·일정](0016-면접-일정-자동화.md) — 배정이 자동이 된다.
> **유지**: [ADR-0027 인적성](0027-인적성-검사.md) 요약만·판정 없음(점수에 넣지 않는다). [ADR-0017 등급 이분화](0017-등급-이분화.md). 지시서: [N1 자동 심사 파이프라인](../02_tasks/N1-자동심사-파이프라인.md).

## 문제

지금 시스템은 "아르가 추천하고 사람이 카드를 옮긴다" 다. 서류 요약에 1~5점 적합도가 붙지만 단계는 사람이 바꾸고, 면접 점수는 면접관이 손으로 넣는다. 팀장이 2026-09-10 멘토링 뒤 정한 방향은 다르다.

> 지원 → 아르가 서류 점수화·합불 판정 → 서류 합격자만 면접(인적성 발송) → 면접관 자동 배정 → 면접도 아르가 점수화(답변 대조 + 표정·음성 진위) → 서류+면접 가중 합계로 분류 → **최종 합격·불합격만 사람이** 판단. 수동 변경은 언제나 가능.

즉 "확정은 사람" 이 한 자리로 옮겨 간다. 나머지 자리는 아르가 판정하고, 사람은 되돌릴 수 있다.

## 결정

### 1. 서류 심사 — 아르가 100점을 매기고 단계를 옮긴다

- 접수 시 요약 3단계 체인의 2단계가 **100점 만점 점수**를 낸다. 세 재료를 따로 채점한다: 필수 요건(`job_postings.requirements` + `description`) · 우대(`preferred`) · 인재상(`company_profile.talent_profile`). 각 0~100, 회사 가중치(기본 50·20·30)로 합산 → `applications.doc_score`. 내역·근거는 `doc_score_detail` JSON.
- 공고별 **임계(`job_postings.pass_threshold`, 기본 60)** 이상이면 `applied → screening → interview` 로 자동 이동, 미만이면 `applied → rejected`. 이력(`stage_history`)에 `changed_by=NULL`(시스템) + 사유 "아르 서류 심사 N점 (기준 M점)" 을 남긴다. `applications.doc_decision`(pass/reject/hold) · `decision_source`(agent/human).
- **불합격 메일은 즉시 보내지 않는다.** 공고 마감 뒤 담당자가 `POST /postings/{id}/send-rejections` 로 일괄 발송한다(팀장 결정: 마감 전 번복 여지). 합격(면접 단계) 메일은 일정 제안 메일이 대신한다.
- `screening_mode='manual'` 인 공고는 점수만 매기고 옮기지 않는다(`hold`). 자동을 끄는 스위치다.
- 사람이 단계를 바꾸면 `decision_source='human'` 이 되고, 그 지원자는 이후 자동 판정에서 빠진다. **수동이 항상 이긴다.**

### 2. 서류 합격 뒤 자동으로 붙는 것

- 인적성 설문 세션 생성 + 링크 메일(기존 `aptitude` 경로 재사용, 발신 주체 `agent`). 점수에는 넣지 않는다(ADR-0027 유지) — 최종 판단 전 참고 요약.
- 면접관 자동 배정: 공고에 등록된 **기본 면접관 풀**(`posting_interviewers`)에서 앞으로의 가용 시간이 있는 사람 중 **배정 건수가 가장 적은 사람 1명**. 그 뒤 일정 제안(ADR-0016)을 자동 생성해 지원자에게 후보 시간을 보낸다. 풀이 비거나 가용 시간이 없으면 면접 단계 안내 메일만 보내고 `doc_score_detail.needs_manual_assignment=true` 로 남긴다. 수동 배정·변경은 여전히 admin(ADR-0013).

### 3. 면접 심사 — 아르가 100점

- 면접 종료(`finish`) 시 백그라운드로 채점: **답변 요건 대조**(전사 텍스트 ↔ 공고 요건·우대·인재상, LLM, 0~100) 와 **진위 일관성**(실시간 판정 `truth_pct` 의 세션 평균, 0~100) 을 회사 가중치(기본 70·30)로 합산 → `interview_sessions.ai_score`, 내역 `ai_score_detail`.
- 이를 위해 `push_verdict` 가 세션에 **집계값만**(표본 수·합계) 쌓는다. 프레임·영상·개별 판정은 저장하지 않는다(ADR-0029 의 취지 유지, 결정 2 만 개정). 진위 표본이 없으면 답변 점수만으로 100 환산.
- 면접관은 점수를 넣지 않고 **코멘트만** 남긴다(`evaluations.score` 는 참고값으로 남되 합계에 안 들어간다).
- **위험을 사실로 남긴다.** 표정·음성 진위는 법정 영상 121개로 학습한 분류기라 "판정" 이 아니라 일관성 신호다. 점수의 30% 상한, 화면 문구는 "진실 쪽에 가까움" 유지. 법·공정성 검토는 발표 전 별건.

### 4. 최종 분류 — 사람이 본다

- `final_score = doc_score × w_doc + interview_ai_score × w_interview`(기본 50·50, `company_profile.scoring_weights`). 등급 S(85↑)·A(70↑)·B(55↑)·C.
- 최종 합격(`accepted`)·불합격(면접 뒤) 은 **사람이** 카드를 옮긴다. 아르는 `interview` 단계에서 멈춘다.

### 5. 학습

- 1차: 프롬프트 주입(요건·우대·인재상·회사 소개) — 이 ADR 의 구현.
- 2차: 담당자가 점수를 정정하면 그 차이를 `agent_traces` 계열로 모아 Qwen3-8B QLoRA 학습(ADR-0032). 팀장 지시로 목표에 넣되 데이터가 쌓인 뒤.

## 대안과 버린 이유

- **점수만 매기고 사람이 일괄 확정** — ADR-0003 을 지키는 가장 싼 길. 팀장이 "기본은 에이전트가 전부 판단" 으로 결정해 버렸다.
- **합격·탈락 메일까지 즉시 자동** — 오판 시 메일은 되돌릴 수 없다. 불합격 메일만 마감 후 일괄로 미룬다.
- **면접관 점수 가중 포함** — 면접관은 코멘트만 하기로 팀장 결정.

## 되돌리기

`screening_mode='manual'` 을 기본값으로 바꾸면 자동 이동이 멈추고 점수만 남는다. 컬럼은 그대로 두어도 해가 없다.
