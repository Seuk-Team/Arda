# ADR-0007. 작업 분배를 도메인 오너제로 전환

- 상태: 확정 (2026-08-24)

## 맥락

지금까지는 [04-team.md](../00_overview/04-team.md) 원칙대로 사람별 고정 배정 없이 **팀장이 작업 풀에서 꺼내 지시서로 발행하고, 전 PR을 팀장이 리뷰**했다. 1주차 실측으로 이 구조의 한계가 드러났다.

- W1 배포 45분 만에 목업 3장이 올라왔고, 한 명은 한 주치 배정을 한 시간에 끝냈다 ([W1-2](../00_overview/06-weekly.md) §1). **프로젝트 속도를 코딩이 아니라 팀장의 지시서 생산·리뷰 속도가 결정한다** (W1-2 §5).
- 전부 팀장이 지시하고 전부 팀장이 검수하면 분업의 의미가 없다 — 팀원은 실행자에 머물고, 각자 면접에서 "내 파트"라 말할 소유권이 생기지 않는다.

## 결정

**사람마다 도메인 하나를 소유한다.** 오너는 자기 도메인의 로드맵(`docs/01_role/<도메인>.md`)을 기준으로 스스로 작업을 쪼개고, 지시서 작성 여부도 스스로 판단한다.

| 도메인 | 오너 | 폴더 |
|---|---|---|
| 인프라·총괄 | bestcow | `infra/` `.github/` `docker-compose.yml` AWS |
| 프론트엔드 | cloverky | `frontend/` |
| 에이전트 | suvisdev | `backend/app/agent/` `backend/app/api/agent.py` |
| 앱 | minahdev | `mobile/` |
| 백엔드 | woojeongalex | `backend/` (agent 제외) |

**리뷰를 위임한다.** 도메인 내부 PR은 오너 책임으로 머지하고(검증 결과 필수, CI 생기면 CI 통과 필수), **팀장 승인은 인터페이스(스키마·02-api·공용 문서·타 도메인 파일)로 좁힌다.** 세부 규칙은 [03-conventions.md](../00_overview/03-conventions.md).

**팀장 전담을 축소한다.** 프론트 뼈대·칸반은 프론트 오너에게, 인증(A1~A3)·단계 전환 로직(D3)은 백엔드 오너에게 이관한다. 팀장에게 남는 것: 스키마·아키텍처 결정, 인터페이스 리뷰, 통합, AWS·배포.

**전환 시점**: 현재 진행 중인 작업(J0·E1·A2·QA 등)이 머지되는 대로. 미착수 큐의 재배정은 [W1-3](../00_overview/06-weekly.md).

## 감수하는 것

- 도메인 내부 품질은 오너 역량에 좌우된다 — CI(J4)와 QA 시나리오가 안전망이고, 이 안전망 구축(인프라 M3)의 우선순위가 그만큼 올라간다.
- 도메인 간 편차가 생길 수 있다 — 컨벤션·에러 표준(J5·J6)을 백엔드 M3에 유지한다.

## 결과

- 팀장 병목 제거: 지시서·리뷰가 임계경로에서 빠진다.
- 각자 면접 스토리가 도메인 단위로 생긴다 (각 로드맵 "면접 스토리" 절).
- [04-team.md](../00_overview/04-team.md) 전면 개편, [03-conventions.md](../00_overview/03-conventions.md) 리뷰 절 교체, CODEOWNERS 도메인별 갱신.
