## 맥락

프로젝트의 외부 서비스가 전부 **팀장 개인 계정에 묶여 있었다** — AWS(루트·IAM 유저 하나), GitHub org 오너 1명, Vercel 프로젝트, 도메인 `seuk.cloud`, Anthropic·OpenAI 키, Discord 서버. 서버 `.env` 의 AWS 키까지 팀장 개인 IAM 유저 키였다. 팀장이 빠지는 순간 배포·메일·업로드가 멈추고, 아무도 고칠 수 없는 구조다.

## 결정

1. **권한은 사람이 아니라 역할에 붙인다.** 운영 콘솔은 인수자의 IAM 유저, 서버가 쓰는 키는 서버 전용 IAM 유저. 개인 키는 어디에도 남기지 않는다.
2. **AWS 계정 자체는 팀장 명의로 유지한다.** 학원 크레딧($400)이 계정에 묶여 있어 옮길 수 없다. 대신 (a) Budgets 알림을 걸고 (b) 프로젝트 종료 시 리소스를 전부 지운 뒤 계정을 해지한다. 해지 전 DB 덤프·S3 객체를 팀에 넘긴다. 상세 근거는 이 결정의 대안 절.
3. **인수자는 woojeongalex.** 백엔드 오너이자 서버 작업(재배포·DB 이행)을 이미 문서 기준으로 수행할 수 있는 유일한 사람이다. 인프라 도메인 폴더(`infra/` · `.github/` · `docker-compose.yml`)의 오너십도 함께 넘긴다 — [04-team.md](../00_overview/04-team.md) 표 갱신.
4. **시크릿은 인수자가 재발급한다.** 팀장이 만든 값(JWT_SECRET · DB_PASSWORD · Anthropic·OpenAI 키)은 인수자가 자기 계정에서 새로 발급해 서버 `.env` 를 교체한다. 팀장 것은 그 뒤 폐기.

## 대안 — AWS 계정을 통째로 넘기지 않는 이유

- **루트 이메일·결제 수단만 교체**: 빠르지만 계정 이력·본인 확인이 팀장 이름으로 남고 크레딧 약관상 양도가 아니다.
- **인수자 계정에 재구축**: DB 덤프 + S3 sync + EIP 이전으로 가능하고 스택이 작아 반나절이면 된다. 그러나 **SES 가 다시 샌드박스**라 도메인 재검증·해제 신청을 처음부터 해야 하고(08/27 한 번 거절된 전력), 크레딧을 버린다.
- 그래서 **계정은 두고 권한만 넘긴다.** 데모 기간이 짧고 크레딧이 비용을 덮는 동안은 이 편이 싸다. 종료 시점에 재구축이 필요해지면 위 두 번째 안의 절차를 그대로 쓴다.

## 결과

- 팀장 개인 키가 서버에서 사라졌다. 키 유출 시 재발급 범위가 `arda-server` 하나로 좁다.
- 남은 항목 5~11 은 대부분 콘솔·대시보드 조작이라 Claude 가 대신 못 한다(보안 설정 변경은 자동 모드에서 차단). 명령·경로는 위 표에 적어 두었다.
