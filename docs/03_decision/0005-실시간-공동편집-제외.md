# ADR-0005. 실시간 공동 편집 제외 — 메모는 행 추가 방식

- 상태: 확정 (2026-08-22)

## 맥락

담당자·면접관이 같은 지원자에 대해 서술형 메모를 남긴다. 이때 노션·구글독스처럼 **하나의 문서를 여럿이 동시에 편집**하고 싶다는 요구가 있었다. 그러나:

- 실시간 동시 편집은 [00-overview.md](../00_overview/00-overview.md)에서 이미 "한 달에 불가"로 제외한 항목이다.
- 공동 편집의 충돌 해소(CRDT·OT)는 **한 레코드를 두 사람이 동시에 고칠 때만** 필요한 기술이다.
- 메모를 `application_notes`처럼 **각자 자기 행을 추가하는 목록**으로 두면 두 사람의 편집 범위가 애초에 겹치지 않는다. 남는 충돌은 "본인이 자기 메모를 두 탭에서 동시 수정" 정도뿐이다.

## 결정

CRDT·OT 기반 실시간 공동 편집을 구현하지 않는다. 메모는 행 추가(append) 목록으로 만든다.

대신 하는 것:

- 상세 패널을 열어둔 사이 남이 메모를 추가하면 표시(폴링 또는 SSE) — 여유 시
- 메모 수정 시 `updated_at` 비교로 덮어쓰기를 감지해 경고(낙관적 잠금)

## 나중에 열 조건

한 문서를 여러 명이 **동시에 고쳐야 하는** 요구가 실제로 생겼을 때(예: 공고 본문 공동 작성, 평가표 합의 작성). 그 전까지는 행 추가 구조로 충분하다.

## 결과

발표 멘트: "동시 편집 충돌을 푸는 대신, 충돌이 생길 수 없는 데이터 구조를 택했다."
