# ADR-0024. sLLM 로컬 모델 전략 — 하이브리드 구성

> **상태: 검토 중 · 2026-08-31** · 모델 선정은 W3 착수 시 GPU 사양 확인 후 확정
>
> **2026-09-01 실측이 아래 [개정 절](#2026-09-01-개정--실측으로-드러난-것)에 붙었다.** 원문의 GPU 전제(RTX 3060 12GB 이상)가 실제 장비(RTX 3050 8GB)와 달라 결론이 바뀐다.
> 관련: [ADR-0011 에이전트 모델 비용](0011-에이전트-모델-비용.md) · [ADR-0021 RAG 시맨틱 검색](0021-RAG-시맨틱-검색.md) · [ADR-0022 프롬프트 체이닝](0022-프롬프트-체이닝.md)

## 문제

현재 에이전트의 AI 호출은 전부 외부 API(Claude, OpenAI Whisper)를 거친다. 채용 데이터는 지원자 개인정보(이름, 연락처, 학력, 경력, 자기소개서)를 포함하며 기업의 가장 민감한 자산 중 하나다. 소주제 2번에서 "데이터 반출 없는 채용 에이전트"를 요구하고 있고, 소주제 4번에서 "STT → RAG → sLLM" 파이프라인을 명시했다.

## 결정

민감 작업은 로컬 sLLM으로, 일반 작업은 API로 나누는 **하이브리드 구성**을 채택한다. 모델은 전부 오픈소스/무료이며, Ollama로 로컬 구동한다. 최종 모델 선정은 서버 GPU 사양 확인 후 확정한다.

## 용도별 모델 후보

### 1. 대화 + 도구 호출 (에이전트 코어)

현재 Claude API가 담당. sLLM 전환 시 후보:

| 모델 | 크기 | VRAM | 한국어 | tool_use | 비고 |
|------|------|------|--------|----------|------|
| Llama 3.1 8B | 8B | ~6GB | 양호 | 지원 | 범용 성능 최상, 커뮤니티 최대 |
| EXAONE 3.5 7.8B | 7.8B | ~6GB | 최상 | 제한적 | LG, 한국어 특화 |
| Gemma 2 9B | 9B | ~7GB | 양호 | 미지원 | Google, 추론 능력 우수 |

**하이브리드 옵션**: GPU 부족 시 Claude API 유지 + 민감 데이터만 마스킹 처리

### 2. 면접 요약 + 분석 (STT 후처리)

소주제 4번 "RAG → sLLM" 파이프라인의 sLLM 부분:

| 모델 | 크기 | VRAM | 특징 |
|------|------|------|------|
| Qwen 2.5 7B | 7B | ~5GB | 128K 컨텍스트, 면접 전사본 전체 입력 가능 |
| Phi-4 Mini 3.8B | 3.8B | ~3GB | 초경량, CPU에서도 동작, 한국어 보통 |

### 3. 임베딩 (RAG 검색용)

| 모델 | 차원 | 한국어 | 실행 환경 |
|------|------|--------|-----------|
| ko-sroberta-multitask | 768 | 전용 | CPU OK (~50ms/건) |
| BGE-M3 | 1024 | 100+언어 | CPU OK (~80ms/건) |

### 4. STT (음성 전사)

| 모델 | VRAM | 특징 |
|------|------|------|
| Whisper large-v3 (로컬) | ~4GB | 현재 API → 로컬 전환. 오픈소스, 무료 |
| faster-whisper | ~2GB | CTranslate2 최적화, 4배 빠름, 동일 품질 |

## 실행 환경별 구성

모델을 동시에 전부 올리지 않는다. Ollama가 미사용 모델을 자동 언로드하며, 실사용 시 6~8GB면 충분하다.

### GPU 있는 경우 (RTX 3060 12GB 이상)

```
[채팅] Llama 8B 로컬 → 도구 호출 → DB
[접수] ko-sroberta 임베딩 (CPU) → pgvector
[면접] faster-whisper 로컬 → RAG 검색 → Qwen 7B 요약
```

전구간 로컬 — 외부 API 호출 0, 운영 비용 0원

### GPU 없거나 약한 경우

```
[채팅] Claude API 유지 (하이브리드) → 도구 호출 → DB
[접수] ko-sroberta 임베딩 (CPU) → pgvector
[면접] faster-whisper CPU → RAG 검색 → Claude API 요약
```

임베딩과 STT는 CPU로 동작, 추론만 API 사용

## 2026-09-01 개정 — 실측으로 드러난 것

> 원문은 고치지 않았다. 원문은 **장비를 보기 전에** 쓴 것이고, 그 전제가 틀렸다는 것이 이 절의 내용이다.
> 근거: 브랜치 `worktree-agent-a867fab28aeed20e1` (어댑터 프로토타입) · RTX 3050 8GB · 실제 DB 지원자 500건 · 실제 도구 실행.

### 1. GPU 전제가 틀렸다

원문은 "RTX 3060 12GB 이상"을 GPU 있는 경우로 잡았다. **실제 장비는 RTX 3050 8GB**다. 메모리 대역폭이 3060 Ti의 절반 수준이라 원문의 "GPU 있는 경우 = 전구간 로컬" 구성은 그대로 성립하지 않는다.

### 2. 속도 실측 — 같은 질의, 같은 DB, 같은 도구

| 질의 | `claude-haiku-4-5` | `qwen3:4b` | `qwen3:8b` |
|---|---|---|---|
| 읽기 도구 1개 ("면접 단계 지원자 보여줘") | **13.6초** | 73.2초 | 107.5초 |
| 쓰기(확인 카드까지) | **2.9초** | 32.6초 | 31.0초 |
| 도구 연쇄 시도 | **6.6초** | 86.8초 | 130.5초 |
| 출력 tok/s | 106 | 45 | 7.4 |

- **8B는 탈락.** VRAM 8GB에 올라가긴 하지만 tok/s가 4B의 1/6이다. 원문 후보표의 8B급(Llama 3.1 8B · EXAONE 7.8B · Gemma 2 9B)은 이 장비에서 같은 벽에 부딪힌다.
- **4B도 지금 구조로는 대화형에 못 쓴다.** 담당자가 33~87초를 기다린다.

### 3. 병목은 프롬프트가 아니라 출력 길이였다

전환 논의는 "고정 프리픽스 17KB가 무겁다"에서 출발했는데, 실측은 다른 곳을 가리킨다. 같은 질의에서 **`qwen3:4b`가 3,248 출력 토큰을 쓰는 동안 haiku는 1,450 토큰**을 썼다. 지원자 10명을 이메일·경력·기술까지 전부 나열하기 때문이다. 45 tok/s에서 3천 토큰은 그 자체로 70초다.

사고 모드(`<think>`)를 의심해 껐지만 출력은 3,444 → 3,248로 거의 그대로였다 — **원인이 아니다.** 토글은 `OLLAMA_THINK`로 남겨 뒀다.

즉 프롬프트를 줄이는 것보다 **응답을 짧게 만드는 것**(도구 결과 필드 축소 · 나열 상한 · 출력 형식 고정)이 먼저다.

### 4. 어댑터 동작은 정상

`AGENT_CHAT_BACKEND` / `AGENT_SUMMARY_BACKEND` 역할별 스위치, `<think>` 제거, 도구 스키마 변환, 단일 GPU 직렬화 락, `num_ctx` 명시. 스모크에서 `<think>` 누출 0 · 도구 선택 정확 · **쓰기는 확인 카드로만**(실행 안 함) · `ollama:` 태그 · `cost_usd` 0.0. 테스트 362 passed(main 312 + 신규 50).

### 5. 도구 연쇄는 예상대로 안 된다

"Python 경험자 중 면접 안 잡힌 사람"은 `search_applications` 한 번에서 끝난다. 중간 결과로 다음 도구를 정하는 계획이 4B로는 서지 않는다. 이 유형을 데모에 넣을지가 **로컬 단독이냐 하이브리드냐**를 가른다.

### 6. 그래서 남은 선택지

원문의 "GPU 있는 경우 = 전구간 로컬"은 이 장비에서 성립하지 않는다. 실질 선택지는 셋이다.

| 안 | 내용 | 대가 |
|---|---|---|
| A | **응답 길이부터 줄이고 4B 재측정** | 가장 싸다. 3천 → 500 토큰이면 4B가 10초대로 들어온다 |
| B | **하이브리드 유지** — 요약·임베딩·STT만 로컬, 채팅은 API | "데이터 반출 없음"이 채팅에서 깨진다 |
| C | **GPU 있는 장비 확보** | 원문 전제로 복귀. 운영 EC2(t3.micro)는 어차피 대상이 아니다 |

**A를 먼저 한다.** B·C는 A의 재측정 뒤에 판단할 것.

### 7. 이 절이 못 채운 것

- 요약 체인(3단, 프롬프트 1.5KB×3)의 로컬 품질·속도 — 미측정
- 임베딩 BGE-M3 교체 — 미착수 (`ko-sroberta`의 `max_seq_length=128` 제약은 그대로)
- 도구 선택 **정답률** — 이번엔 속도만 쟀다. ADR-0023 eval 프레임워크가 필요하다
- `확정일`·`확정자`는 여전히 빈칸이다. 소개문 2번의 정식 범위 여부가 선행이다
