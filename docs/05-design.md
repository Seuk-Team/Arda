# DESIGN — Arda 디자인 규칙

> **상태: 1단계 골격** — 슬롯·규칙만 확정. 구체 값(색 hex·px·ms)은 대표 화면(칸반 보드) 시안에서 팀장이 보면서 확정한 뒤 이 문서에 박제한다(2단계). **값이 "(시안에서 확정)"으로 남아 있는 항목은 임의 값으로 구현 금지.**
>
> 베이스 룩은 기획 프로토타입([planning/05_prototype.html](planning/05_prototype.html))에서 출발하되, 시안 단계에서 조정한다.

## 0. 대원칙

1. **모든 값은 토큰(CSS 변수)으로.** 색·간격·폰트 크기·테두리·radius·그림자·모션 시간·z-index 전부. 토큰에 없는 값을 쓰려면 팀장 확인 후 토큰으로 추가한다.
2. **테마: 라이트 온리.** 단 토큰은 시맨틱 네이밍(`--bg`, `--text`)으로 두어 다크 확장이 가능한 구조로.
3. **부분 구현 + 피드백.** 화면을 조각(예: 칸반 = 헤더 → 툴바 → 컬럼 → 카드 → 상세 패널)으로 쪼개, **조각마다 팀장 확인을 받고 다음 조각으로** 간다. 한 번에 화면 전체를 완성하지 않는다.
4. 근거 문서: Apple HIG(터치 타깃·모션), Material Design(밀도·상태 레이어). 발표 시 "플랫폼 공식 가이드 준수" 근거로 쓴다.

## 1. 타이포그래피

- **전 화면 공통 스케일만 사용. 이 외 크기 금지. 페이지마다 임의 크기 절대 금지.**

| 토큰 | 용도 | 값 |
|---|---|---|
| `--font-display` | 화면 제목 | (시안에서 확정) |
| `--font-h1` | 섹션 제목 | (시안에서 확정) |
| `--font-h2` | 카드·패널 제목 | (시안에서 확정) |
| `--font-body` | 본문 (16px 이상) | (시안에서 확정) |
| `--font-sm` | 보조 텍스트 | (시안에서 확정) |
| `--font-caption` | 뱃지·메타 | (시안에서 확정) |
| `--font-mono` | 숫자·날짜·건수 | (시안에서 확정) |

- 폰트 패밀리: 한글 포함 산세리프 1종(후보: Pretendard) + 숫자용 `font-variant-numeric: tabular-nums` — 지원자 수·D-day·날짜가 자리 흔들림 없이 정렬되게. (시안에서 확정)
- **줄바꿈 규칙 (한글·영어 공통)**
  - 한글 본문: `word-break: keep-all` — 단어 중간 절단 금지. 제목류는 `text-wrap: balance`.
  - **한 줄이어야 하는 텍스트(버튼 라벨·뱃지·메뉴·컬럼 헤더·통계 수치)는 `white-space: nowrap` 고정.** 두 줄이 되는 순간 그것은 버그다 — 컨테이너를 넓히거나 라벨을 줄이거나 말줄임한다.
  - 컴포넌트는 **자기 내용의 최소 폭을 보장**해야 한다(`min-width: max-content` 또는 명시 최소 폭). 좌우 폭을 고려하지 않은 텍스트박스 배치 금지.
- 표기 통일: 날짜 `2026.09.02`, D-day `D-12`, 건수 `48명`. 화면마다 포맷 다르게 쓰지 않는다.

## 2. 색

| 토큰 | 용도 | 값 |
|---|---|---|
| `--bg` / `--bg-elev` | 바탕 / 카드·패널 | (시안에서 확정) |
| `--text` / `--text-sub` | 본문 / 보조 | (시안에서 확정) |
| `--border` | 테두리 | (시안에서 확정) |
| `--accent` | 핵심 액션(버튼·활성) | (시안에서 확정) |
| `--stage-applied/screening/interview/accepted/rejected` | 단계색 5종 (컬럼 바·카드 스트립·뱃지 공용) | (시안에서 확정) |
| `--success` / `--warning` / `--danger` | 상태 피드백 | (시안에서 확정) |

- **AI 표시 규약 (불변)**: 앰버 **점선** = AI 제안 / 청록 **실선** = 사람 확정. AI 점수 박스엔 "확정은 담당자가 합니다" 상시 표기.
- 같은 의미는 항상 같은 색: 단계색은 칸반 컬럼·카드 스트립·뱃지·타임라인 어디서든 동일 토큰.

## 3. 간격·배치

- **간격은 4px 배수 스케일 토큰만**: `--sp-1`(4) ~ `--sp-8`(48) 급. 임의 px 금지 — "픽셀 단위 통일감"은 값을 손으로 맞추는 게 아니라 **같은 토큰을 쓰는 것**으로 달성한다.
- 동종 요소는 동일 규격: 모든 카드의 패딩·radius·그림자는 같은 토큰, 모든 입력 필드의 높이는 같은 토큰. 화면마다 카드 모양이 다르면 버그다.
- 정렬 기준선: 한 화면의 좌우 여백·컬럼 간격은 하나의 그리드에서 나온다. 컨테이너 최대 폭·사이드바 폭은 토큰 고정. (시안에서 확정)
- **레이아웃 깨짐 금지 체크**: 어떤 뷰포트 폭에서도 가로 스크롤은 의도된 곳(칸반 보드 영역)에만. 요소 겹침·삐져나옴·찌그러진 카드가 보이면 그 조각은 미완성이다.

## 4. 테두리·radius·그림자

- 테두리 굵기 토큰 1~2종만(`--border-w`: 1px 기본, 강조 케이스만 별도). 화면마다 다른 굵기 금지.
- radius 토큰 2~3종(카드/버튼/뱃지), 그림자 토큰 2종(카드/오버레이) 이내. 모든 카드에 무거운 그림자 남발 금지. (값은 시안에서 확정)

## 5. 모션

- duration 토큰: `--dur-fast`(hover·press용) / `--dur-base`(전환) / `--dur-slow`(등장) — 구체 ms는 시안에서 확정하되 HIG·Material 권장 범위(대략 100~400ms) 안에서.
- easing 토큰 1~2종 고정. 요소마다 다른 easing 금지.
- **hover**: 색/그림자/1~2px 이동 수준의 절제된 반응. **press(터치·클릭)**: 눌림이 즉각 보일 것(100ms 내 시작). 모바일은 hover 없음 전제로 설계 — hover에만 의존하는 정보 금지.
- 모션그래픽(스크롤 등장 등)은 시그니처 요소 한 곳에만. 한 화면에 등장 애니메이션 흩뿌리기 금지.
- **`prefers-reduced-motion` 대응 필수.**

## 6. 상태 디자인 (컴포넌트 완성의 정의)

모든 인터랙티브 컴포넌트는 **default / hover / press / focus / disabled** 를, 모든 데이터 화면은 **loading(스켈레톤) / empty / error** 를 정의해야 "완성"이다.

- empty: 지원자 0명 컬럼("카드를 여기로"), 검색 결과 없음, 평가 없음 — 각각 안내 문구 포함.
- loading: 스피너 남발 대신 스켈레톤 우선.
- 드래그 중: 원본 자리 표시 + 드래그 고스트 + 드롭 가능 영역 표시.
- **피드백 토스트**: 단계 이동 성공("면접으로 이동 · 메일 발송됨") / 실패 시 롤백 안내. 낙관적 업데이트의 실패가 조용히 지나가면 안 된다.

## 7. 오버플로 (10만 건 기준 극단값 전제)

- 1줄 영역(카드 이름·이메일·공고 제목): `ellipsis`. 여러 줄 허용 영역(자소서 미리보기): `line-clamp` 지정 줄 수.
- 태그 다수: 표시 N개 + `+3` 카운터.
- 구현 검증 시 반드시 극단값으로: 아주 긴 이름, 태그 10개, 자소서 5천 자.

## 8. 레이어 (z-index 토큰)

`--z-base(0) < --z-sticky < --z-dropdown < --z-modal < --z-toast < --z-drag` — 이 토큰 외 z-index 직접 지정 금지. 겹침 순서 버그의 원천 차단.

## 9. 반응형

- 브레이크포인트 토큰: mobile / tablet / desktop. (값은 시안에서 확정, 중간 폭에서도 깨지지 않는지 확인)
- 모바일은 칸반 금지 → 단계 탭 + 리스트 (기획 확정). 단계 이동은 상세 화면 버튼.
- 터치 타깃 최소 44×44px(HIG) — 모바일의 모든 버튼·탭·카드 액션.
- PC 최소 지원 폭 정의(시안에서 확정). 그 이하는 모바일 레이아웃으로 전환.

## 10. 접근성 최소선

- 텍스트 대비 WCAG AA(4.5:1, 큰 글씨 3:1). 단계색 뱃지도 검사 대상.
- 키보드 포커스 링 항상 표시(`:focus-visible`). 드래그의 대체 수단 = 상세 화면 단계 변경 버튼.

## 11. 금지 (AI 티 방지)

- 보라→파랑 그라데이션 기본값, 다색 그라데이션 남용
- shadcn/Radix 기본 테마 그대로 출고, Tailwind 생성물 그대로 출고 (참고만, 토큰으로 재작성)
- 모든 섹션 가운데 정렬, 의미 없는 01/02/03 마커, 이모지 불릿
- 버튼 라벨 "Submit/Click here" — 동작 그대로("지원서 제출", "합격 처리"). 같은 동작의 라벨이 화면마다 바뀌기 금지
- 주제 무관 패럴랙스·플로팅 장식

## 12. 작업 절차 (팀원 + Claude 공통)

1. 화면 작업은 **조각 단위 지시서**로 받는다. 조각마다 완성 → 팀장 확인 → 다음 조각.
2. 구현 전 이 문서의 해당 토큰이 값 확정 상태인지 본다. "(시안에서 확정)"이면 시작하지 않고 팀장에게 요청.
3. 완성 체크: §6 상태 전부 정의? §7 극단값 통과? §3 깨짐 없음? §1 nowrap 위반 없음? — 하나라도 아니면 미완성.
