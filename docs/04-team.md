# 04. 작업 분배

사람별 고정 배정은 하지 않는다. **팀장이 상황(각자 가능한 시간·진행 상태)에 따라 작업 풀에서 꺼내 지시서(`docs/tasks/`)로 발행한다.** 발표용 역할표(A~E)는 프로젝트 후반에 실제 수행 기준으로 확정한다.

## 팀장 전담 (다른 사람 손대지 않음)

- 스키마([01-erd.md](01-erd.md)) · 아키텍처 결정
- 프론트 뼈대: 라우팅·디자인 토큰·공통 컴포넌트, 칸반 드래그·낙관적 업데이트
- 백엔드 핵심: 단계 전환 로직, 인증·권한
- 파트 간 통합, 전체 PR 리뷰·머지

## 팀원 작업 풀

꺼내 줄 수 있는 일 목록. **격리 = 실패해도 다른 파트가 안 죽는 정도.** 지시서 없이 시작하지 않는다.

## 발표용 역할표 (후반 확정, 이름 미기입)

| 역할 | 담당 | 면접에서 말할 것 |
|---|---|---|
| A | 도메인 백엔드 | 상태 전환 규칙을 DB와 코드 중 어디서 강제했는가 |
| B | 검색 · 데이터 | 느린 쿼리를 어떻게 찾았고 인덱스로 얼마나 줄였는가 |
| C | 파일 · 알림 | 파일 업로드가 왜 API 서버를 거치면 안 되는가 |
| D | 프론트엔드 | 드래그 실패 시 낙관적 업데이트를 어떻게 롤백했는가 |
| E | 인프라 · 인증 | 배포 파이프라인과 권한 모델을 어떻게 설계했는가 |

**전원 공통**: 자기 수행 작업의 문서화, 발표 자료 본인 파트.
