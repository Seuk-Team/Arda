>
> **왜 두 직무인가.** 멘토링(2026-09-10) 8번 "다른 직종이 지원했을 때 잘 나올지" 와 2번 "다양한 이력서에서 요약이 나오는지" 를 데이터로 확인하려면, 요건이 분명히 다른 공고 두 개가 필요하다. 이 두 요강으로 지원자 데이터셋([../07_eval/fit-check-2026-09.md](../07_eval/fit-check-2026-09.md))을 돌린다.
>
> **Arda 등록 규칙 (2026-09-10 실측).** 아르의 적합도 평가(`backend/app/agent/summarizer.py` `_build_prompt_vars`)는 공고의 **`description` 한 칸만** 요건으로 읽는다. 09-08 에 추가된 `requirements` · `preferred` · `benefits` 컬럼과 회사 소개 표는 평가 프롬프트에 들어가지 않는다. 그래서 아래 각 요강의 **"§ Arda description 에 붙여 넣을 것"** 블록을 통째로 `description` 에 넣어야 평가가 요건을 본다. 이 빈틈은 에이전트 오너에게 넘긴다(제안: `_build_prompt_vars` 가 `requirements`·`preferred`·회사 §8.1 인재상을 함께 넣도록).

## 1. 프론트엔드 개발자 (React · TypeScript) — 경력 2~6년

### 모집 부문
- 개발실 프론트엔드 · 1명 · 경력 2년 이상 6년 이하

### 담당 업무
- 스타트업·중견기업 신제품의 웹 프론트엔드를 기획 단계부터 출시까지 만든다 (프로젝트당 3~6개월, 3~5명 팀)
- 디자인실 시안을 컴포넌트로 옮기고, 백엔드 API 계약(OpenAPI)을 함께 정한다
- 출시 뒤 운영으로 이어지는 프로젝트의 성능·접근성·오류를 지표로 보고 고친다
- 화면이 곧 스펙이 되도록 목데이터 화면을 먼저 만들고 데이터 모델을 검증한다

### 자격 요건 (필수)
- React 와 TypeScript 로 실서비스 화면을 2년 이상 만들어 운영까지 경험한 분
- REST API 를 직접 붙여 본 분 (인증 토큰 처리, 401·에러 상태 처리, 낙관적 갱신 경험 중 하나 이상)
- Git 브랜치 → PR → 머지 흐름으로 협업해 본 분
- 자기 결정과 그 근거를 문서(PR 본문·설계 메모)로 남겨 본 분

### 우대 사항
- Vite · 번들 크기·초기 로딩 최적화 경험
- WebSocket · WebRTC 등 실시간 화면 경험
- Flutter 또는 React Native 로 모바일 화면을 함께 만든 경험
- 디자인 시스템(토큰·컴포넌트 라이브러리) 운영 경험
- 접근성(키보드·스크린리더) 대응 경험
- 오픈소스 기여 또는 공개 포트폴리오

### 이런 분과 일하고 싶습니다 (회사 소개 §8.1)
- 승인을 기다리기보다 자기 도메인은 자기가 판단하는 분
- 필요하면 백엔드 코드도 열어 고쳐 본 분
- 실패를 팀에 공개하고 원인·조치를 세 줄로 적을 수 있는 분

### 이런 분과는 잘 안 맞을 수 있습니다 (§8.2)
- 세세한 지시가 있어야 편한 분 · 회의로 결정하는 것을 선호하는 분 · 완벽할 때까지 릴리스하지 않는 분

## 2. 백엔드 개발자 (Python · FastAPI · PostgreSQL) — 경력 3~8년

### 모집 부문
- 개발실 백엔드 · 1명 · 경력 3년 이상 8년 이하

### 담당 업무
- 신제품의 API 서버와 데이터 모델을 설계하고 구현한다 (Python · FastAPI · PostgreSQL)
- 스키마 변경을 마이그레이션(alembic)으로 관리하고, ERD 를 팀 계약으로 유지한다
- 파일 업로드(S3 presigned)·메일 발송·큐 같은 부가 인프라를 서버 밖으로 빼는 구조를 잡는다
- 배포 자동화(컨테이너·CI)와 운영 지표(백업·경보)를 함께 본다
- 프로젝트 인수 시 3주 안에 기존 코드를 파악하고 운영 가능한 상태로 만든다

### 자격 요건 (필수)
- Python 으로 실서비스 API 를 3년 이상 개발·운영한 분 (FastAPI · Django · Flask 중 하나)
- 관계형 DB(PostgreSQL 권장) 스키마 설계와 인덱스·쿼리 튜닝 경험
- 인증(JWT 등)·권한 모델을 직접 설계해 본 분
- 테스트 코드를 CI 에서 돌려 본 분 (pytest 등)
- Docker 로 서비스를 배포해 본 분

### 우대 사항
- 비동기(asyncio)·WebSocket 서버 경험
- 큐·워커(SQS · Redis · Celery 등)로 비동기 작업을 분리한 경험
- AWS(EC2 · S3 · IAM) 운영 경험 또는 온프레미스 이전 경험
- LLM API(도구 호출·RAG·임베딩) 를 서비스에 붙여 본 경험
- pgvector 등 벡터 검색 경험
- 무결성·감사 로그(append-only, 해시 체인) 설계 경험

### 이런 분과 일하고 싶습니다 (§8.1)
- ADR 처럼 기술 결정을 문서로 남겨 본 분
- 배포가 깨졌을 때 원인·조치·재발 방지를 스스로 공개한 분
- 프론트나 인프라 코드도 필요하면 고쳐 본 분

### 이런 분과는 잘 안 맞을 수 있습니다 (§8.2)
- 자기 도메인만 지키는 것이 편한 분 · 결정을 승인 라인에 태우는 것이 편한 분
