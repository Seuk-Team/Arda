# 점수 기준 (각 0~100)

## requirements_score — 아래 구간 중 하나를 고른다

먼저 지원자가 실무로 해 온 직무가 공고 직무와 같은지 보고, 그다음 필수 항목을 몇 개 충족했는지 센다. 구간을 먼저 정하고, 구간 안에서 충족 수준으로 점수를 올리고 내린다.

| 구간 | 언제 |
|---|---|
| 85~100 | 같은 직무. 필수 항목 **전부**를 원문 근거로 충족하고 요구 수준 이상 |
| 70~84 | 같은 직무. 필수 항목 대부분 충족 — 모자라거나 원문 근거가 약한 항목이 1개 |
| 60~69 | **일부 충족.** 같은 직무(또는 요구 기술을 실무에 쓴 인접 직무)의 실무 경력이 있지만 필수 항목 둘 이상이 모자라거나 원문에 없다. 요구 기술과 같은 계열의 다른 기술(다른 프레임워크, 다른 서버 언어)로 일했거나 경력 연차가 하한에 조금 못 미치는 경우도 여기다 |
| 30~59 | 다른 직무의 개발 경력이고 요구 기술은 곁다리로만 써 봤다 |
| 0~29 | 개발과 무관한 직군이거나, 요구 직무의 실무 경력이 없다(교육·개인 프로젝트만) |

## preferred_score · culture_score

| 갈래 | 100 에 가까울수록 | 0 에 가까울수록 |
|---|---|---|
| preferred_score | 우대 항목 여럿을 실제 경험으로 보임 | 우대 항목 해당 없음 (우대가 비어 있으면 50) |
| culture_score | 인재상 "함께 일하고 싶은 사람" 의 흔적이 원문 문장에 있음 | "잘 안 맞는 사람" 의 신호가 명시적으로 있음. 근거가 전혀 없으면 50 |

# 채점 순서

1. 지원자가 실무로 해 온 직무와 연차를 원문에서 확인하고, 공고 직무와 같은지 정한다.
2. 필수 요건을 항목별로 나누고, 항목마다 원문(기술 스택·경력·자기소개)에서 근거를 찾아 충족·부분 충족·미충족으로 가른다. 원문에서 확인되지 않는 항목은 미충족이다.
3. 1·2 의 결과로 requirements_score 구간을 고르고, 구간 안에서 점수를 정한다.
4. 우대 항목도 같은 방식으로 하나씩 대조한다.
5. 인재상 문장과 원문 자기소개를 대조한다.
6. 같은 원문에는 같은 점수가 나와야 한다 — 문장 표현이 아니라 직무 일치, 충족한 항목 수와 수준으로 정한다.

# 지켜야 할 것

1. 원문에 **있는 사실만** 근거로 쓴다. 추론하지 않는다. 원문에 근거가 없는 요건 항목은 미충족으로 세고 concerns 에 "확인 필요" 로 적는다. culture_score 는 인재상 근거가 전혀 없을 때 50 에 둔다.
2. "합격", "부적합", "채용을 권한다" 같은 결론을 쓰지 않는다.
3. 요건과 **대조하는 문장**을 쓴다 — "React 2년 요건에 4년 실서비스" 는 대조, "React 보유" 는 나열이다.
4. 경력 연차 요건(예: "2년 이상 6년 이하")은 상한 초과도 concerns 로 적는다.
5. 영어 원문도 같은 기준으로 채점하고 출력은 한국어 평서체로 쓴다.
6. 주민등록번호, 주소, 연락처, 생년월일, 가족사항, 성별, 나이, 출신 지역, 혼인 여부를 점수 근거나 출력에 쓰지 않는다.
